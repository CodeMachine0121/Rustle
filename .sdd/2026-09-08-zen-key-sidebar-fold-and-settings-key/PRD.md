## 1. Background & Goal

### Problem Statement

寫作者每天在這個 App 裡做三件事會被迫把手從鍵盤上拿開，或是被迫記住一個不該記的規則：

1. **收起干擾要靠滑鼠。** 專注模式今天只有兩條路：畫面右上角那顆按鈕，和 `Esc`。按鈕要用滑鼠；`Esc` 則是把一個本來就有主人的鍵借去兼差。
2. **`Esc` 身上掛了太多事。** 它同時是「關掉片語選單」「停止填空」「Vim 退回常態模式」「離開專注模式」。開著 Vim 的寫作者一天要按幾百次 `Esc`，而其中只要有一次畫面突然攤開，那就是一次被打斷的句子。
3. **畫面只有兩檔。** 要嘛四欄全開，要嘛專注模式一次收掉兩欄。想留著文章清單、只把最左邊那一欄收掉，今天沒有辦法。
4. **開設定只有一條路。** 左上角那顆齒輪。齒輪住在最左邊那一欄裡，所以那一欄一旦不在（專注模式，或本切片新增的摺疊），設定就完全叫不出來。

### Expected Outcome

- 專注模式**在 Vim 的語言裡有自己的鍵**：常態模式下的 `zz`。
- `Esc` **只做 Vim 的那一件事**，不再是離開專注模式的路，也不再無條件吃掉按鍵。
- 最左邊那一欄**可以單獨摺疊**，是一個會被記住的偏好，而且**摺疊起來之後仍然有一顆看得見、鍵盤走得到的按鈕把它叫回來**。
- `Cmd+,`（非 macOS 上 `Ctrl+,`）**在任何時候都叫得出設定面板**，包含最左欄不在的時候。

### Out of Scope

- Vim 模式關著時的 `zz`。不做，理由是那會讓兩個 `z` 變成打不出來的字。
- 側邊欄摺疊的快捷鍵。這個切片只給按鈕。
- 讓 `Cmd+,` 可以在設定檔裡改成別的鍵。
- 文章清單那一欄自己的摺疊。
- 專注模式那顆按鈕、預覽面板三種排列、預覽面板的快捷鍵——一個字都不動。
- 把 `zz` 列進快捷鍵清單。

| :--- | :--- | :--- |

## 3. User Stories & Acceptance Criteria

### US-01 — 用 `zz` 開關專注模式 [priority: P0]

> 身為開著 Vim 的寫作者，我想在常態模式下連按兩下 `z` 就收起或攤開畫面，這樣我收畫面的時候手不必離開鍵盤。

```gherkin
Scenario: 常態模式下 zz 進入專注模式
  Given Vim 模式開著
    And 寫作者在常態模式
    And 專注模式沒有開
  When 寫作者連按兩下 "z"
  Then 專注模式開著
    And 最左邊兩欄不在畫面上

Scenario: 常態模式下 zz 離開專注模式
  Given Vim 模式開著
    And 寫作者在常態模式
    And 專注模式開著
  When 寫作者連按兩下 "z"
  Then 專注模式沒有開
    And 最左邊兩欄回到畫面上

Scenario: 輸入模式下的 zz 是兩個字母
  Given Vim 模式開著
    And 寫作者在輸入模式
    And 專注模式沒有開
  When 寫作者打 "zz"
  Then 文章裡多了 "zz"
    And 專注模式仍然沒有開

Scenario: Vim 模式關著時 zz 是兩個字母
  Given Vim 模式關著
    And 專注模式沒有開
  When 寫作者打 "zz"
  Then 文章裡多了 "zz"
    And 專注模式仍然沒有開

Scenario: 選取模式下的 zz 不碰專注模式
  Given Vim 模式開著
    And 寫作者在選取模式，選著一段文字
    And 專注模式沒有開
  When 寫作者連按兩下 "z"
  Then 專注模式仍然沒有開
    # 那一下仍然是 Vim 自己的 zz（捲到畫面正中）。我們只在常態模式接手這個鍵，
    # 沒有把它從別的模式拿走。

Scenario: 只按一個 z 什麼都不做
  Given Vim 模式開著
    And 寫作者在常態模式
    And 專注模式沒有開
  When 寫作者按一下 "z" 就停手
  Then 專注模式仍然沒有開
    And 文章沒有變
```

### US-02 — `Esc` 不再離開專注模式 [priority: P0]

> 身為開著 Vim 的寫作者，我想按 `Esc` 的時候只發生一件事——退回常態模式——這樣我不必在每一次按下去之前先想一遍現在畫面是什麼狀態。

```gherkin
Scenario: 專注模式下按 Esc，畫面不變
  Given 專注模式開著
    And Vim 模式開著
    And 寫作者在常態模式
  When 寫作者按 "Escape"
  Then 專注模式仍然開著

Scenario: Vim 模式關著時按 Esc，畫面也不變
  Given 專注模式開著
    And Vim 模式關著
  When 寫作者按 "Escape"
  Then 專注模式仍然開著

Scenario: Esc 仍然帶寫作者退回常態模式
  Given Vim 模式開著
    And 寫作者在輸入模式
  When 寫作者按 "Escape"
  Then 寫作者在常態模式

Scenario: Esc 仍然關得掉片語選單
  Given 片語選單開著
  When 寫作者按 "Escape"
  Then 片語選單關掉了

Scenario: Esc 仍然停得掉填空
  Given 片語填空進行中
  When 寫作者按 "Escape"
  Then 填空停止了
```

    And 文章清單不在畫面上

Scenario: 最左欄不在時視窗按鈕有地方站

    And 文章清單在畫面上

## 4. Business Flow & Logic

### `zz` 走的路

```
按鍵 → 輸入法在選字？ ── 是 ──▶ 交給輸入法，結束
                        │
                        否
                        ▼
             Vim 模式開著 且 在常態模式？ ── 否 ──▶ 照舊（打字 / 什麼都不做）
                        │
                        是
                        ▼
              第一個 z：記住，等下一個鍵
                        ▼
              第二個 z：翻轉專注模式
```

### `Esc` 剩下幾層

拿掉「專注模式那一層」與「無條件吃掉按鍵」之後：

```
Esc → 片語選單開著？ ── 是 ──▶ 關掉選單，結束
        │
        否
        ▼
      填空進行中？ ── 是 ──▶ 停止填空，結束
        │
        否
        ▼
      Vim 模式開著？ ── 是 ──▶ Vim 自己決定（輸入模式 → 常態模式）
        │
        否
        ▼
      交還給編輯器本身
```

### 哪幾欄在畫面上

| 專注模式 | 最左欄摺疊 | 最左欄 | 文章清單 | 視窗三顆按鈕站在哪 |
| :--- | :--- | :--- | :--- | :--- |
| 關 | 攤開 | 在 | 在 | 最左欄的頂端（今天就是這樣） |
| 關 | 收起 | 不在 | 在 | **文章清單的頂端** |
| 開 | 攤開 | 不在 | 不在 | 寫作區的控制列（今天就是這樣） |
| 開 | 收起 | 不在 | 不在 | 寫作區的控制列 |

### Core Business Rules

| # | 規則 |
| :--- | :--- |
| BR-01 | `zz` 只在「Vim 模式開著 + 常態模式 + 輸入法沒在選字」時翻轉專注模式；其餘每一種情況照舊。 |
| BR-02 | `zz` 是**翻轉**，不是「進入」也不是「離開」。 |
| BR-03 | `Esc` 對專注模式沒有任何作用。 |
| BR-04 | `Esc` 不再無條件吃掉按鍵；沒人接手就交還給編輯器。 |
| BR-05 | 最左欄的摺疊是一個**會被記住**的偏好，寫進 Vault 自己的設定檔。 |
| BR-06 | 專注模式**蓋過**摺疊（開著時最左欄一定不在），但**不改寫**它。 |
| BR-07 | 摺疊不改變任何選擇，也不改變文章清單的內容。 |
| BR-08 | 最左欄不在、文章清單在的時候，替視窗自己的三顆按鈕留位置的是文章清單。 |
| BR-09 | `Cmd+,`／`Ctrl+,` 翻轉設定面板，不論最左欄在不在。 |
| BR-10 | `Cmd+,` 在輸入法選字時不作用。 |
| BR-11 | `Cmd+,` 不可設定，寫死。 |
| BR-12 | 快捷鍵清單新增 `Cmd+,` 一列；`zz` 不列；`Esc` 那一列保留。 |

### Edge Cases

| 情況 | 行為 |
| :--- | :--- |
| 只按一個 `z` 就停手 | 什麼都不發生。這是 Vim 序列的正常行為。 |
| `zz` 在選取模式 | 不碰專注模式。那一下仍然是 Vim 自己的 `zz`——我們只在常態模式接手這個鍵。 |
| 設定檔讀不到 | 最左欄以**攤開**開場（和其他每一個讀不到就用預設的欄位一樣），寫作者仍然可以摺疊，只是下次重開會忘記。 |
| 設定檔裡摺疊欄位是 `true`，但同一次開機又進了專注模式 | 專注模式蓋過去；離開專注模式後回到收起來的樣子。 |
| 設定面板開著時按 `Cmd+,` | 關掉。與按齒輪一致。 |
| 摺疊鈕在專注模式時 | 跟著它所在的那一欄一起不在——沒有東西可摺。 |

## 5. UI/UX Design & Interaction

### 摺疊鈕放哪裡（收斂 BRIEF 的開放決定 1）

**放在文章清單那一欄的頂端。** 理由：

- 它是**唯一一個在「最左欄在」與「最左欄不在」兩種狀態下都在畫面上**的位置。放在最左欄裡的話，收起來之後它就跟著消失了，寫作者叫不回來。
- 它就緊貼在最左欄的右邊，一顆指向左邊的箭頭在那裡的意思不必解釋。
- 文章清單那一欄本來就需要在最左欄不在時替視窗三顆按鈕留位置——這兩件事在同一列上解決。

它是一顆真正的 `<button>`，有無障礙標籤，鍵盤走得到，`aria-expanded` 說明它現在是攤開還是收起。

### 摺疊狀態記在哪（收斂 BRIEF 的開放決定 2）

記在設定檔既有的 `sidebar` 底下，和「哪幾段被摺起來」放在一起。理由：那個欄位本來就叫 sidebar，本來就是在記「這一欄被收掉了多少」。

### `zz` 的畫面回饋

沒有額外回饋。畫面本身就是回饋——兩欄收起來或攤開來。

## 6. Non-Functional Requirements

| # | 需求 |
| :--- | :--- |
| NFR-01 | 這三件事**都不可以重建編輯器**。重建會丟掉復原歷史、丟掉輸入法正在組的字、丟掉上次存檔後打的每一個字。 |
| NFR-02 | 中文輸入永遠不出錯：`zz` 與 `Cmd+,` 在輸入法選字期間都不作用。 |
| NFR-03 | 摺疊先改畫面，再寫設定檔；寫檔不可以擋住畫面，寫檔失敗不可以讓畫面回退。 |
| NFR-04 | 所有面向讀者的字都走既有的兩語系詞彙表，元件不得自己寫死任何一個字。 |
| NFR-05 | 這個切片不新增任何第三方依賴。 |

## 7. Dependencies & Risks

### External Dependencies

| 依賴 | 用途 |
| :--- | :--- |
| 既有的 Vim 模式（見 vim-mode 切片） | `zz` 這個序列由 Vim 的按鍵語言解析；本切片需要它能「自訂動作 + 綁定按鍵」。 |

### Known Risks

| 風險 | 影響 | 對策 |
| :--- | :--- | :--- |
| Vim 原本的 `zz`（捲到畫面正中）被蓋掉 | 熟 Vim 的人會愣一下 | 刻意取捨，寫進 BRIEF 與通用語言地圖。這個產品只有一份長文，捲動不是核心動作。 |
| 拿掉 `Esc` 的「無條件吃掉按鍵」之後，編輯器自己的「`Esc` 然後 Tab 跳出寫作區」的路會回來 | **在 Vim 常態模式也會回來**：Vim 對常態模式的 `Esc` 明說「沒我的事」而不接手，所以按了 `Esc` 再按 `Tab`，跳出去的是焦點而不是縮排 | 當時**接受**，理由是那條路是編輯器因為吃掉 `Tab` 而欠寫作者的。⚠️ **已由 `.sdd/2026-09-08-tab-always-indents-in-vim-mode/` 推翻**：使用者裁決 Vim 模式下 `Tab` 永遠是縮排，那條路只在 Vim 關著時存在。Vim 關著時本列所寫的一切照舊。 |
| `Cmd+,` 與可自訂的預覽快捷鍵撞在一起 | 寫作者若把 `previewPanel.toggleShortcut` 設成 `Mod+,`，一次按鍵會同時開設定與切換預覽 | 接受。兩個監聽各自獨立、沒有仲裁機制，而這是寫作者自己把鍵設成作業系統慣用鍵造成的。真的要處理，該做的是一個統一的按鍵仲裁，那是另一個切片。 |
| 設定檔多一個欄位，舊設定檔沒有 | 舊檔開起來要當成「攤開」 | 讀取端一律有預設值，這是既有做法。 |
| `Cmd+,` 與作業系統選單的偏好設定列衝突 | 按了兩件事都發生 | 這個 App 的選單目前沒有偏好設定那一列；由畫面自己接這個鍵。 |
