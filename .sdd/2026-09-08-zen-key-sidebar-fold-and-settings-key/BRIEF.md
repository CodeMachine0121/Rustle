# 專注模式的鍵、側邊欄的摺疊、設定的鍵 — 需求共識

- **切片**：`feature/zen-key-sidebar-fold-and-settings-key`
- **日期**：2026-09-08
- **狀態**：需求已共識，可進 `/prd`

---

## Goal

三件都是「手不離鍵盤、眼睛不離字」的小事，合成一個切片，因為它們動到的是同一件東西：**寫作者要看多少畫面，以及他用哪一個鍵去改變它。**

1. **專注模式有自己的鍵了**——在 Vim 的常態模式下連按兩下 `z`，畫面就收起來或攤開來。
2. **`Esc` 不再兼差**——它只做 Vim 的事：從輸入模式退回常態模式。它不再是離開專注模式的路。
3. **最左邊那一欄可以摺疊**——不進專注模式，也能單獨把「所有文章／workspaces／狀態／標籤」那一欄收掉，只留文章清單和寫作區。
4. **`Cmd+,`叫得出設定**——不必先把滑鼠移到左上角那顆齒輪。

---

## Requirements

### 一、`zz` 是專注模式的開關

- **在 Vim 模式開著、且寫作者在常態模式（NORMAL）時**，連按兩下 `z`：專注模式沒開就開，開著就關。
- **這是一個 Vim 語言裡的鍵**，所以：
  - Vim 模式**關著**的時候，`zz` 就是兩個字母 `z`，照樣打進文章裡，什麼都不會發生。
  - 在**輸入模式（INSERT）**打 `zz`，也是兩個字母，照樣打進文章裡。
  - 在**選取模式（VISUAL）**不切換專注模式——選取中的寫作者要的是選取，不是換畫面。（那裡的 `zz` 仍然是 Vim 自己的 `zz`，把游標行捲到畫面正中；我們沒有把它拿走，只是沒有在那個模式接手。）
- Vim 原本的 `zz`（把游標所在行捲到畫面正中）**在常態模式讓給這個功能**。這是刻意的取捨：這個產品是寫文章的地方，畫面上永遠只有一份長文，「捲到正中」的價值遠低於「把干擾收掉」。其他模式一個字都不動。
- **中文輸入中不作用。** 正在選字時鍵盤屬於輸入法，這條規則和這個產品既有的每一個鍵一樣。

### 二、`Esc` 只剩 Vim 的那一件事

- `Esc` **不再離開專注模式**。今天它會，這個切片把它拿掉。
- `Esc` 保留的是：**Vim 模式下從輸入模式退回常態模式**。
- 「片語選單開著時 `Esc` 關掉選單」與「填空進行中時 `Esc` 停止填空」**不算 `Esc` 的功能，是那個當下浮在畫面上的東西自己的關閉方式**，照舊保留——沒有它們，選單就沒有辦法關掉。同理，設定面板開著時 `Esc` 關掉面板、篩選框打字中 `Esc` 取消，也都照舊。
- 拿掉「不管有沒有人接手都吃掉這個按鍵」的那一層之後，`Esc` 沒人要時就沒人要，交還給編輯器本身。
- **這件事有代價，而且我們接受它**：編輯器收到一個沒人要的 `Esc` 就會武裝「下一次 `Tab` 交出去移動焦點」兩秒。所以在 Vim 常態模式按了 `Esc`（那裡 Vim 本來就沒事可做）再按 `Tab`，跳出去的是焦點而不是縮排。換來的是**只用鍵盤的人重新有路離開寫作區**——那條路本來就是編輯器欠寫作者的，前一個切片把它花掉了。它只有一次按鍵的寬度，中間按任何別的鍵就解除，所以正在寫字的人碰不到。
  > ⚠️ **這一項取捨已由 `.sdd/2026-09-08-tab-always-indents-in-vim-mode/` 推翻。** 使用者裁決不接受 Vim 模式下的那個代價：Vim 開著時，沒人要的 `Esc` 由 Vim 區塊留下，`Tab` 永遠是縮排。Vim 關著時本段所寫的一切照舊。上面這段留著，因為它是當時的決定。

### 三、最左邊那一欄可以摺疊

- 最左邊那一欄（上面是「所有文章」，底下是 WORKSPACES／狀態／標籤三段）**可以整欄收起來**，收起來之後畫面剩下文章清單和寫作區。
- **收起來之後一定要看得到把它叫回來的控制項**，而且不能只有滑鼠能用——它是一顆真正的按鈕，鍵盤走得到。
- **這是一個偏好，會被記住**：下次打開 App 還是上次的樣子。這一點和專注模式相反，專注模式是刻意不記的。理由是：專注模式一次收掉兩欄、畫面剩下一片白，開機看到會以為壞了；這裡只收一欄，而且旁邊就有一顆看得見的按鈕把它叫回來。
- **和專注模式各走各的。** 專注模式開著時左邊兩欄都不在，這一欄摺不摺疊都看不出來；離開專注模式之後，它還是寫作者上次留下的樣子。
- 摺疊**不會改變任何選擇**。收起來的時候選著的 workspace、狀態、標籤都還選著，文章清單一列都不會變。
- 那一欄收起來的時候，**視窗自己的三顆按鈕（關閉／縮到最小／放大）要有地方站**——它們畫在視窗左上角的固定位置，那一欄一走，站的位置就變成文章清單那一欄的頂端。

### 四、`Cmd+,` 叫出設定

- 按 `Cmd+,`（或非 macOS 上的 `Ctrl+,`）**打開設定面板**，等同於按下那顆齒輪。
- 這是每一個 macOS App 都有的鍵，寫作者不必學。
- **面板已經開著的時候再按一次就關掉**——一顆按鈕怎麼用，這個鍵就怎麼用。
- **左邊那一欄不在的時候（摺疊了、或在專注模式裡）也叫得出來。** 面板本來就畫在整個畫面之上，不屬於任何一欄；寫作者按了鍵就是要它出來。
- **中文輸入中不作用**，理由同上。

### 五、快捷鍵清單怎麼跟著改

- 設定面板裡那份「這個產品教過哪些鍵」的清單，**新增 `Cmd+,` 一列**。
- **`zz` 不進那份清單。** 那份清單白紙黑字寫著「Vim 的鍵不列」，而 `zz` 只在 Vim 的常態模式下成立——列進去等於清單裡出現一列在半數情況下是假的。
- `Esc` 那一列**留著**：它仍然關得掉片語選單、停得掉填空，仍然是這個產品教過的鍵。

## 不做的事

- 不讓 `zz` 在 Vim 模式關著時也生效——那會讓「打兩個 z」變成沒辦法打的字。
- 不做「側邊欄摺疊」的快捷鍵。這個切片只給它一顆按鈕；要不要給鍵是下一個人的事。
- 不讓 `Cmd+,` 可以被寫作者改成別的鍵。預覽面板那個鍵可以改是因為它是這個產品自創的；`Cmd+,` 是作業系統的慣例。
- 不動文章清單那一欄本身能不能摺疊——只有最左邊那一欄。
- 不動預覽面板的三種排列、不動專注模式那顆按鈕。

每個例子只列會影響結果的資料。

### Rule 一：`zz` 是專注模式的開關

| # | Given（只列相關資料） | When | Then |
|---|---|---|---|
| 1（happy）| Vim 模式開著、常態模式、專注模式沒開 | 連按兩下 `z` | 進專注模式，左邊兩欄收掉 |
| 2（happy）| Vim 模式開著、常態模式、專注模式開著 | 連按兩下 `z` | 離開專注模式，左邊兩欄回來 |
| 3（branch）| Vim 模式開著、**輸入模式** | 打 `zz` | 文章裡多了 `zz` 兩個字，畫面不變 |
| 4（branch）| **Vim 模式關著** | 打 `zz` | 文章裡多了 `zz` 兩個字，畫面不變 |
| 5（boundary）| Vim 模式開著、**選取模式**、選了一段字 | 連按兩下 `z` | **專注模式不變**，選取還在（畫面會照 Vim 自己的 `zz` 捲動，那是 Vim 的行為，不是我們的） |
| 6（exception）| Vim 模式開著、常態模式、輸入法正在選字 | 按 `z` | 屬於輸入法，畫面不變 |
| 7（boundary）| Vim 模式開著、常態模式 | 只按一下 `z` 就停手 | 什麼都不發生（`z` 是一個序列的開頭） |

## 開放決定（留給 `/prd` 收斂）

1. 摺疊鈕放在哪一欄的哪一個位置——BRIEF 只要求「收起來之後看得見、鍵盤走得到」。
2. 摺疊狀態記在設定檔的哪個欄位底下。
