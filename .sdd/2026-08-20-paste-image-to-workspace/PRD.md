# 需求規格 — 貼上圖片

- **切片**：`feature/paste-image-to-workspace`（Wave 4）
- **覆蓋需求**：R-13 ~ R-19、FR-6.1 ~ FR-6.10、FR-5.9、§7.4 第一列與第五列陷阱
- **上游共識**：[BRIEF.md](BRIEF.md)。留白處的裁決一律以那份的 §7 為準，本檔只把它展開成可驗收的行為。
- **詞彙**：通用語言地圖。本切片新增的詞彙已進地圖。

---

## 1. 目標

在編輯區按一次貼上，剪貼簿裡的圖片就成為這篇文章的一部分：檔案落在 `{workspace}/images/{uuid}.{副檔名}`，正文多一行相對路徑的 Markdown，預覽面板立刻顯示它。全程不問任何問題，一次貼上是一步 undo，而 undo 不刪檔。

## 2. User Stories

| # | 身為 | 我想要 | 這樣我就能 |
| :--- | :--- | :--- | :--- |
| US-1 | 寫文章的人 | 截圖之後直接在編輯區貼上 | 不用離開文章去處理檔案 |
| US-2 | 寫文章的人 | 正文裡是相對路徑 | 這篇文章搬去別的工具、上 Git 之後圖片還在 |
| US-3 | 寫文章的人 | 貼上之後預覽裡就看得到圖 | 知道自己貼的是哪一張、位置對不對 |
| US-4 | 寫文章的人 | 貼錯了按一次 undo 就乾淨 | 不必手動刪掉五行語法 |
| US-5 | 寫文章的人 | 從 Finder 複製動畫 GIF 進來還會動 | 不必為了「會動」自己繞過 App |
| US-6 | 寫文章的人 | 存不進去的時候正文不要被弄髒 | 不會留下一行指向不存在檔案的語法 |
| US-7 | 打中文的人 | 組字中按到貼上不要出事 | 選字不被打斷 |
| US-8 | 這台機器的主人 | `rustle:` 只拿得到 vault 裡的圖片 | 一段惡意的正文問不出別的檔案 |

## 3. 業務流程

### 3.1 一次成功的貼上

```
編輯區收到 paste 事件
   │
   ├─ 組字中？ ──────────────────── 是 ─▶ 什麼都不做，事件交給輸入法（FR-6.10）
   ├─ 有所屬 workspace？ ────────── 沒有 ─▶ 什麼都不做（FR-6.8）
   ├─ 事件的剪貼簿裡有圖片項目？ ─── 沒有 ─▶ 什麼都不做，編輯區照常貼文字（FR-6.7）
   │
   ▼ 有（圖片優先於文字，FR-6.5）
攔下這次事件，顯示「正在存」（FR-6.9）
   │
   ▼
負責檔案存取的那一層：讀剪貼簿 → 逐張決定格式（R-15／R-16）→ 逐張以 UUID 命名（R-14）
        → 需要時轉成 PNG → 建立 images/（R-13）→ 寫檔
   │
   ├─ 任何一張失敗 ─▶ 不插入任何語法，畫面上說出原因（R-19）
   │
   ▼ 全部成功
一個交易插入所有語法（FR-6.6），游標停在最後一張的 alt 位置（FR-6.4）
   │
   ▼
undo 歷史上這是一步（FR-6.3）；預覽在渲染那一刻把相對路徑改寫成 rustle: URL（FR-5.9）
```

### 3.2 預覽怎麼看見一張相對路徑的圖（§7.4 第一列陷阱）

```
檔案裡           ![](images/8f3c.png)                    ← 永遠是這個（R-17）
   │
   ▼ 渲染那一刻
預覽的 HTML      <img src="rustle://vault/Blog/images/8f3c.png">
   │
   ▼ 預覽載入圖片時發出這個請求
負責檔案存取的那一層的 handler  只認得 {workspace}/images/{檔名}，其餘一律拒絕
   │
   ▼ 交給 VaultScope（唯一的路徑守門人）→ 解析符號連結 → 包含判斷
圖片的位元 + media type
```

### 3.3 一次失敗的貼上

```
寫檔失敗（磁碟滿／權限不足／images 是指向 vault 外的連結）
   │
   ▼
負責檔案存取的那一層回傳失敗（帶原因），正文一個字都不動
   │
   ▼
畫面上一行非阻斷訊息；寫作者可以繼續打字，什麼都沒有被擋住
```

## 4. 驗收標準（Gherkin）

「編輯區」指欄 3；「預覽」指欄 4；「正文」指編輯區手上的內容。

### Feature：`rustle:` 只服務 vault 底下的圖片（NFR-4、NFR-7、§7.3 安全基線）

```gherkin
# TC-26
場景: 服務一張真的圖片
  假設 "Blog/images/8f3c.png" 存在

    | ".webp"| "image/webp"    |
    | ".bmp" | "image/bmp"     |
    | ".tif" | "image/tiff"    |
    | ".tiff"| "image/tiff"    |

# TC-28
場景: 檔案不存在

  那麼 回應是 404
  並且 回應裡沒有出現 vault 的絕對路徑

場景: 拒絕一切不是「某個 workspace 的 images 底下的一個圖片」的請求

  那麼 回應不是成功
  並且 沒有任何檔案的位元被回出去

    | 請求                                              | 為什麼                     |

    | "rustle://vault/Blog/images/"                      | 沒有檔名                   |
    | "rustle://vault/Blog/x.png"                        | 少了 images 那一段         |
    | "rustle://elsewhere/Blog/images/x.png"             | host 不是 vault            |
```

## 5. 非功能驗收（不是 Gherkin，因為無頭環境量不到）

| 項目 | 判準 | 怎麼驗 |
| :--- | :--- | :--- |
| 大圖不凍結（FR-6.9） | 貼一張 > 10MB 的圖，寫檔期間畫面照樣重繪、編輯區照樣可以打字 | 實機。觀察「正在存」指示的出現與消失來量測，不要倚賴計時器——視窗未聚焦時，GUI 框架可能把計時器節流到很慢、暫停逐幀回呼；實作時須確認所選 GUI 框架的行為 |
| 完全離線（NFR-2） | 貼上與預覽顯示圖片的整個過程沒有任何對外請求 | 實機：正式版本的 `connect-src 'none'` 與 `img-src` 未被放寬 |
| 輸入法（T-1 ~ T-12） | 本切片新增一個綁 paste 的處理器，發佈檢查清單要求重跑 | 人工 runbook |
