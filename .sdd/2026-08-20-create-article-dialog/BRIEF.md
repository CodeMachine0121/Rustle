# 需求共識 — 建立文章對話框（GUI metadata 設定）

- **切片**：Wave 3, `feature/create-article-dialog`
- **日期**：2026-08-20
- **輸入**：需求文件 §4.4（FR-3.1~FR-3.8）、§4.3（FR-2.5）、§3.2（R-6~R-9 的呼叫端）、§6.2（FR-8.6）、§6.3（T-9）、§7.3 分層與安全基線
- **狀態**：需求已定案（v0.3），本階段不回頭問使用者。文件留白處由本檔 §7「假設」一次裁決，並同步寫進 PR 說明

---

## 1. 這個切片要解決的問題

需求文件 §4.4 的第一句話是「**這是本產品最關鍵的互動**」。它關鍵不是因為畫面難做，而是因為這個對話框是**整個產品唯一一次讓使用者看到 metadata 的地方**：在這裡填完標題、分類、標籤，按下建立，之後每天寫作眼前只有正文，永遠不會再看到 `---` 或 YAML。前四個切片把「檔案怎麼讀、正文怎麼存、清單怎麼列」都做完了，但**在 App 裡建立一篇文章至今做不到**——輸入法回歸清單的前置步驟現在還寫著「手動建檔是目前唯一的辦法」。

```
      按下「＋ 新文章」                        送出之後
  ┌──────────────────────┐        ┌───────────────────────────────┐
  │  新文章               │        │ 欄 2 多一列並被選取             │
  │  Title  [__________]  │        │ 檔名由標題產生（撞名自動編號）    │
  │  Category [技術筆記×] │  ───▶  │ 檔頭寫進 front matter           │
  │  Tags   [electron ×]  │        │ 欄 3 的游標停在第一行            │
  │  建立於 2026-08-20 …  │        │ ——使用者直接開始打字             │
  │        [取消] [建立]  │        └───────────────────────────────┘
  └──────────────────────┘
```

**真正困難的地方有兩個，都不在畫面上。**

第一個是 `Enter`。這個對話框有三個文字輸入欄位，而 `Enter` 在中文輸入法裡是「確定選字」。需求文件 FR-3.8 與 FR-8.6 明文規定：組字中的 `Enter` 一律屬於輸入法，**不得**被解讀為送出表單或建立 chip。T-9 這一項人工回歸測試就是為這個對話框寫的，它現在還標著「待驗」。欄 1 的「新 workspace 名稱」欄位已經踩過一次這個坑，做法是**刻意不用會隱性送出的表單**——因為單一欄位的表單會在 `Enter` 時自己送出，而要可靠地攔住那個隱性送出是一場打不贏的仗。

第二個是 `Esc` 與磁碟。FR-3.7 要求取消不建立任何檔案；而這個切片是**全專案第一個真的建立檔案的切片**，所以它同時要關掉發佈檢查清單的 S-2：目標檔案在檢查那一刻還不存在，`realpath` 用不上，範圍檢查必須改成解析**父資料夾**。

## 2. 對誰有價值

| 角色 | 拿到什麼 |
| :--- | :--- |
| 寫作者 | 在 App 裡建立文章。填三個欄位、按建立、游標已經在編輯區第一行，可以直接打字 |
| 寫中文的寫作者 | 三個欄位的 `Enter` 都屬於輸入法，選字不會誤送出、不會誤生 chip |
| 想維持詞彙一致的寫作者 | 分類與標籤的候選來自這個 workspace 已經用過的詞，「技術筆記」不會又長出一個「技術」 |
| 不想為檔名做決定的寫作者 | 檔名由標題產生，中文標題保留中文，撞名自動編號，全程不問 |
| 之後每天寫作的自己 | 檔頭的 front matter 是自我描述的，這個檔案丟進 Obsidian／Hugo／Git 都認得 |
| 輸入法回歸清單 | T-9 從「待驗」變成真的可以跑；前置步驟不再需要手動建檔 |
| 後續切片（事後編輯 metadata，Wave 4） | 一個已經證明「GUI 表單 + chip 輸入 + 自動補全」可行的形狀，以及可重用的 chip 輸入元件 |
| 全專案的安全基線 | 發佈檢查清單 S-2 的最後一半（建立不存在的檔案）關掉 |

## 3. 成功的樣子（可觀察的行為）

1. 欄 2 有一個「＋ 新文章」按鈕；workspace 裡 0 篇文章時，空狀態上也有一個入口。
2. 對話框有三個欄位：Title（單行、必填）、Category（多值）、Tags（多值）。
3. 建立時間只以「建立於 2026-08-20 14:32」這樣的文字出現，**沒有任何可填的時間欄位**。
4. 分類與標籤是 chip：打字後按 `Enter` 或 `,` 成為一個 chip，`Backspace` 或點 × 移除。
5. 打字時出現候選，候選來自當前 workspace 既有的所有分類／標籤；點一下就成為 chip。
6. Title 為空時「建立」是停用的，而且畫面上說得出為什麼。
7. `Esc` 或「取消」關掉對話框，磁碟上什麼都沒有多出來。
8. 組字中按 `Enter`：不送出、不建立 chip。選完字之後再按一次才會。
9. 送出之後，一個新的 `.md` 出現在 workspace 裡，檔名由標題產生，檔頭是需求文件 §3.2 的那個形狀。
10. 那一列出現在欄 2 並被選取，欄 1 的篇數跟著加一。
11. 欄 3 的編輯區拿到焦點，游標在第一行——使用者不必再點一下就能打字。
12. workspace 資料夾是一個指向 vault 外的符號連結時，建立被拒絕，而且 vault 外一個位元都沒被寫出。

## 5. 具體例子（釘住邊界與例外）

### 5.1 一次成功的建立

使用者在 workspace `Blog` 裡按「＋ 新文章」，填 Title「Tauri 與 Electron 的取捨」、Category 兩個 chip「技術筆記」「桌面開發」、Tags 兩個 chip「tauri」「electron」，按建立。`Blog/` 裡出現 `tauri-與-electron-的取捨.md`，內容一個位元不多不少：

````markdown
---
title: Tauri 與 Electron 的取捨
created_at: 2026-08-20T14:32:05.000Z
updated_at: 2026-08-20T14:32:05.000Z
category:
  - 技術筆記
  - 桌面開發
tags:
  - tauri
  - electron
---
````

正文是空的——沒有模板、沒有把標題再寫成一行 `#`。使用者要打的第一個字就是這篇文章的第一個字（假設 A-2）。`created_at` 與 `updated_at` 都是建立那一刻，時間格式與檔案系統的修改時間同一種（UTC 並把時區寫出來），這是自動儲存切片已經定下的形狀。

### 5.2 撞名

| workspace 裡已經有 | 新標題 | 產生的檔名 |
| :--- | :--- | :--- |
| （空的） | `Zen of Writing` | `zen-of-writing.md` |
| `zen-of-writing.md` | `Zen of Writing` | `zen-of-writing-2.md` |
| `zen-of-writing.md`、`zen-of-writing-2.md` | `Zen of Writing` | `zen-of-writing-3.md` |
| `ZEN-OF-WRITING.MD` | `Zen of Writing` | `zen-of-writing-2.md`（比對不分大小寫，因為檔案系統也不分） |
| 一個叫 `notes.md` 的**資料夾** | `Notes` | `notes-2.md`（撞名比對看的是資料夾裡的每一個名字，不只文章） |
| `!!!.md` | `!!!` | `untitled.md`（標題被清成空字串時的替代名，`ArticleFileNameSlug` 已定） |

### 5.3 chip 的四種操作

| 操作 | 結果 |
| :--- | :--- |
| 打「技術筆記」按 `Enter` | 一個 chip「技術筆記」，輸入框清空 |
| 打「tauri」按 `,` | 一個 chip「tauri」，輸入框清空 |
| 輸入框是空的時候按 `Backspace` | 最後一個 chip 被移除 |
| 輸入框還有字的時候按 `Backspace` | 只刪一個字，chip 一個都不動 |
| 點某個 chip 的 × | 只有那一個被移除 |
| 打「　技術筆記　」（前後空白）按 `Enter` | chip 是「技術筆記」（空白修掉） |
| 只打空白按 `Enter` | 什麼都不發生 |
| 打一個已經有的值按 `Enter` | 不重複新增，輸入框清空 |

### 5.4 候選（為什麼候選的來源比小工具本身重要）

`Blog` 裡三篇文章的 front matter 分別用了 `category: [技術筆記]`、`category: [技術筆記, 桌面開發]`、`tags: [electron]`。開啟對話框、在 Category 欄位打「技」：候選是「技術筆記」一個（去重過），點一下成為 chip。打「TECH」：沒有候選。已經選了「技術筆記」之後再打「技」：候選是空的（已經選的不再出現）。

需求文件 FR-3.4 把目的寫出來了：**降低同義詞漂移（「技術筆記」vs「技術」）**。所以候選必須來自「這個 workspace 真的用過的詞」，不是一份寫死的清單、也不是全 vault 的詞——換 workspace 就換一組詞彙，這是 workspace 的意義。

### 5.5 `Esc` 與磁碟

| 情況 | 結果 |
| :--- | :--- |
| 填了標題但按 `Esc` | 對話框關閉。workspace 資料夾的內容一個位元都沒變，也沒有暫存檔 |
| 按「取消」 | 同上 |
| **組字中**按 `Esc` | 對話框**不關**——那一次 `Esc` 屬於輸入法（FR-8.7） |
| 標題是空白就送出（畫面層已經擋住，但負責檔案存取的那一層不信任畫面層） | 負責檔案存取的那一層拒絕，磁碟上什麼都沒有出現 |
| 送出之後負責檔案存取的那一層答不出來（磁碟滿、權限不足） | 對話框留著、說得出原因，使用者可以再試一次 |

### 5.6 組字中的 `Enter`（T-9 就是這一條）

使用者在 Title 欄位打注音 `ㄊㄞˊ`，候選視窗開著。按 `Enter` 選字：**只確定選字**，表單不送出。再按一次 `Enter`：這次才送出。同一條規則在 Category 與 Tags 欄位是「不建立 chip」——第一次 `Enter` 確定選字，第二次才成為 chip。判斷用兩種問法：按鍵事件自己帶的「正在組字」標記，以及全畫面共用的組字狀態；欄 1 的名稱欄位已經證明任何一種單獨用都曾經答錯。

### 5.7 游標落在第一行（FR-3.6 的最後一步）

建立完成之後，使用者**不必再點任何東西**就能打字。這一步是這個切片的產品承諾，也是最容易做掉一半的一步：清單那一列出現了、編輯區也換成新文章了，但焦點還留在剛剛關掉的對話框上，於是使用者打的第一個字掉進虛空。所以「編輯區拿到焦點、游標在第一行」是驗收標準，不是收尾的細節。

## 7. 假設（需求文件沒寫，本切片一次裁決）

| # | 假設 | 為什麼這樣選 |
| :--- | :--- | :--- |
| A-1 | **入口放在欄 2**：清單上方一個「＋ 新文章」按鈕，0 篇時空狀態裡再放一個 | FR-2.5 把按鈕寫在欄 2 的需求裡，FR-2.8 的空狀態文案是「建立第一篇文章」。兩個入口，同一個對話框 |
| A-2 | **新文章的正文是空的**，不放模板、不把標題再寫成一行標題 | FR-3.6 的承諾是「使用者可立刻開始打字」。任何預先塞進去的字都得先被刪掉才能寫，而且會讓「第一行」不再是第一行 |
| A-3 | 「建立於 …」顯示的是**對話框開啟那一刻的本機時間**到分鐘；寫進檔案的權威值由負責檔案存取的那一層在建立那一刻取 | 需求只要求「以文字顯示、由系統帶入」。畫面層不該決定檔案裡的時間（分層原則），而顯示一個到分鐘的近似值與寫進去的值差幾秒，對使用者沒有意義 |
| A-4 | **`updated_at` 不另外顯示一行**，只顯示「建立於 …」並註明兩個時間都由 Rustle 自動維護 | FR-3.2 要的是「不出現為可填欄位」。建立當下 `updated_at` 等於 `created_at`，多印一行一樣的時間是雜訊 |
| A-5 | 候選**只在輸入框有文字時**出現 | FR-3.4 寫的是「輸入時自動補全」。欄位一聚焦就攤開整份詞彙表會讓對話框變吵，而且它不是選單，是輸入欄位 |
| A-6 | chip 的重複比對是**修掉前後空白後的字面比對，區分大小寫** | 把 `Electron` 與 `electron` 視為同一個等於幫使用者改字。防止大小寫漂移是自動補全的工作（A-5 的候選），不是去重規則的工作 |
| A-7 | `Enter` 在 Title 欄位是**送出**，在 chip 欄位是**建立 chip、永不送出** | T-9 明寫「選完字後再按一次 `Enter` 才建立 chip／送出」。如果 chip 欄位的第二次 `Enter` 會送出，那就沒有一次 `Enter` 能建立 chip 了 |
| A-8 | 送出時 chip 欄位裡**還沒變成 chip 的文字也一起收成 chip** | 使用者剛打完「桌面開發」就去按建立是很自然的動作，讓它無聲消失是最糟的選擇 |
| A-9 | 建立成功、但「離開當前文章」被自動儲存拒絕時（未回答的外部改動警示／上一次寫檔失敗），**仍然算建立成功**：對話框關閉，畫面不換過去 | 檔案真的在磁碟上，說它失敗是說謊。為什麼沒換過去，標題列已經在說（自動儲存切片的規則），對話框沒有第二句話要補 |
| A-10 | 建立成功後**重讀整個文章清單**，而不是把回傳的那一列插進清單 | 排序規則住在負責檔案存取的那一層（`WorkspaceContents`）。在畫面層插一列就等於在畫面層複製一份排序規則，兩份規則遲早不一樣 |
| A-11 | 建立成功後**也重讀 workspace 清單**，讓欄 1 的篇數不落後 | FR-1.1 要求顯示文章數。建立一篇之後那個數字就錯了，而它與新出現的那一列在同一個畫面上互相打臉 |
| A-12 | 負責檔案存取的那一層**不信任畫面層**：標題是空白的建立請求一律拒絕（走一般失敗） | §7.3 的分層與安全基線。`ChannelFailure` 沒有「業務拒絕」這種原因，而回覆型別是 `ArticleSummary`，說不出「被擋下」——所以它走失敗，而畫面層本來就不會送出（FR-3.5 停用按鈕） |
| A-13 | 建立用「**不存在才建立**」的開檔方式；撞名就失敗，不覆蓋 | 檔名編號已經先避開撞名，這一層是最後防線：兩次點擊之間、或別的程式剛好放了同名檔案時，寧可失敗也不能蓋掉別人的文章 |
| A-14 | 建立**不走**「暫存檔 + rename」 | `rename` 會蓋掉已經存在的檔案，而建立最重要的性質正是「絕不蓋掉任何東西」。R-11 的原子寫入針對的是「替換既有檔案」；建立的正確形態是「不存在才建立 + 落磁碟」 |
| A-15 | ~~**文章換進編輯區的那一刻就把焦點與游標交給編輯區**，不只有建立那一次~~ **→ 已被 review 推翻，見 §9** | 原本的理由是「打開一篇文章就是可以開始打字」。它對滑鼠成立，對鍵盤是回歸：啟動欄 2 的一列就被丟進編輯區，而回去的唯一路徑是 `Esc` 再 `Tab` 再重走一次清單——那條路徑存在的理由本來就是讓鍵盤使用者**去**清單。現在只有剛建立的那一篇會拿到游標 |
| A-16 | 逗號只在**按鍵那一刻**成為 chip；貼上一串含逗號的文字不拆開 | 需求寫的是「按 Enter 或 `,`」。貼上拆解是另一條路徑，值得等到真的有人抱怨再做 |

## 8. review 之後的裁決（`/contract` 之後回頭改的，不是記憶）

| # | 裁決 | 為什麼 |
| :--- | :--- | :--- |
| R-1 | **游標交接只發生在「剛建立的那一篇」**，用清單打開一篇文章時焦點留在清單 | A-15 的寬版打壞了欄 2 的鍵盤操作（見上表）。寬版對**滑鼠**確實是主流慣例（Obsidian／Bear／VS Code 都這樣），所以哪天真要它，正確的形狀是「滑鼠啟動交出、鍵盤啟動不交」，而不是「文件換了就交」——那需要一條需求，現在沒有。**「用哪一篇判斷換文件」留著**：undo 不再退回上一篇是它關掉的，與焦點無關 |
| R-2 | **`created_at`／`updated_at` 寫成帶當地位移的 ISO 8601**（`2026-08-20T00:30:00+08:00`），與需求文件 §3.2 的範例同形 | 清單那一列直接取前 10 個字當日期（刻意不重新格式化，否則會被機器的時區重新解讀）。原本寫成 UTC 的 `Z`，於是台北時間 00:00–08:00 建立的文章在清單上顯示**前一天**，而同一秒的對話框說的是今天。檔案系統的修改時間仍然是 UTC——那些只互相比較，不給人看 |
| R-3 | **名字在建立那一刻被佔用時，說出是哪一篇擋著**，不把檔案系統的原話（含 vault 絕對路徑）丟到畫面上 | 檔名是從清單算出來的，所以中間有一個縫；兩次點擊或兩個視窗會落進去。拒絕本身是對的（「不存在才建立」買到的就是這個），要修的是那句話 |

## 9. 不做的技術決定（留給實作階段）

哪個物件放哪一層、`VaultScope` 多出哪一個方法、對話框拆成幾個元件——那些是 `/architecture` 的事，不在本檔。本檔只釘住「使用者看得到什麼、什麼情況算成功、哪些情況我們明確不處理」。
