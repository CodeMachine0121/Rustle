- **切片**：Wave 3, `feature/create-article-dialog`
- **上游文件**：[BRIEF.md](BRIEF.md)、需求文件 §4.4、§4.3（FR-2.5）、§3.2（R-6、R-9）、§6.2、§7.3
- **覆蓋需求 ID**：FR-3.1、FR-3.2、FR-3.3、FR-3.4、FR-3.5、FR-3.6、FR-3.7、FR-3.8、FR-2.5；R-6 與 R-9 的第一個真實呼叫者；橫切約束 FR-8.6（三個新的文字輸入欄位）、FR-8.7（組字中的 `Esc`）；非功能 NFR-4（vault 範圍檢查，發佈檢查清單 S-2）、NFR-7（不回歸）
- **人工回歸項目**：T-9（**本切片就是它的受測對象**，交付後從「待驗」變成可跑）、T-6（新增了綁 `Enter` 的欄位）、T-11（本切片新增一條「把文章換進編輯區」的路徑）

## 1. 目標

讓寫作者在 App 裡建立一篇文章：在一個 GUI 對話框裡填標題、分類、標籤，按下建立之後檔案落地、清單出現那一列並被選取、游標停在編輯區第一行。metadata 只在這裡輸入，之後寫作時眼前只有正文。

四件不可妥協的事：

- **`Enter` 在組字中屬於輸入法**（FR-3.8／FR-8.6）：三個欄位都不得把選字誤判為送出或建立 chip。
- **`Esc` 取消不建立任何檔案**（FR-3.7），而且這一點要在真實檔案系統上驗得到。
- **送出之後游標落在編輯區第一行**（FR-3.6）：使用者不必再點任何東西就能打字——而且**只有這一次**，用清單打開一篇文章時焦點留在清單（否則就打壞了 FR-7.7 那條「鍵盤使用者去清單」的路徑）。
- **建立一個還不存在的檔案也要過 vault 範圍檢查**（NFR-4／發佈檢查清單 S-2）：解析父資料夾的符號連結。

## 2. User Stories

| ID | 故事 |
| :--- | :--- |
| **US-1** | 作為寫作者，我要在欄 2 按一個按鈕就開始建立文章，這樣我不必離開 App 去手動建檔 |
| **US-2** | 作為寫作者，我要在一個表單裡填完標題、分類、標籤，這樣之後寫作時我永遠不必看到 YAML |
| **US-3** | 作為寫作者，我要分類與標籤用 chip 輸入，打完按 `Enter` 或逗號就成為一片、按 `Backspace` 或點 × 就移除，這樣我不必自己處理分隔符號 |
| **US-4** | 作為想維持詞彙一致的寫作者，我要輸入分類與標籤時看到這個 workspace 已經用過的詞，這樣我不會又長出一個「技術」跟「技術筆記」並存 |
| **US-5** | 作為寫作者，我要標題沒填時「建立」按不下去而且看得到原因，這樣我不會建出一篇沒有標題的文章 |
| **US-6** | 作為寫作者，我要 `Esc` 就能反悔，而且磁碟上什麼都沒留下，這樣打開對話框不是一個需要承諾的動作 |
| **US-7** | 作為寫作者，我要送出之後檔名自己產生、front matter 自己寫好、清單自己出現那一列並選取、游標自己落在第一行，這樣我可以立刻開始打字 |
| **US-8** | 作為寫中文的寫作者，我要在三個欄位裡用注音打字並用 `Enter` 選字，而不會誤送出表單、誤生 chip、或誤關對話框 |
| **US-9** | 作為使用者，我要 App 只在 vault 裡建立檔案——就算 workspace 資料夾是一個指向外面的符號連結，也不能因此在 vault 外寫出東西 |
| **US-10** | 作為使用者，我要建立永遠不覆蓋既有檔案，這樣一次誤觸不會蓋掉我寫了三小時的文章 |

## 3. 業務流程

### 3.1 開啟對話框

```
使用者按「＋ 新文章」（或空狀態的「建立第一篇文章」）
  → 對話框出現，Title 欄位拿到焦點
  ├─ 讀出當前 workspace 既有的所有分類與標籤，當作候選詞彙
  └─ 記下這一刻的時間，顯示成「建立於 2026-08-20 14:32」
```

### 3.2 一次 chip 輸入

```
使用者在 Category 或 Tags 欄位打字
  ├─ 組字中 → 什麼都不做（按鍵屬於輸入法）
  ├─ 按 Enter 或 , → 修掉前後空白 → 空的丟掉 → 重複的丟掉 → 成為一個 chip
  ├─ 按 Backspace 且輸入框是空的 → 移除最後一個 chip
  ├─ 點某個 chip 的 × → 移除那一個
  └─ 打字時 → 候選 = 既有詞彙 ∩ 含這段文字（不分大小寫） − 已經選了的
             點候選 → 成為一個 chip
```

### 3.3 一次「建立文章」

```
使用者按「建立」（或在 Title 欄位按 Enter）
  → 畫面層：把還沒成為 chip 的文字收成 chip，送出 { workspace, 標題, 分類, 標籤 }
  → 負責檔案存取的那一層：
     ├─ 正規化：標題修空白（空的→拒絕）、分類與標籤修空白/去空/去重
     ├─ 列出 workspace 資料夾第一層的每一個名字
     ├─ 由標題產生檔名 slug，與那些名字比對，撞名就加 -2、-3…
     ├─ 取現在的時間，created_at 與 updated_at 都用它
     ├─ 組出檔案內容：front matter（title / created_at / updated_at / category / tags）＋ 空正文
     ├─ 解析 workspace 資料夾的符號連結並做包含判斷 → 逃出 vault 就拒絕
     └─ 以「不存在才建立」的方式寫檔並落磁碟 → 撞名就失敗，絕不覆蓋
  → 回覆那一列（reference + 檔案自己說的 metadata）
  → 畫面層：
     ├─ 重讀文章清單（那一列依清單規則出現在該出現的位置）
     ├─ 重讀 workspace 清單（欄 1 的篇數跟著加一）
     ├─ 開啟那一篇（先寫掉上一篇；被拒絕就停在原地，但文章已經建立）
     ├─ 記住位置到設定檔
     └─ 關閉對話框
```

### 3.4 把游標交給編輯區

```
編輯區收到「這是另一篇文章」
  ├─ 組字中 → 等組字結束
  └─ 把新文件換進同一個編輯區（不重建它）
     → 編輯區拿到焦點，游標在文件開頭（第一行第一個字）
```

### 3.5 取消

```
使用者按 Esc 或「取消」
  ├─ 組字中的 Esc → 交給輸入法，對話框不關
  └─ 否則 → 對話框關閉，什麼請求都沒有送出，磁碟上什麼都沒有多出來
```
