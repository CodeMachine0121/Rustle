## 1. 目標

左欄從「一排 workspace」變成**分區的側欄**：Workspace 一區、狀態一區、標籤一區，每一區都能折疊並記住。點狀態或點標籤就收窄右邊的文章清單，兩邊同時選時要同時符合。新增 **All Notes** 入口，讓寫作者一次看到 vault 裡所有 workspace 的文章。同時讓**分類**整個退場，換成**狀態**——一篇文章只有一個，只能是固定四個之一。

要解決的問題只有一個：**寫作者不必記得文章放在哪個 workspace，也能靠「這篇進行到哪了」與「這篇講什麼」把它找出來。**

## 2. User Stories

| # | 身為 | 我想要 | 以便 |
| :--- | :--- | :--- | :--- |
| US-1 | 寫作者 | 在左欄看到 Active／On Hold／Completed／Dropped／No Status 各有幾篇 | 一眼知道手上有幾件還沒寫完 |
| US-2 | 寫作者 | 點一個狀態就只看那個狀態的文章 | 今天只處理「進行中」的那幾篇 |
| US-3 | 寫作者 | 點幾個標籤就只看同時帶著它們的文章 | 用主題把文章找出來，而不是靠回想檔案放在哪 |
| US-4 | 寫作者 | 一個 All Notes 入口列出所有 workspace 的文章 | 忘記文章在哪個 workspace 時照樣找得到 |
| US-5 | 寫作者 | 建立文章時就能選狀態，之後也能改 | 狀態跟著寫作進度走，而不是一次填完就作廢 |
| US-6 | 寫作者 | 把用不到的分區折疊起來，下次開 App 還是收著的 | 左欄只留我現在真的在用的角度 |
| US-7 | 用了很久 Rustle 的寫作者 | 舊檔案裡的分類原樣留著 | 分類退場不會動到我硬碟上任何一個字 |

## 3. 業務流程

### 3.1 左欄長什麼樣

```
┌──────────────────────────┐
│ All Notes                │  ← 與「選某一個 workspace」互斥
├──────────────────────────┤
│ WORKSPACES        ▾      │  ← 標題可點，折疊／展開；折疊狀態記在設定檔
│   Blog              12   │
│   Work               3   │
│   ＋ 新 workspace        │
├──────────────────────────┤
│ STATUS            ▾      │
│   ● Active           3   │  ← 五列永遠都在，0 也顯示
│   ● On Hold          1   │
│   ● Completed        0   │
│   ● Dropped          0   │
│   ○ No Status        2   │
├──────────────────────────┤
│ TAGS              ▾      │
│   work               4   │  ← 篇數多到少，同篇數以名稱升序
│   bug                1   │
└──────────────────────────┘
```

### 3.2 文章清單畫哪幾列

```
當前範圍的全部文章
   （選了 workspace → 那個 workspace；選了 All Notes → 所有 workspace）
        │
        ├──────────────▶ 狀態區與標籤區的篇數（永遠算整個範圍，不受任何選取影響）
        │
        ├──────────────▶ metadata 表單的標籤候選（永遠是整個範圍）
        │
        ▼
   側欄的過濾：狀態（最多一個）＋ 標籤（多選，且要全部都有）
        │
        ▼
   文字篩選框：不分大小寫比對「標題」與「標籤」（**不再比對分類**）
        │
        ├─ 正在編輯的那篇被收掉了？ → 仍然保留它那一列，並標示「開著的」
        │
        ▼
   排序（建立時間新到舊／標題／更新時間新到舊）
        │
        ▼
   畫出來的列（All Notes 之下每一列還說得出自己屬於哪個 workspace）
```

三道收窄是**獨立且疊加**的。任何一道都不選取、不開啟、不關閉任何文章，也不向磁碟要求任何事。

### 3.3 一次狀態選取

```
點 Active
   ├─ 原本沒選 → 選上 Active
   ├─ 原本選著 Active → 取消選取（回到沒有狀態過濾）
   └─ 原本選著 Completed → 只剩 Active（Completed 自動放掉）
```

### 3.4 一次標籤選取

```
點 work  → work 選上
點 bug   → work 與 bug 都選上（文章要「兩個都有」）
再點 bug → 只剩 work
```

### 3.5 換範圍

```
選 workspace「Blog」  ──▶ 清空狀態選取與標籤選取 ──▶ 列 Blog 的文章
選 All Notes          ──▶ 清空狀態選取與標籤選取 ──▶ 列所有 workspace 的文章
```

清空的理由：帶著過濾切過去，會讓一個明明有文章的 workspace 因為**畫面外的原因**看起來是空的。

### 3.6 檔案裡的狀態

```
讀檔：status 是那四個之一？
        ├─ 是 → 這篇就是那個狀態
        └─ 否（包含沒有 status 這個鍵） → 這篇沒有狀態
              └─ 而且那一行**永遠不被改寫、不被刪除**

寫檔：寫作者主動選了四個之中的一個 → 寫進去（取代原本那一行）
      寫作者主動選了 No Status      → 只有原本是那四個之一時才把鍵移掉
      沒有動到狀態的存檔（自動儲存正文） → 完全不動 status 這一行
```

## 4. 驗收標準（Gherkin）

以下用語一律照通用語言地圖：「清單」指文章清單畫出來的列；「範圍」指當前選的 workspace，或 All Notes 之下的所有 workspace；「開著的那篇」指編輯區當前持有、儲存機制綁著的那一篇。

### Feature：一篇文章只有一個狀態，且只能是那四個之一

```gherkin
# TC-01
場景: 建立文章時選了狀態
  假設 建立文章的表單裡狀態選了 Active
  當 文章建立完成
  那麼 這篇的狀態是 Active

# TC-02
場景: 建立文章時沒有選狀態
  假設 建立文章的表單裡狀態留在 No Status
  當 文章建立完成
  那麼 這篇沒有狀態
  並且 它被算進側欄狀態區的 No Status 那一列

# TC-03
場景: 事後把狀態改掉
  假設 一篇狀態是 Active 的文章
  當 在編輯 metadata 的表單裡把狀態改成 Completed
  那麼 這篇的狀態是 Completed
  並且 這篇不再算進 Active

# TC-04
場景: 表單只提供那五個選項
  假設 打開編輯 metadata 的表單
  當 看狀態欄位
  那麼 可選的只有 Active、On Hold、Completed、Dropped、No Status 五個
  並且 沒有任何可以自己輸入狀態的地方

# TC-05
場景: 檔案裡記著一個認不出來的狀態
  假設 一篇文章的檔案裡狀態那一行寫著「進行中」
  當 開啟這篇
  那麼 這篇當成沒有狀態
  並且 它被算進 No Status 那一列

# TC-06
場景: 認不出來的狀態存檔後原樣還在
  假設 一篇文章的檔案裡狀態那一行寫著「進行中」
  當 寫作者改了正文並存檔
  那麼 檔案裡「進行中」那一行原樣還在

# TC-07
場景: 認不出來的狀態不會被「No Status」清掉
  假設 一篇文章的檔案裡狀態那一行寫著「進行中」
  當 寫作者在編輯 metadata 的表單裡不動狀態（顯示的是 No Status）並儲存
  那麼 檔案裡「進行中」那一行原樣還在

# TC-08
場景: 主動選一個狀態會取代認不出來的那一行
  假設 一篇文章的檔案裡狀態那一行寫著「進行中」
  當 寫作者在編輯 metadata 的表單裡把狀態選成 Active 並儲存
  那麼 這篇的狀態是 Active
  並且 檔案裡再也沒有「進行中」

# TC-09
場景: 把狀態清掉
  假設 一篇狀態是 Active 的文章
  當 寫作者在編輯 metadata 的表單裡把狀態改成 No Status 並儲存
  那麼 這篇沒有狀態
  並且 檔案裡沒有狀態那一行

# TC-10
場景: 改狀態不會動到檔案裡其他任何東西
  假設 一篇文章的檔案裡有寫作者自己加的欄位、註解、以及分類
  當 寫作者把狀態改成 Active 並儲存
  那麼 狀態被寫進去
  並且 那些欄位、註解與分類原樣還在，順序也沒有變
```

## 5. 這份規格做的決定（BRIEF「Open Decisions」的答案）

BRIEF 留了六個決定給本檔。逐條的答案與理由：

| BRIEF 的問題 | 決定 | 為什麼 |
| :--- | :--- | :--- |
| 狀態的畫面文字用英文還是中文 | **英文**：Active、On Hold、Completed、Dropped | 與範例 App 一致，也與既有的大寫英文區塊標題（WORKSPACES／ARTICLES）同一種語言。表單裡既有的欄位提示（Title／Tags）本來也是英文 |
| 「未設定」那一列的畫面文字 | **「No Status」** | 同上一條。它與另外四個是同一組選項，同一種語言才讀得成一組 |
| 分區標題的畫面文字 | **WORKSPACES／STATUS／TAGS**；跨 workspace 入口是 **All Notes** | 沿用既有的大寫英文區塊標題 |
| 標籤區怎麼排 | **篇數多到少，同篇數以標籤名升序** | 最常用的在最上面是這一區存在的理由；同篇數要有一個固定的第二鍵，否則每次畫出來順序會跳 |
| 標籤區的篇數是否受狀態過濾影響 | **不受影響。** 篇數一律算當前範圍的全部文章，不受狀態選取、標籤選取、文字篩選框影響 | 一個會隨另一個面向的選取而變的數字是**循環**的：選了 Active 之後 work 顯示 3，取消之後顯示 7，寫作者無法預測下一次會看到什麼。恆定回答「這個範圍裡有幾篇帶著它」才是可以信的數字。TC-17 與 TC-24 守著這件事 |
| All Notes 之下的排序並列怎麼定 | 三種排序的**意義不變**；並列時以 workspace 名稱升序，再以檔名升序 | 排序要是全序，否則同一份資料每次畫出來的順序不一樣。既有的「同分以標題定序」保留在前面，workspace 接在標題之後、檔名之前 |
| 切換 workspace 是否清空狀態與標籤選取 | **清空**（選 All Notes 也清空） | 帶著過濾切過去，會讓一個明明有文章的 workspace 因為畫面外的原因看起來是空的。TC-34、TC-35 |

另外三個 BRIEF 沒問、但實作必須有答案的決定：

| 問題 | 決定 | 為什麼 |
| :--- | :--- | :--- |
| 認不出來的狀態，「No Status」儲存時要不要清掉它 | **不清。** 只有原本是那四個之一時，選 No Status 才會把鍵移掉 | BRIEF 明文：「檔案裡原本那行字不能被改掉或清掉」。表單開起來顯示的是 No Status（因為認不出來），寫作者按儲存並沒有表達「請刪掉那一行」的意思。要取代它，主動選四個之中的一個即可（TC-07、TC-08） |
| All Notes 要不要跨重啟記住 | **不記。** 設定檔記的仍然是上次開的 workspace 與文章 | All Notes 不是一個位置，是一個看法。從 All Notes 打開一篇文章時，記住的是那篇文章與它所屬的 workspace——下次開 App 直接回到那篇，這比回到一份跨 vault 的清單更接近「把寫作者放回上次的位置」 |
| All Notes 之下能不能改 metadata、刪文章 | **能。** 兩者都作用在那一列自己所屬的 workspace | 那些按鈕就在列上。在 All Notes 之下讓它們失效，等於畫一個按不動的按鈕；而「這一列屬於哪個 workspace」是清單本來就知道的事（TC-32） |

## 6. 不做（範圍邊界）

見 [BRIEF.md](BRIEF.md)「Out of Scope」。其中四條最容易被誤判成「漏做」，在此重述：

1. **純外觀不在本切片的驗收範圍**。重點色、字級、間距、圓角、卡片與膠囊樣式由 `feature/visual-theme-refresh` 獨立處理。本切片會為新的側欄結構寫樣式，但**只引用**那條分支定義的設計變數名稱，一個都不定義。
2. **不做一次性資料搬遷**。舊檔案的分類不搬成標籤、不搬成狀態、不刪除。BRIEF 明文選的是「完全不動它」。
3. **不做全文搜尋**。文字篩選框的比對範圍從「標題／分類／標籤」變成「標題／標籤」，檔名與正文都不算。
4. **不做巢狀 workspace**、不做把 vault 換到別的位置、不做在標題下方直接改狀態（不開表單）。

需求文件的改版也不在本切片範圍內——那是寫作者本人的事，時間點不影響本切片。
