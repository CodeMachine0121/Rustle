## 1. Background & Goal

### Problem Statement

寫作區有四件事讓寫作者看不清楚、或改不動：

1. **標題讀起來就是正文。** 標題文字與正文同色，只差一點字重，掃過去分不出哪一行是標題。
2. **在一行裡選幾個字看不出選到哪幾個。** 選取的底色被「游標在這一行」的底色蓋掉了，所以同一行內的選取等於沒有回饋；跨行選反而看得見。
3. **任務項沒有現成的形狀。** 每一個任務項都要自己打短橫、空白、中括號、空白、中括號。（**訂正**：這份文件原本還斷言「按換行鍵時框不會跟著長、只有框沒有字也不會收掉清單」。實作階段實測證明兩句都是錯的——續行由 Markdown 語言支援提供，框會跟上、勾會去掉、空白的那一項會收掉。見 §7 的訂正。）
4. **把一段字變粗體或斜體只能自己打記號**，前後各兩個星號自己數。

### Expected Outcome

- **標題文字與正文不同色**，六級標題共用一色；`#` 本身維持它今天的安靜顏色。
- **在一行裡選幾個字，看得出選到的是哪幾個字。**
- **任務項叫得出來**：片段選單選一下就落下一個任務項。**接得下去這一半已經成立**（上游提供），本切片以測試釘住它而不新增程式碼。
- **選一段字按快速鍵就變粗體或斜體**，同一個鍵按第二次拿掉。
- **既有的每一個按鍵、每一套主題、每一個顏色，除上述之外一個都沒有變。**

### Out of Scope

清單前面短橫的顏色、中括號的顏色、粗體斜體換色、六級標題彼此不同色、正文裡的行內標籤、選取底色本身的顏色調整、任務項的勾能不能用滑鼠點、預覽區的任何顏色、粗體斜體以外的其他快速鍵。理由逐項見 BRIEF。

## 2. User Personas

- **Primary Role:** 寫作者——Rustle 唯一的使用者角色。
- **Secondary Role:** 主題作者（同一個人）——寫一套新主題的時候，他不該為了拿到一個好看的標題色而逐項交代顏色。
- **Usage Context:** 寫作途中，一邊打字一邊掃過已經寫好的部分。**四件事有三件與輸入法搶鍵或搶注意力**：換行鍵是注音的選字鍵、快速鍵在組字中按下去不得動文件、而選取的回饋正是組字時最需要看清楚的東西。

## 3. User Stories & Acceptance Criteria

### US-01 — 標題看得出是標題 [priority: P0]

**As a** 寫作者，**I want** 標題文字與正文不同色，**so that** 我掃過文章時分得出哪一行是標題。

```gherkin
Scenario: 標題文字不是正文的顏色
  Given 一篇文章裡有一行「# 今天」與一行普通正文「最近在選桌面框架」
  When 寫作者看這兩行
  Then 「今天」與「最近在選桌面框架」是兩個不同的顏色

Scenario: 井號本身維持它原本的安靜顏色
  Given 一行「# 今天」
  When 寫作者看這一行
  Then 「#」的顏色與「今天」不同
  And 「#」的顏色與正文也不同
  And 「#」的顏色與粗體記號、引言符號等其他記號相同

Scenario: 六級標題是同一個顏色
  Given 一篇文章從一個井號到六個井號的標題各有一行
  When 寫作者看這六行
  Then 六行的標題文字都是同一個顏色

Scenario: 一套只交代了自己顏色的主題也拿得到標題色
  Given 一套主題沒有逐項指定標題文字的顏色
  When 寫作者選用它並看一行「# 今天」
  Then 「今天」不是正文的顏色
  And 它的顏色與同一個寫作區裡的連結、引言、程式碼、記號四者都不同

Scenario: 粗體只是比較粗，顏色沒有變
  Given 一行正文「這是**重點**的地方」
  When 寫作者看這一行
  Then 「重點」的顏色與「這是」「的地方」相同
  And 「重點」比它們粗

Scenario: 斜體只是斜的，顏色沒有變
  Given 一行正文「這是*重點*的地方」
  When 寫作者看這一行
  Then 「重點」的顏色與「這是」「的地方」相同
  And 「重點」是斜的

Scenario: 沒有記號的正文不受影響
  Given 一段完全沒有記號的正文
  When 寫作者切換到任何一套主題
  Then 那段正文的顏色與這個功能上線前逐字相同
```

### US-02 — 選取範圍一定看得見 [priority: P0]

**As a** 寫作者，**I want** 選到的字有明顯的底色，**so that** 我知道自己選到的是哪幾個字。

```gherkin
Scenario: 同一行裡選幾個字看得見
  Given 一行「這是重點的地方」
  When 寫作者用滑鼠拖曳選取「重點」兩個字
  Then 「重點」底下有底色
  And 那個底色與這一行其他字底下的顏色不同

Scenario: 有選取時「游標在這一行」的底色讓位
  Given 一行「這是重點的地方」，游標落在這一行
  When 寫作者選取「重點」兩個字
  Then 這一行不再整行鋪著「游標在這裡」的底色
  And 只有「重點」兩個字底下有底色

Scenario: 沒有選取時「游標在這一行」的底色照舊
  Given 游標停在一行「這是重點的地方」上，沒有選取任何字
  When 寫作者看這一行
  Then 整行鋪著「游標在這裡」的底色，與這個功能上線前相同

Scenario: 取消選取之後那片底色回來
  Given 寫作者剛選取了「重點」兩個字
  When 寫作者點一下取消選取
  Then 游標所在那一行整行又鋪著「游標在這裡」的底色

Scenario: 跨行的選取每一行都不缺
  Given 一篇文章連續三行都有字
  When 寫作者從第一行拖曳選到第三行
  Then 三行被選到的部分底下都有底色
  And 沒有任何一行缺了那塊底色
```

### US-03 — 任務項叫得出來 [priority: P0]

**As a** 寫作者，**I want** 從片段選單挑一個任務項，**so that** 我不必自己打短橫與中括號。

```gherkin
Scenario: 空行上叫出一個任務項
  Given 游標在一行空的行上
  When 寫作者打半形斜線、選任務項那一列
  Then 那一行變成一個沒有打勾的任務項
  And 游標停在框的右邊，等著填字

Scenario: 打名字的開頭就縮到它
  Given 游標在一行空的行上
  When 寫作者打半形斜線加上任務項名字的頭幾個字母
  Then 片段選單裡只剩任務項那一列

Scenario: 一行已經有字時，任務項另起一行
  Given 游標在「今天要做：」的後面
  When 寫作者打半形斜線、選任務項那一列
  Then 「今天要做：」原封不動留在它那一行
  And 任務項出現在它的下一行
  And 游標停在那個任務項的框右邊

Scenario: 標題片段維持原本的行為
  Given 游標在「今天要做：」的後面
  When 寫作者打半形斜線、選一個標題片段
  Then 標題記號緊接在「今天要做：」後面，沒有另起一行

Scenario: 表格格子裡叫不出來
  Given 游標在一列表格列裡
  When 寫作者打半形斜線
  Then 片段選單沒有出現

Scenario: 程式碼區裡叫不出來
  Given 游標在一段程式碼區裡
  When 寫作者打半形斜線
  Then 片段選單沒有出現
```

### US-04 — 任務清單接得下去，也收得掉 [priority: P0]

**As a** 寫作者，**I want** 任務清單的換行與既有的清單一樣，**so that** 我列一串任務不必每一項重打一次框。

> **已成立，不新增程式碼。** 下列每一條都是 Markdown 語言支援今天就提供的行為，本切片以測試釘住它（依賴而非擁有）。原本以為要自己做，理由已證明錯誤——見 §7 的訂正。兩條情境依實測修正為真實行為。

```gherkin
Scenario: 行尾換行長出下一個任務項
  Given 游標在「- [ ] 買牛奶」這一行的末尾
  When 寫作者按換行鍵
  Then 下一行是一個沒有打勾的任務項
  And 游標停在那個框的右邊

Scenario: 打勾不繼承給下一項
  Given 游標在「- [x] 買牛奶」這一行的末尾
  When 寫作者按換行鍵
  Then 下一行的任務項沒有打勾

Scenario: 只有框沒有字的那一項收掉清單
  Given 一份已有兩項的任務清單，游標在第三項的末尾，而第三項只有框、右邊沒有任何字
  When 寫作者按換行鍵
  Then 那一項整行消失
  And 游標落在一行空行上

Scenario: 清單第二項是空的時候，換行鍵開一個空行而不是離開
  Given 游標在「- [ ] 買牛奶」的末尾
  When 寫作者按換行鍵，接著再按一次換行鍵
  Then 正文是「- [ ] 買牛奶」、一個空行、一個空的任務項
  And 一個普通清單與一個編號清單在同樣的兩次按鍵下得到形狀相同的結果

Scenario: 縮排的任務項，下一項對齊同一層
  Given 游標在一個縮了一層的任務項「  - [ ] 買牛奶」的末尾
  When 寫作者按換行鍵
  Then 下一行的任務項與上一項對齊在同一層

Scenario: 縮排的空任務項退一層，而不是離開清單
  Given 游標在一個縮了一層、只有框沒有字的任務項的末尾
  When 寫作者按換行鍵
  Then 那一項退到外面那一層
  And 一個縮排的普通清單項在同樣的按鍵下得到形狀相同的結果

Scenario: 游標在字中間時不長出新的方框
  Given 游標在「- [ ] 買牛奶」的「買」與「牛」之間
  When 寫作者按換行鍵
  Then 那一行在游標處被切成兩行
  And 記號帶到下一行，但沒有長出任何新的方框
  And 一個普通清單項在同樣的位置得到形狀相同的結果

Scenario: 普通清單與編號清單的行為一個字都沒有變
  Given 游標分別在「- 買牛奶」與「1. 買牛奶」的末尾
  When 寫作者各按一次換行鍵
  Then 兩者各長出下一項，與這個功能上線前逐字相同
```

### US-05 — 粗體與斜體有快速鍵 [priority: P0]

**As a** 寫作者，**I want** 選一段字按快速鍵就變粗體或斜體，**so that** 我不必自己數星號。

```gherkin
Scenario: 選取的字變粗體
  Given 一行「這是重點的地方」，寫作者選取了「重點」
  When 寫作者按粗體的快速鍵
  Then 那一行變成「這是**重點**的地方」

Scenario: 再按一次拿掉粗體
  Given 一行「這是**重點**的地方」，寫作者選取了「重點」
  When 寫作者按粗體的快速鍵
  Then 那一行變成「這是重點的地方」

Scenario: 選取的字變斜體
  Given 一行「這是重點的地方」，寫作者選取了「重點」
  When 寫作者按斜體的快速鍵
  Then 那一行變成「這是*重點*的地方」

Scenario: 再按一次拿掉斜體
  Given 一行「這是*重點*的地方」，寫作者選取了「重點」
  When 寫作者按斜體的快速鍵
  Then 那一行變成「這是重點的地方」

Scenario: 別人用底線寫的粗體也拿得掉
  Given 一行「這是__重點__的地方」，寫作者選取了「重點」
  When 寫作者按粗體的快速鍵
  Then 那一行變成「這是重點的地方」

Scenario: 沒有選取時，加粗游標所在的那個詞
  Given 一行「the important part」，游標停在「important」的中間，沒有選取
  When 寫作者按粗體的快速鍵
  Then 那一行變成「the **important** part」

Scenario: 中文沒有空白分詞，所以加粗的是連點兩下會選到的那一段
  Given 一行「這是重點的地方」，游標停在「重」與「點」之間，沒有選取
  When 寫作者按粗體的快速鍵
  Then 被星號包起來的範圍，與寫作者在同一個位置連點兩下滑鼠會選到的範圍相同

Scenario: 空行上按下去，落下一對空記號
  Given 游標停在一行空的行上，沒有選取
  When 寫作者按粗體的快速鍵
  Then 那一行是四個星號
  And 游標停在第二個與第三個星號之間

Scenario: 空記號落下之後打的字就是粗體
  Given 寫作者剛在空行上按了粗體的快速鍵
  When 寫作者打「重點」
  Then 那一行是「**重點**」
  And 游標停在「點」的後面

Scenario: 跨行的選取什麼都不做
  Given 寫作者選取的範圍從一行的中間延伸到下一行
  When 寫作者按粗體的快速鍵
  Then 兩行都沒有變
  And 選取範圍還在原處

Scenario: 斜體的快速鍵不再把整個結構選起來
  Given 游標停在一行正文裡的一個連結中間
  When 寫作者按斜體的快速鍵
  Then 游標所在的那個詞被星號包起來變成斜體
  And 沒有任何東西被選起來
```

**As a** 寫作者，**I want** 這四件事只做它們自己那一件，**so that** 我原本的每一個按鍵與每一套主題都還在。

Scenario: 組字中按粗體的快速鍵不動文件

  And 候選視窗還開著

Scenario: 組字中在任務項上按換行鍵不動文件
  Given 游標在一個任務項的末尾，而寫作者正在用注音組字、候選視窗開著
  When 寫作者按換行鍵
  Then 沒有長出任何新的任務項
  And 正文一個字元都沒有變

Scenario: 一次加粗算一步 undo
  Given 寫作者剛把選取的「重點」變成粗體

Scenario: 一次長出任務項算一步 undo

  When 寫作者按一次 undo

Scenario: 縮排鍵沒有被搶走
  Given 游標在一行正文上，沒有任何片段的挖空在等著填
  When 寫作者按縮排鍵
  Then 那一行縮進一級，與這個功能上線前相同

Scenario: 片段選單開著時換行鍵仍然屬於選單
  Given 寫作者打了半形斜線與一個片段名字，片段選單開著
  When 寫作者按換行鍵
  Then 選中的那一份片段落進正文
  And 沒有長出任何任務項

Scenario: 表格續列沒有被搶走
  Given 游標在一列表格列的末尾
  When 寫作者按換行鍵
  Then 下一列的直線自動出現，與這個功能上線前相同

Scenario: 每一套主題都還能用
  Given 隨 App 出貨的每一套主題
  When 寫作者逐一選用它們
  Then 每一套都畫得出完整的畫面
  And 每一套的標題文字都與它自己的正文顏色不同

Scenario: 寫作區以外的顏色沒有變
  Given 任何一套主題
  When 寫作者看側邊欄、文章清單與預覽面板
  Then 它們的每一個顏色與這個功能上線前相同

Scenario: 落下的任務項是普通 Markdown
  Given 寫作者用片段與換行鍵列了三個任務項並填完
  When 寫作者看預覽面板
  Then 預覽把它渲染成一份帶勾選框的任務清單

## 4. Business Flow & Logic

### 核心規則

| # | 規則 |
| :--- | :--- |
| R-1 | **標題文字的顏色是「算出來的」，不是「必填的」。** 一套主題不必交代它；沒交代時由這套主題自己的顏色算出一個。四套出貨的主題**都不逐項交代**，全部走這條算法 |
| R-2 | 標題文字的顏色**從紫色算出來**。判準是「與寫作區已經上了色的四件事都分得開」——連結是藍、引言是綠、程式碼是紅、各種記號是次要文字的灰，紫是唯一沒被用掉的色相，而它在三套出貨主題裡都與其他四者分得開 |
| R-3 | **`#` 本身不屬於標題文字。** 它與粗體記號、引言符號、圍籬等一起，維持記號原本的顏色 |
| R-4 | **六級標題共用一個顏色**，字重也不逐級變化 |
| R-5 | **粗體與斜體維持正文色。** 「寫作區的強調靠字重而不靠色相」這條既有規則只在標題上破例 |
| R-6 | **有選取範圍時，不畫「游標在這一行」的那片底色。** 那片底色的職責是回答「游標在哪」，選取範圍已經回答了，所以它讓位。沒有選取時照舊 |
| R-7 | **任務項片段落下一個沒有打勾的任務項**，游標停在框的右邊 |
| R-8 | **任務項片段在一行已經有字時另起一行。** 這是既有規則的改寫：原本是「橫跨好幾行的形狀才另起一行」，現在是「**由片段自己說要不要獨占一行**」——標題與連結片段照舊不獨占，任務項獨占 |
| R-9 | **任務清單的換行行為與既有的清單、編號清單一致**：行尾長出下一項、只有框沒有字的那一項收掉、縮排對齊同一層、游標在字中間就是普通換行。**這一條已成立，由 Markdown 語言支援提供**；本切片只以測試釘住它。「一致」是這條規則的全部內容——包含兩個例外（清單第二項的空白項開一個空行；縮排的空白項退一層），因為那兩個例外普通清單與編號清單一模一樣 |
| R-10 | **長出來的下一項一律沒有打勾。** 勾是那一項自己的事。同 R-9，已成立 |
| R-11 | **粗體與斜體的快速鍵是切換式。** 已經是粗體的再按一次就拿掉 |
| R-12 | 加上時**寫星號**（粗體兩個、斜體一個）；拿掉時**星號與底線兩種寫法都認得** |
| R-13 | 沒有選取時，作用範圍是**游標所在的那個詞**。**游標落在一個詞裡面時，那個範圍與滑鼠連點兩下選到的範圍相同**；游標不在任何詞裡面（空白、標點、空行）時沒有詞可作用，見 R-14。不另訂一套邊界規則——這個 App 對「這裡是哪個詞」已經有一個答案，兩處用同一個。（措辭於 `/contract` 收緊：原本寫成無條件相等，而連點兩下在空白上會選取整串空白，那一格由 R-14 接手） |
| R-14 | 沒有選取、而游標旁邊沒有任何詞時（例如空行），**落下一對空記號**，游標停在中間 |
| R-15 | **跨行的選取什麼都不做**，正文與選取範圍都不變。理由**不是**「Markdown 的記號跨不過換行」——段落內的軟換行其實跨得過（`/contract` 後的 review 實測推翻了原本的說法）——而是拖過行尾之後「要強調哪一段」已經不清楚，一顆靠猜測改寫兩行的鍵比一顆等寫作者講清楚的鍵糟 |
| R-16 | **組字中一律不作用**，三顆鍵（換行、粗體、斜體）都一樣 |
| R-17 | 一次加粗、一次拿掉、一次長出任務項、一次收掉，各算**一步** undo |
| R-18 | 斜體的快速鍵原本會把游標所在的整個結構選起來，**那個行為退場** |
| R-19 | **唯讀時兩顆強調鍵吃掉按鍵、不動文件。** 編輯器拒絕編輯不代表寫作者想離開編輯器——與縮排鍵既有的做法一致。（`/contract` 補記：原本是有實作而無條款的行為） |
| R-20 | 強調快速鍵只作用於**主要**的那個選取範圍，其餘游標不動。與表格續列既有的做法一致。（`/contract` 補記） |
| R-21 | 一份片段把「要不要獨占一行」寫錯型別時**忽略而不下架**——那份片段照樣提供。拒絕它會讓寫作者少一列叫得到的形狀，換來的只是避免一個黏在句子上的形狀。（`/contract` 補記） |
| R-22 | **旁邊那一段的記號不是這一段的記號。** 判斷「這一段已經有強調了嗎」時，左邊那串記號必須真的**開得起來**、右邊那串必須真的**關得起來**（Markdown 自己的 flanking 規則：後面接空白的開不了，前面接空白的關不了）。少了這一條，「兩個粗體之間拖一段再按鍵」會刪掉寫作者四個字元並把粗體挪到錯的字上。（獨立 code review 找出，`/contract` 之後補上） |
| R-23 | **一段只有記號的選取什麼都不做。** 包起來會讓記號變兩倍，當成「已經有強調」會把它們刪掉——而三個連續星號是一條分隔線，變成一個星號就毀了它。**空的**選取不同：那是準備打字，落下一對空記號（R-14）。（同上） |
| R-24 | **程式碼裡兩顆強調鍵都不作用**（圍籬區塊、縮排區塊、行內程式碼），按鍵吃掉、正文不動。程式碼不是散文，`const **a** = 1;` 在任何語言裡都不合法，而那裡的星號也不是強調。與片段選單「程式碼區裡不開」同一個判斷。（同上） |
| R-25 | **只有主要那一個選取範圍會被改寫，其餘游標一律隨改動平移而不是被取代。** 這個編輯器允許多重游標、預設鍵表也給了兩種加游標的方式，所以交回單一範圍不叫「其餘不動」，叫把它們刪掉。（同上；R-20 原本只說「不動」，這一條說清楚怎麼做到） |

### 邊界與例外

| 情況 | 行為 |
| :--- | :--- |
| 選取的範圍首尾帶著空白（例如選到「重點 」） | 星號包在**有字的部分**外面，空白留在星號外——`**重點** ` 而不是 `**重點 **`，因為後者測出來不是粗體 |
| 選取的範圍剛好就是已經包著的星號本身 | **什麼都不做**（見 R-23）。原本裁決為「視為已經是粗體、按下去拿掉」，但那個讀法在「只選到開頭那一對星號」時會讓記號變兩倍；一段只有記號的選取沒有東西可以強調 |
| 選取的範圍一部分是粗體、一部分不是 | 視為「還不是粗體」，整段包起來 |
| 一個任務項只有框、右邊只有空白 | 算「沒有字」，按換行鍵收掉清單 |
| 任務項在文件最後一行 | 照樣長出下一項，正文長出一行 |
| 有選取範圍時按換行鍵 | 不長出任務項，是普通的換行（取代選取內容） |
| 一套主題交代了標題文字的顏色 | 照它交代的畫。算法只在沒交代時作用 |
| 行號那一側 | **沒有標記「游標在這一行」的東西**，所以沒有東西需要一起讓位 |

## 7. Dependencies & Risks

### 外部依賴

無新增。四件事都用寫作區既有的機制：顏色走主題、片段走片段選單、換行走既有的按鍵層、選取的底色走既有的繪製方式。

### 訂正（實作階段）

**US-04 已經成立，本切片不為它新增任何產品程式碼。**

這份文件與它的 BRIEF 原本都斷言兩件事：按換行鍵時方框不會跟著長出來，以及只有框沒有字的那一項不會結束清單。**兩件都是錯的。** 推論是從「這個編輯器跑 CommonMark，語法樹裡沒有任務項節點」出發的——那句話為真，但續行的實作不讀語法樹，它拿清單記號去比對那一行的文字，而那個比對式本身就含著方框，並在複製時把勾清成空白。

實作階段把任務項、普通清單、編號清單擺在一起實測，結果是三者逐項相同：框跟上、勾不繼承、縮排與引言保留、空白的那一項結束清單。連兩個例外也相同——清單**第二項**的空白項會開一個空行而不是結束（語言把緊湊的兩項清單讀成寫作者正在撐開它），**縮排的**空白項是退一層。

所以 US-04 的交付物是**測試**而不是程式碼：釘住上游的承諾，讓下一次升級編輯器必須維持它或明講。這與這個 App 對輸入法的既有態度一致——依賴而非擁有的行為，值得寫下來守著。

> **重寫注意**：上述「上游已經做好」是舊版編輯器元件的實測結果。改用新的編輯器元件後，清單續行（含任務項）若不是元件本身提供，就得自行實作；需求不變，仍以 US-04 的驗收情境為準。

**為什麼表格要自己做而任務項不用**：表格的續行上游真的沒有（那條比對式裡沒有任何一種表格）。任務項在那條比對式裡。這個差別讀語法樹看不出來，因為兩者在樹裡都不存在——這正是當初判斷失準的地方。

### 已知風險

| 風險 | 說明與對策 |
| :--- | :--- |
| **粗體與斜體是這個 App 第四、第五顆被搶的鍵** | 縮排鍵、離開鍵、換行鍵之後是這兩顆。斜體那一顆**今天已經有人在用**（把游標所在的整個結構選起來），要搶它必須排在編輯器預設之上。放錯優先權的症狀是「快速鍵沒反應」而不是錯誤，所以這一項要有測試守著，不能只靠手動試一次 |
| ~~**任務項不被寫作區當成一種結構**~~ | **這條風險是錯的，已由實測推翻。** 原文斷言「R-9 的每一條都得自己做」，理由是 CommonMark 的語法樹裡沒有任務項節點。前提為真而結論不成立：續行不查語法樹，它拿清單記號比對那一行的文字，而那個比對式含著方框並在複製時清掉勾。訂正見下方 |
| **不要重做上游已經做好的事** | 「照清單辦」這句話聽起來像沒事做，而它**真的就是沒事做**。這一項最大的風險不是低估，是高估：自己實作出來的版本會在「清單第二項的空白項」上離開清單，而普通清單與編號清單在那裡是開一個空行——任務項於是成為唯一不一樣的那一種，正好違反這條需求本身 |
| **「片段要不要獨占一行」的規則要改寫** | 今天這件事由「這個形狀有幾行」決定，而任務項只有一行卻要獨占。改寫成「由片段自己說」會動到片段的資料形狀，而片段的說明文件明白寫著「沒有第三個欄位」——同一份文件也明白寫著「若一份新片段逼得某條規則要改，錯在那條規則，改它」。所以這是預期內的改寫，不是破例 |
| **標題色與連結色撞色** | 若標題色改從強調色算出來，三套出貨主題裡有兩套的強調色與它們的連結色都是相近的藍，標題會讀成連結；而第三套的強調色與它的引言色是同一個綠。R-2 選紫色正是為了避開這三次撞色 |
| **選取的可見度不能靠調色解決** | 根因是「游標在這一行」的底色蓋住選取，而不是選取的顏色太淡。把選取調亮會被同一片底色蓋掉——所以 R-6 是讓位而不是換色。這一項若改錯方向，症狀不變而工作白做 |
| **「那個詞」在中文上會比預期寬** | R-13 沿用連點兩下的答案，而中文沒有空白分詞，所以一按可能加粗一整串連續中文。**這是刻意接受的結果**（BRIEF 的例子已經釘住），對策是不另發明一套邊界規則——兩處行為一致，寫作者按一次就學會了 |
