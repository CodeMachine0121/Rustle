# Rustle — Project Map

## Vision

A local, offline Markdown writing app for someone who writes in Chinese every day. Articles are plain `.md` files in a vault folder; typing with an input method must never break.

## Layer map

```
src/ (webview) ──invoke──▶ src-tauri ──▶ rustle-application ──▶ rustle-domain ◀── rustle-infrastructure
```

- The webview has **no** Tauri permissions; it can only call registered channels through `src/ipc/channels.ts`.
- The webview sends **names** (workspace, file name), never paths. Commands parse them into `WorkspaceName` / `ArticleFileName` / `ImageFileName` and get paths only from `ResolvedVaultScope` (lexical check + symlink resolution).
- Default vault: `~/Rustle` (`VaultScope::at_default_location`). Settings: `<vault>/.rustle/settings.json`.

## Shared seams — how a slice plugs in

**Implement an existing channel** (e.g. `readBody`):
1. Replace the body (and signature) of `src-tauri/src/commands/read_body.rs`. Put the use case in `rustle-application`, the I/O in `rustle-infrastructure`.
2. Update the one line for `readBody` in `src/ipc/channels.ts` with the real arguments and payload type.

**Add a new channel**: add one line to the `channels!` table in `src-tauri/src/channel.rs`, one file under `src-tauri/src/commands/`, one `pub mod` line in `src-tauri/src/commands.rs`, one line in `src-tauri/src/channels.rs`, one line in `src/ipc/channels.ts` (and the `COMMAND_NAMES` table in its test). The registry refuses to start if a channel has no handler or two.

**Errors across the boundary**: library crates define `thiserror` enums. Convert them into `CommandError` with a `From` impl (`src-tauri/src/command_error.rs`). The webview always receives `ChannelResult<T>` = `{ ok: true, payload } | { ok: false, reason, message }` with `reason` in `notImplemented | outsideVault | unknownChannel | unexpected`. A new reason = one `FailureReason` variant + the same string in `src/ipc/channelResult.ts`.

**Front matter**: never touch YAML outside `rustle_domain::ArticleDocument`. `ArticleDocument::parse(text)` → `body()`, `status()`, `metadata(&file_name)` (tolerant; `has_incomplete_metadata` when the title fell back to the file name), `with_body(..)`, `with_metadata(&MetadataUpdate::default().updated_at(..))`, `to_text()`. Untouched bytes are written back as they were; a broken block is never rewritten. New file names: `ArticleFileNameSlug::from_title(title).available_file_name(existing)`.

**Article status (categories are retired)**: `rustle_domain::ArticleStatus` (`Active | OnHold | Completed | Dropped`) is the only place that knows the four statuses: `parse` (case and the separator in "on hold" do not matter; anything else is no status) and `as_front_matter_value` (`active`, `on-hold`, `completed`, `dropped`); on the wire it is `"active" | "onHold" | "completed" | "dropped" | null` (`src/ipc/articleStatus.ts`). `ArticleDraft::new(title, status, tags)`; `ArticleDraft::edit` writes a chosen status, removes a recognised one for "no status", and never touches an unrecognised line. `MetadataUpdate::status(..)` / `without_status()` (`FieldValue::Removed`). Categories are not read or written anywhere: their lines stay byte for byte. Labels for the webview (incl. "No Status") live only in `src/features/sidebar/statusChoice.ts` (`STATUS_CHOICES`, `StatusChoice = ArticleStatus | "noStatus"`).

**Articles on disk**: `rustle_domain::ArticleRepository` has `read` and a guarded `write(workspace, article, text, expected_modified_at) -> ArticleWrite::{Written { modified_at }, ModifiedElsewhere}`; there is no unguarded write — read first if you need the current modification time. `FileSystemArticleRepository` is managed Tauri state built in `configure(builder, vault_scope)`; a command takes it as `State<'_, FileSystemArticleRepository>` and hands it to its use case. `readBody(workspace, fileName)` → `ArticleBody { workspace, fileName, body, lastKnownModifiedAt }` (ISO 8601 UTC, `UtcTimestamp`). `saveBody({ workspace, fileName, body, lastKnownModifiedAt, overwrite })` → `SavedBody` (`outcome: "saved" | "modifiedElsewhere"`).

**Time**: take `rustle_domain::Clock` (`SystemClock` in production, `MockClock` in tests); never call `SystemTime::now()` in a use case. Modification times and autosave's `updated_at` are `UtcTimestamp` (`…Z`, compared as strings). Times a person reads in the file (`created_at`/`updated_at` written at creation) are `LocalTimestamp::new(now, clock.local_offset_seconds(now))` → `2026-08-20T00:30:00+08:00`, so the list's leading date is the writer's date.

**Creating an article**: `ArticleRepository::create(workspace, article, text)` opens create-new (never replaces; a taken name is `ArticleRepositoryError::AlreadyExists { article }` naming `workspace/file`, no absolute path) and fsyncs. The rules of a new article live in `rustle_domain::ArticleDraft` (`new` rejects a blank title and cleans categories/tags, `file_name(entries)` counts every name in the folder, `to_text(created_at)`). `createArticle({ workspace, title, status, tags })` → `ArticleSummary` (every `ArticleSummary` carries its `workspace` and `status`; `ArticleLocation = { workspace, fileName }` identifies a row, compare with `isSameArticle` in `src/features/vault/articleLocation.ts`). In the webview, `VaultSession.createArticle(draft)` → `{ outcome: "created" } | { outcome: "failed", message }` refreshes both lists, opens the article and remembers it.

**Another file that does not exist yet**: `ResolvedVaultScope` judges a missing path by its nearest existing ancestor (the workspace folder's links resolved); create it with the crate-private `create_new_durably` (create-new, fsync, folder fsync), as articles and images do.

**Images**: `rustle_domain::ImageAssetRepository` (`create` makes `images/` on demand and never replaces; `read`) is implemented by `FileSystemImageAssetRepository` (managed Tauri state). What a pasted image is decides itself: `PastedImage::recognize(bytes)` (by signature) → `storage()` = `Original { extension }` (PNG, animated GIF/WebP, SVG) or `ConvertToPng`. `ImageFileName::relative_path()` (`images/{name}`, what the body stores) and `media_type()` (also "is this an image name"). `SaveClipboardImages` sequences clipboard → recognise → convert → name → create; `saveClipboardImage(workspace)` → `{ images: [{ relativePath }] }` (empty when the clipboard held no image). Another image source (drag and drop, a file picker) is another use case over the same pieces. In the webview, `ImagePaste` (`src/features/imagePaste/`) owns pasting: hand its `extension()` to an editor through `MarkdownEditor imagePaste`, show its status with `ImagePasteStatusLine`; it inserts one isolated undo step and never while composing.

**Metadata form (webview)**: `src/features/articleMetadata/` has `ChipInput` (Enter/`,` add, Backspace on empty removes, × removes, IME-safe, reports composition), `withChip` / `candidatesFor` and `vocabularyOf(articles)` (the scope's tags from the listed rows). `ArticleMetadataForm` composes these into the one IME-safe title + Status select + tag chips dialog; `CreateArticleDialog` and `EditArticleMetadataDialog` only pass what differs. A dialog is a `div role="dialog"` with no `<form>` (no implicit submit, no focus restore stealing the editor's focus).

**Deleting anything (system trash)**: never delete permanently. `rustle_domain::Trash` is addressed by vault names (`move_article_to_trash`, `move_workspace_to_trash`); `SystemTrash` (managed Tauri state) is its only implementation: it locates the entry through `ResolvedVaultScope::workspace_entry_path` / `article_entry_path` (a link's target confined, but the link itself is what gets trashed or renamed; a missing item refused) and hands the location to the `trash` crate (macOS: `NsFileManager`, no Finder automation prompt). Something new to throw away = one name-addressed method on `Trash`. Tests mock it with `MockTrash`; no automated test moves anything into the real trash (that is the release checklist).

**Editing an article's metadata**: `ArticleDraft` holds the form's rules for creating and editing (`new`, `edit(document, updated_at)`); `ArticleDocument::edit_metadata` is the strict twin of `with_metadata` (refuses a front matter it cannot edit, instead of silently keeping it). `updateMetadata({ workspace, fileName, title, status, tags })` → `{ outcome: "updated", article } | { outcome: "modifiedElsewhere" }` (read, then a guarded write against the time just read).

**Workspace contents and renaming**: `WorkspaceRepository::image_entries` (missing `images/` lists as empty) and `rename` (never onto an existing entry); `VaultEntry::as_image` (a visible file). Channels: `countWorkspaceContents(workspace)` / `deleteWorkspace(workspace)` → `{ articleCount, imageCount }`, `renameWorkspace(workspace, newName)` → `{ outcome: "renamed", workspace } | { outcome: "rejected", reason }`, `deleteArticle(workspace, fileName)`. Rejected-name sentences are `workspaceNameRejections` in the catalog (create and rename share them).

**A failed operation (webview)**: `VaultSession.snapshot.operationFailure = { operation, reason: FailureReason }` is the one exit for non-fatal failures (`reason` says why — `reported` text from the backend, `leavingRefused`, `modifiedElsewhere`, `noWorkspaceSelected` — never a finished sentence); `OperationFailureNotice` words it in the interface language with a dismiss button and the next success clears it. A new operation = one `Operation` value and its sentence in `failedOperations` in both catalogs. Before touching the open article, an operation calls the holder's `closeArticle` and turns a refusal into `{ kind: "leavingRefused", refusal }` (the second try after a failed save lets go). Destructive confirmations use `ConfirmDeletionDialog` (`src/features/deletion/`: focus starts on 取消, Esc cancels, Enter never confirms); `ArticleDeletionDialog` / `WorkspaceDeletionDialog` hold their wording. An operation that does not touch the selection must not start a new selection (`VaultSession.#selectionFor`).

**Handing the keyboard to the editor**: pass `focusEditor: true` to `ArticleHolder.openArticle`; it flows to `EditorDocument.takesFocus` → `MarkdownEditor focusOnShow`, applied only when a new document is shown. Opening from the list never passes it, so the keyboard stays on the list.

**Save status line**: `SaveStatusLine` (under the editor, inside `AutosavedEditor`) shows `workspace ❯ fileName` and the wordless `AutosaveStatus.indicator` (`saving` from the first keystroke, also while an outside change waits; `saved`, a green check that stays; `failed`, a warning mark), with the failure text and the outside-change warning (覆寫 / 重新載入) on the same line. There is no bar above the editor any more.

**Icons and colours**: every icon is a `lucide-react` line icon drawn through `IconButton` (`src/shared/icons/`) or with `className="icon"` (`stroke-width: 1.5`, `currentColor`); never a character or an emoji. Only the save indicator has its own colour (`--color-success`, `--color-warning`). The editor's Xcode look is `xcodeTheme()` (`src/features/editor/xcodeTheme.ts`): a monospaced font and a highlight style whose colours are the theme's `--color-editor-*` tokens, used only under `.markdown-editor`.

**Opening / leaving an article (webview)**: the app owns one `AutosaveSession` (`src/features/autosave/`) and hands it to `VaultSession` as its `ArticleHolder`. Change the open article only through `await session.openArticle({ article: ArticleBody, title })` or `session.closeArticle()`, and act only when the answer is `"switched"` (`blockedByUnansweredWarning` / `blockedByFailedSave` mean the save status line is already explaining why); `VaultSession` already does this for every click and keeps the previous selection when refused. The editor body follows `session.document` (`AutosavedEditor` inside `EditorColumn`); do not remount the editor yourself. Anything that writes the open article from elsewhere: leave through `closeArticle`, write, then `openArticle` with the fresh `ArticleBody`.

**Application menu (macOS)**: `src-tauri/src/application_menu.rs`. `application_menu(app)` is `Menu::default` with both stock Close Window rows (File, Window) swapped in place for a `close-window` item on `Shift+CmdOrCtrl+W`; `application_menu::install(builder)` adds it with its handler, which closes the main window through `Window::close` (so `CloseRequested` and the close guard run as before). Installed in `run` only (native menus need the main thread; `configure` stays mock-buildable); other platforms keep the stock menu. A new row or another rebinding goes there; `tests/application_menu.rs` (no harness) pins every row against `Menu::default`.

**Window close**: the backend holds `CloseRequested` and asks the webview over `watchCloseRequests`; the webview answers with `answerCloseRequest(close)`. Something else that must run before closing belongs in `AutosaveSession.prepareToCloseWindow` (or next to it in `watchWindowCloseRequests`), not in a second listener.

**Settings**: `rustle_domain::Settings` has `indentation`, `previewPanel { isOpen, widthRatio, toggleShortcut? }`, `lastOpened { workspace, article }`, `sidebar { collapsedSections: ("workspaces" | "status" | "tags")[] }` (unknown names dropped), `interfaceLanguage?` (`"zh" | "en"`, absent until chosen; anything else reads as absent), `fontSize? { editor?, preview? }` (pixels as written; a non-number reads as absent, the range is the webview's), `theme?` (a theme id or `followSystem` as written; a non-string reads as absent, the webview judges the name), `vimMode?` (`true` only while on; anything else reads as off, and off is not written) and no vault path. A new field = one field on `Settings` + one on the private tolerant shape in `settings/stored_settings.rs` (a wrong type or out-of-range value falls back to that field's default). `FileSystemSettingsRepository` keeps unknown keys and unusable values (top level and inside each section), writes atomically and checks the location against the vault on every call. `readSettings` (a broken file reads as defaults) and `writeSettings(settings)` are wired; the webview type is `src/ipc/settings.ts`. In the webview, **only `SettingsSession`** (`src/features/settings/`) holds the settings: read them with `useSettings(session)` and change them with `session.change((settings) => ({ ...settings, … }))`, which writes the whole latest settings (only when they were read). The app builds one and hands it to `VaultSession` and the preview; never keep a second copy.

**Vault listing**: `WorkspaceRepository` (`vault_entries`, `workspace_entries`, `create`) answers raw `VaultEntry { name, kind: Folder | File | Unreachable }` lists, links already resolved and confined. What counts is decided only on `VaultEntry` (`as_workspace`, `as_article`, `compare_names`, `clashes_with`) and `WorkspaceNameRequest::judge`. A new listing rule is one method there. Channels: `listWorkspaces()`, `listArticles(workspace)`, `listAllArticles()` (every workspace in name order, an unreadable one skipped), `createWorkspace(name)`, `createArticle(request)` → `{ outcome: "created", workspace } | { outcome: "rejected", reason }` (a rejection is a value, not a failure).

**Selection (webview)**: `src/features/vault/VaultSession.ts` is the single owner of the scope (`selectedWorkspace`, or `showsAllNotes` via `selectAllNotes()`; never both, All Notes is not remembered), the `sidebarFilter` over it (`toggleStatusFilter` / `toggleTagFilter`; cleared on every scope change), the selected article (`ArticleLocation`; operations act on the row's own workspace), the lists, the body and the per-column failure lines; every click goes through `selectWorkspace` / `selectArticle`, a late answer to an older click is dropped, and each selection is written to `lastOpened`. Leaving the open article asks the `ArticleHolder` (autosave) first; clicking the open article again does nothing. Filtering plugs in there. Bind with `useVaultSnapshot(session)`.

**Layout**: `AppLayout({ sidebar, articles, editor, preview, writing, controls, sidebarFooter? })` (the sidebar is a `nav`; `sidebarFooter` holds the settings entry) where `preview = { content, width, onResize, onResizeEnd }`, `writing` is the `WritingLayout` snapshot and `controls = { zenButton, viewModeButtons }`. **`WritingLayout`** (`src/features/writingLayout/`, one per app, bound with `useWritingLayout(layout, settings)`, which also owns the preview shortcut) is the only owner of the arrangement: `viewMode` (`editorOnly | sideBySide | previewOnly`; `previewPanel.isOpen` remembers only "preview on screen", so preview only restarts side by side), `isZen` (never remembered) and `controlsLiveIn` (the header carrying Zen on the left and the three view mode buttons on the right). Never unmount the editor region: preview only and Zen Mode set `hidden` on regions, which keeps the `EditorView` (text, cursor, undo, composition) and the columns' own state. `VaultSession` gets `layout.revealEditorWhenNeeded(autosave)` as its holder, so a refused leave in preview only brings the editor (and its warning) back, as does opening an article with `focusEditor` (a newly created one). Side by side: a `PaneDivider` (`role="separator"`, drag + arrow keys) and the `PREVIEW` region at `flex-basis: width.ratio`. A new arrangement = one `ViewMode` value, its branch in `WritingLayout`, one icon in `ViewModeButtons`. `PreviewWidth` (`src/features/preview/`) owns the 20%–80% clamp, drag arithmetic and keyboard step; `usePreviewPanel(settings)` returns `width`, `resize` (screen only, while dragging) and `commitWidth` (writes `previewPanel.widthRatio`, kept through every view mode).

**Sidebar (column 1)**: `Sidebar` (`src/features/sidebar/`) = All Notes + `CollapsibleSection`s WORKSPACES / STATUS / TAGS (folding is `useCollapsedSections(settings)`, written to `settings.sidebar`; a folded section hides, it never clears). `sidebarCounts(snapshot.articles)` counts the whole scope (five status rows always, tags by count desc then name), never the selection. `SidebarFilter` is the value: at most one `StatusChoice`, any tags, all required. A new section = one `SidebarSection` variant (Rust + `src/ipc/settings.ts`) and one `CollapsibleSection`.

**Article list (column 2)**: what the column draws is `arrangeArticles(snapshot.articles, { filterText, sidebarFilter, openArticle })` (`src/features/vault/articleArrangement.ts`) → `{ article, isOutsideFilter }[]`: the sidebar filter and a case-insensitive substring over title / tags, the open article always kept (flagged `isOutsideFilter`, shown as 開著的), in one fixed order: created newest first (times compared as instants, no time last, ties by title, then workspace, then file name). Sorting was retired; bringing it back is its own slice. `orderArticles(articles)` is every article in that order with no filter (the finders list in it); `firstArticleIn(articles)` is "the newest one" (`goTo`). Above the list, always: the funnel `ArticleFilterField` (composition-aware, shared debouncer, 150 ms; Enter applies, Esc clears) and the new article icon. Each card: title, a left-aligned meta line (status label — "No Status" too — then date, tags, incomplete / open markers), pencil top-right, trash bottom-right (always in the DOM, so the keyboard reaches them). Under All Notes each row names its workspace and 新文章 is refused with 請先選一個 workspace. Filter text is the column's React state — never in the snapshot, never persisted, never a channel call — so anything that needs the whole workspace (the create dialog's vocabulary) keeps reading `snapshot.articles`.

**Scroll sync**: one `ScrollSynchronizer` (built in `App`) keeps the editor and the preview on the same zero-based body line. A side joins with `attach("editor" | "preview", pane)`, which returns its detach (return it from the effect); `MarkdownEditor` and `PreviewPanel` take an optional `scrollSynchronizer` and do this themselves. A `ScrollPane` is `listen / position / maximumPosition / lineAtTop / positionForLine / scrollTo`: `EditorScrollPane` (CodeMirror line blocks) and `PreviewScrollPane` (re-measures a `PreviewLineMap` from `SOURCE_LINE_ATTRIBUTE` blocks each time). Echoes are recognised by position, never by a timer. To scroll the editor or preview to a line from elsewhere (outline, click-to-locate), use the pane's `positionForLine`.

**Preview**: the only way from a body to HTML is `renderPreviewHtml(body)` (`src/features/preview/`): markdown-it → DOMPurify → `recheckPreviewHtml`, all held to `PreviewHtmlPolicy` (allowed tags/attributes; `a[href]` relative/http/https/mailto, `img[src]` relative/`rustle:`). A new allowed tag, attribute or scheme is one line in the policy. Every block element carries its zero-based body line in `SOURCE_LINE_ATTRIBUTE` (`data-source-line`) — scroll sync reads that constant. `renderPreviewHtml(body, workspace)`: a Markdown image at `images/{one segment}` is shown as `rustle://vault/{encoded workspace}/images/{segment}` while rendering only; anything else (and raw `<img>`) is kept as written. `PreviewedBody.workspace` is the shown article's workspace. What the preview shows comes from `PreviewedBody` (over `AutosaveSession.document` / `.body`): immediate on open, 150 ms after typing stops, never while composing. The toggle shortcut (`previewPanel.toggleShortcut`, default `Mod+Shift+P`, `Mod` = Cmd or Ctrl) is parsed by `KeyboardShortcut`.

**No article open**: editor and preview both render `NoArticleState` (`src/features/vault/`); change the wording there only.

**Editor body**: `MarkdownEditor` takes `body` and keeps one `EditorView` for the app's lifetime: a new body replaces the state in place (fresh undo history), waits while composing (latest wins), and the same body again is ignored. Leaving the editor ends a composition whose end event never came.

**Atomic writes**: use `rustle_infrastructure::write_atomically` (temp file `.{name}.{random}.rustle-temporary` in the same folder → fsync → rename). Article files go through `ArticleRepository::write`, which adds the modification-time check before and right before the rename.

**Custom scheme `rustle:`**: `VaultAssetScheme` serves only `rustle://vault/{workspace}/images/{image}` with an image media type (403 for any other shape or a location outside the vault, 404 when missing, bodies never name a path). It is registered in `scheme_handlers(&vault)` and allowed in `img-src`. Another scheme = one `SchemeHandler` + one line in `src-tauri/src/protocols.rs`.

**Composition-aware timing**: get the shared state with `useCompositionState()` and create a `CompositionAwareDebouncer(state, delayMilliseconds)`; call `schedule`, `cancel`, `dispose`. Do not read composition from props or a second source. A text field reports its own composition to the shared state (`start` / `end`, and `end` on blur) and asks `state.ownsKey(event)` before acting on Enter or Tab — see `NewWorkspaceDialog`.

**Editor indentation**: `MarkdownEditor` takes `indentation?: { style: "spaces" | "tab"; width }` (`src/features/editor/IndentUnit.ts`); missing or unreasonable values fall back to 2 spaces. The settings slice passes the stored value straight through. Tab / Shift+Tab are owned by `TabIndentation` (capture-phase listener on the editor root): do not bind Tab in another extension; the instance is private to `MarkdownEditor` today, so a future toolbar must first expose `indent()` / `outdent()` through a `MarkdownEditor` handle (React `ref`) rather than build its own.

**Enter in the editor**: three owners, by precedence. `Prec.highest` is reserved for a popup that owns Enter while open (the snippet menu). `TableRowContinuation` (`src/features/editor/`, `Prec.high`, listed before `markdown()` so it also beats Markdown's own list/quote continuation) owns a plain Enter at the end of a table row (next empty row, cursor in its first cell) and on the table's last row when its cells are all empty (clears it to leave the table); it never acts while composing (`CompositionState.ownsKey`). Everything else falls through to Markdown's continuation and the default Enter. "Is this line a table row?" is `TableRow.parse(line.text) !== null` — reuse it (e.g. "no snippet menu inside a table"), never a second regex.

**Snippets and the slash menu**: `src/features/snippets/`. A snippet is one JSON file in `snippets/` (copy `snippetTemplate.json`: `name`, `template`; `{{name}}` marks an empty field, the name never reaches the body); menu order is file-name order, an unreadable file is left out. `Snippet.parse` is the only place that knows the field syntax; `SnippetCatalog.shipped()` globs the files. The editor installs one `SnippetExpansion(composition, catalog, menuLabel)`: `slashOpeningSnippetMenu(transaction)` is the whole rule for when a typed `/` opens the menu (line start or after a blank, not in code or a table row, never a composition input); `SnippetMenu` (state field + tooltip, ↑/↓/Enter at `Prec.highest`, one isolated undo step per expansion) and `SnippetFields` (one waiting group, mapped through edits, ended by leaving the snippet, undo, another snippet or Esc). A tenth snippet = one more file. Loosening "not in tables" = one condition in `slashTrigger.ts`.

**Tab and Esc before indentation**: `TabIndentation` stays the only Tab listener. Something that must take Tab or Esc first while it has work in progress registers an `indentationKeyClaims` entry (`claimTab(view, backward)`, `claimEscape(view)`); a claim that takes Esc `preventDefault`s it. Tab is always indentation: there is no Esc-then-Tab way out of the editor any more (the keyboard reaches the article list only by mouse). Esc is one ladder, one rung per press: snippet menu → waiting fields → Vim back to Normal (Vim on, Insert/Visual) → leave Zen Mode (`useWritingLayout`'s window bubble listener: only an Esc nobody `preventDefault`ed and no input method owns) → nothing. Read `SnippetExpansion` and `VimEditing` before giving Esc another job.

**Keys in the editor beyond Enter and Tab**: `EmphasisShortcuts` (`Prec.high`) owns `Mod-b` / `Mod-i`; `Mod-i` (`selectParentSyntax`) is removed from the default keymap `MarkdownEditor` installs. What a toggle does lives in `InlineEmphasis` (`bold` / `italic`, `toggle(state)` → a transaction spec or `null`): it reads the Markdown syntax tree, so "is this already bold" and "is this code" are the parser's answer, never a regex. Another inline shortcut (inline code, strikethrough) = another `InlineEmphasis` instance and one binding. Task lists, plain and ordered lists are continued by `markdown()`'s own Enter (pinned by `TaskListContinuation.test.tsx`); do not add a second list continuation.

**Writing-surface colours and keys**: the Markdown colours are `xcodeTheme()`'s (one heading token for all six levels, marks including `#` in `--color-editor-mark`, bold and italic uncoloured); do not stack another highlight style on it. The cursor-line background is `cursorLineHighlight()` (`.cm-cursorLine`, `--color-cursor-line`) and is not drawn while any selection range is non-empty; do not add CodeMirror's `highlightActiveLine` beside it. `Mod-b` / `Mod-i` are `EmphasisShortcuts` over `InlineEmphasis` (toggle on the main selection, unwrapping what the Markdown tree sees as emphasis; underscore runs between letters are re-read as asterisks); `defaultKeymap` is installed without its `Mod-i`. `Mod-w` is `ExtendSelection` (`Prec.high`): the word under the main cursor (`state.wordAt`, the same call `InlineEmphasis` makes) when it is empty and next to one, otherwise `selectParentSyntax`, and past the outermost block the whole body; selection only (works read-only, no undo step), never while composing.

**Vim mode**: `src/features/vim/`. `VimModeSession` (one per app, over `SettingsSession`) owns "is Vim on" (`isEnabled`, `setEnabled`) and the mode the editor reports (`report`, `mode`: `normal | insert | visual`, `null` while off); `useVimEnabled` re-renders only on on/off, `useVimMode` on every mode (the status line's `VimModeLabel`, `NORMAL`/`INSERT`/`VISUAL`, never translated). `MarkdownEditor vimEnabled onVimModeChange` builds one `VimEditing` (`@replit/codemirror-vim`) that orders every key in three bands: the app's own keys (any `keymap.of` at default or higher precedence, `TabIndentation`, window listeners) → Vim (`Prec.low`) → the editor's typing keys (`vimEditing.typingKeys(bindings)`: `defaultKeymap`, `markdownKeymap`), which with Vim on run after Vim and only in Insert mode, and swallow the key in Normal/Visual so nothing falls through to an edit (so Cmd+A does nothing there). A new app key beats Vim with no Vim code; a new stock typing keymap goes through `typingKeys`. Any user selection means Visual, even from Insert; keys an input method owns in Insert mode never reach Vim. Turning Vim on or off is `switchTo` (text, cursor and undo kept); a new document starts in Normal.

**Interface language (webview copy)**: every sentence Rustle itself shows lives in `src/features/interfaceLanguage/messages.ts`: `CHINESE_MESSAGES` (complete; its shape is the `Messages` type) and `ENGLISH_MESSAGES` (`Partial<Messages>`, completed with Chinese by `withFallback`, so a missing English sentence shows Chinese, never a blank or a key; a test fails while English misses a key). A component reads `const messages = useMessages()`; a sentence with a value in it is a function (`messages.deleteArticle(title)`), and the value (the writer's own words, a time, a backend reason) is inserted untouched. Never store a finished sentence in session state — store why and word it when rendering. New copy = one key in both catalogs. The language in use is `useInterfaceLanguage(settings, channels)`: `settings.interfaceLanguage ?? system` (system = the first of `readPreferredLocales()` → `{ locales }`, Chinese when its primary subtag is `zh`, else English; `navigator.languages` only for the first frame). `InterfaceLanguageProvider language` wraps the app and keeps `<html lang>` (`zh-Hant` / `en`). The settings dialog (`SettingsEntry` = gear + `SettingsDialog`, in `AppLayout`'s `sidebarFooter`) holds one `<section className="settings-item">` per setting — a new setting is one more section. vault / workspace / metadata stay untranslated inside Chinese sentences; the WORKSPACES title is the same in both.

**Finding (webview)**: `src/features/finding/`. `Finders` (rendered once in `App`) owns which finder is open; `useFindingKeys` is the only listener for `Cmd+T` / `Shift+Cmd+F` / `Cmd+P` (window capture phase, `preventDefault` + `stopPropagation`, so the editor never sees them; Ctrl never counts — `finderForKey`). `FINDING_SHORTCUTS` names the keys for a keymap list. Every finder is a `FinderPalette` (IME-aware field, ↑/↓ clamped, Enter, Esc, outside click) fed rows and a status sentence; a new finder = one `FinderKind`, one shortcut, one component. The match rule is `FindingText` (webview: titles, workspace names) and `rustle_domain::SearchText` (body lines), both "one contiguous piece, any case, blanks mean nothing typed". `searchBodies({ text, articles })` → `{ matches: [{ workspace, fileName, lineNumber, lineText }], isTruncated }` reads the *saved* bodies of the given articles in the given order (unreadable ones skipped, at most `BODY_MATCH_LIMIT` = 200); `BodySearch` debounces it and drops stale answers.

**Going somewhere vs looking**: `VaultSession.goTo(scope)` (`Scope` = `{ kind: "workspace", workspace } | { kind: "allNotes" }`) switches the scope and opens `firstArticleIn` without the keyboard (empty or unreadable → editor empty); `selectWorkspace` / `selectAllNotes` stay "look only". `openFoundArticle(article, cursorLine?)` opens with the keyboard and the cursor on a body line (from 1), or only moves the cursor when it is already open (`ArticleHolder.placeCursor`; `WritingLayout.revealEditorWhenNeeded` brings the editor back from preview only for it). Under it, `AutosaveSession` publishes `EditorDocument.cursorPlacement = { line, sequence }` and `MarkdownEditor cursorPlacement` puts the cursor at that line's start (clamped to the last line), scrolls it into view and focuses.

**Font sizes of the editor and the preview**: `FontSize` (`src/features/fontSize/`) is the only rule (default 15, 10–28 px, never rounded while shown, a tenth of a pixel in the settings); Rust stores the numbers and never clamps or rounds them. `EditingSurfaceFontSizes` (one per app, `useEditingSurfaceFontSizes`) owns both live sizes: a Cmd/Ctrl wheel or a WebKit pinch (`ZoomGesture` turns both into one ratio) scales the region marked `FONT_SIZE_SURFACE_ATTRIBUTE` under the pointer, is `preventDefault`ed everywhere (no page zoom) and is written 300 ms after the gesture; Cmd/Ctrl+0 resets the hovered surface (not while composing). `MarkdownEditor fontSizePixels` resizes the existing view and re-measures it; `PreviewPanel fontSizePixels` sizes the article, and everything inside `.preview-content` is sized in `em`. A third surface = one `FontSizeSurface` value, one settings field, one marked region.

**Colours and themes**: `app.css` and `xcodeTheme.ts` write no colour of their own (`appStyles.test.ts` pins it): every colour is `var(--color-<token>)`, and the tokens are set on `<html>` by the theme. A theme is one JSON file in `src/features/theme/themes/` (copy `themeTemplate.json`: `id`, `name { zh, en }`, fourteen `base` entries — `appearance` + 13 hex colours — and optional `overrides` per token); menu order is file-name order, and a file missing a base colour is left out. `Theme` (`parse`, `tokens`, `applyTo`) owns the token list and the one derivation table (`color-mix(in oklab, …)` over base colours); a new token = one derivation entry, then use it in CSS. Light and Dark override every token with the pre-theme colours. `ThemeSession` (one per app, `useTheme`) owns the choice (`followSystem` resolves to the `light` / `dark` files and follows `prefers-color-scheme`); it starts from a `localStorage` cache that `main.tsx` paints before the first render (`paintCachedTheme`), follows `settings.theme`, and `menu.choose(id)` writes through `SettingsSession.change` (screen first). The settings dialog shows it with `ThemeSetting` (a native `<select>`). Shadow and backdrop strengths stay in CSS over `--color-shade`.

**Frontend features**: put them in `src/features/<feature>/`; call the backend only through `channels`.

**Security**: change the CSP only in `src-tauri/src/content_security_policy.rs` *and* `tauri.conf.json` (a test keeps them identical). The navigation guard (`NavigationPolicy`) keeps the window on its own page; http(s) links open in the system browser.
