## 1. 這個切片要解決的問題

到目前為止 Rustle 打得開一個編輯區，但**它從來沒有讓使用者看見自己的 vault**。地基切片給了一個載入記憶體示範正文的編輯區；front matter 切片給了「打開某一個檔案、只交出正文」的能力，可是「某一個檔案」是測試裡寫死的名字——沒有任何畫面列得出使用者的 workspace，也沒有任何畫面列得出一個 workspace 裡有哪些文章。

本切片要做的，就是把磁碟上的那棵樹變成畫面上的兩份清單，並把 §4.1 的版面骨架立起來：

```
~/Rustle/                      ┌───────────┬────────────────┬──────────────┬─────────┐
├── .rustle/settings.json      │ WORKSPACES│ ARTICLES       │ EDITOR       │ PREVIEW │
├── Blog/                     │           │                │              │（他人）  │
│   ├── images/               │ ▸ Blog    │  Tauri 與 Ele… │ ## Tauri 與  │         │
│   ├── zen-of-writing.md     │ ▸ Work    │  08-20 · 技術  │              │         │
│   └── tauri-vs-electron.md  │           │  ───────────── │ 最近在選桌面 │         │
└── Work/                     │ ───────── │  Zen of Writing│ 框架，把…    │         │
    └── 2026-q3-review.md     │ ＋ 新增   │  08-18 · 隨筆  │              │         │
                              └───────────┴────────────────┴──────────────┴─────────┘
```

真正困難的地方不是「把資料夾列出來」，而是**哪些東西根本不算 workspace、不算文章**。使用者的 vault 裡會有 `.git`、`.rustle`、`images/`、`README.txt`、甚至 `Blog/2026/` 這種子資料夾。需求文件 R-1~R-5 把這五條規則寫得很硬，而它們一旦寫錯，使用者會看到自己的 `.git` 變成一個 workspace，或看不到自己明明存在的文章。

第二個困難的地方是**「新增 workspace」的擋下條件必須在負責檔案存取的那一層**。使用者輸入的名字會變成一個真實的資料夾名稱；如果只有畫面層在檢查，那條防線就等於不存在。

## 2. 對誰有價值

| 角色 | 拿到什麼 |
| :--- | :--- |
| 使用者（James） | 打開 App 就看到自己的 workspace 與文章，點一下就讀進編輯區；關掉再打開，回到上次那一篇 |
| 使用者（vault 裡有 `.git` / `images/` / 非 `.md` 檔的人） | 那些東西不會冒充成 workspace 或文章，也不會被動到 |
| 使用者（第一次打開 App 的人） | 空的 vault 不是一片空白，而是一句「建立你的第一個 workspace」 |
| Wave 3 建立文章對話框 | 一個「當前 workspace 是誰」的單一真實來源，與一份可以插入新文章的清單 |
| Wave 3 預覽面板 | 一個已經留好第四欄位置的版面，接上去不必重排 |
| Wave 4 篩選與排序 | 一份已經整理好、每列都帶 metadata 的文章清單，排序與篩選只需要換順序與過濾 |
| 只用鍵盤的使用者 | FR-7.7 的逃脫路徑第一次有真實的去處——在此之前畫面上只有編輯區一個可聚焦元素 |

## 3. 成功的樣子（可觀察的行為）

1. 欄 1 列出 vault 底下所有 workspace，依名稱排序，每一列帶著該 workspace 的文章數。
2. `.rustle`、`.git` 這種以 `.` 開頭的資料夾**不在**清單上；vault 底下叫 `images` 的資料夾也不在；vault 底下的**檔案**也不在。
3. 點一個 workspace，欄 2 換成它的文章清單，欄 3 清空；同一時間只有一個 workspace 被選取。
4. 欄 2 每一列顯示標題、建立日期、分類、標籤；沒有 `title` 的檔案以檔名代替並被標成「metadata 不完整」。
5. 欄 2 只列 workspace **第一層**的 `.md` 檔：`Blog/2026/` 底下的東西不出現，`images/` 不出現，`README.txt` 不出現且不會被動到。
6. 點一篇文章，欄 3 載入它的正文（沒有 front matter）。
7. 新增 workspace：輸入名字建立同名資料夾；名字重複、含 `/` 或 `\`、叫 `images`、或空白時**擋下並說出原因**，而且**沒有任何資料夾被建立**。
8. 空的 vault 顯示「建立你的第一個 workspace」；沒有文章的 workspace 顯示「建立第一篇文章」；沒有選文章時欄 3 顯示空狀態，而且**沒有任何可以打字的空白區**。
9. 關掉 App 再打開，上次選的 workspace 與文章都還在選取狀態。
10. 在「新 workspace 名稱」欄位用注音打字，按 Enter 選字**不會**送出表單。
11. 淺色／深色跟隨系統。

## 4. 邊界：本切片明確不做

| 不做 | 為什麼 / 誰做 |
| :--- | :--- |
| 重新命名／刪除 workspace（FR-1.5） | Wave 4 `metadata-editing-and-destructive-operations`。破壞性操作要垃圾桶與二次確認，是另一組行為 |
| 刪除文章、事後編輯 metadata（FR-2.6、FR-2.7） | 同上 |
| 篩選框與排序切換（FR-2.2、FR-2.4） | Wave 4 `article-filter-and-sorting`。本切片只保證清單順序**穩定**（依檔名），預設的「依建立時間新到舊」屬於那個切片 |
| 建立文章對話框（FR-2.5、FR-3.x） | Wave 3 `create-article-dialog`。本切片的欄 2 空狀態只放一句引導文字，不放對話框 |
| 預覽面板（欄 4、FR-5.x） | Wave 3 `preview-panel`。本切片只把第四欄的**位置**留出來（版面接受一個預覽區塊，今天沒有人給它） |
| 自動儲存、切換文章前先存檔（R-10、FR-2.3 的儲存半段） | Wave 2 `autosave-and-atomic-write`。本切片切換文章時直接載入新的，因為現在還沒有任何路徑會改動正文 |
| 可拖曳分隔線與寬度持久化（FR-5.6） | Wave 4。本切片的欄寬是固定的 |
| 變更 vault 位置 | 沒有任何 FR 要求它。設定檔照 §7.3 記下 vault 路徑，但那是**記錄**，不是可改的設定（見假設 A-9） |
| 標題列的儲存狀態（FR-4.6） | 自動儲存切片 |

## 5. 具體例子（釘住邊界與例外）

### 5.1 哪些東西算 workspace

vault 底下有這些東西：

```
~/Rustle/
├── .rustle/          （資料夾）
├── .git/            （資料夾）
├── images/          （資料夾）
├── Blog/            （資料夾）
├── work/            （資料夾）
├── Reading-Notes/   （資料夾）
├── README.txt       （檔案）
└── Blog.md          （檔案）
```

清單上應該是：`Blog`、`Reading-Notes`、`work`——三個，依名稱排序。其餘六個都不是 workspace（兩個以 `.` 開頭、一個叫 `images`、兩個是檔案；`Blog.md` 是檔案不是資料夾）。

### 5.2 哪些東西算文章

`Blog/` 底下有這些東西：

```
Blog/
├── images/                  （資料夾，保留名稱）
├── 2026/                    （資料夾）
│   └── nested.md            （第二層，不算）
├── notes.md/                （資料夾，名字剛好長得像檔案）
├── zen-of-writing.md        （檔案）
├── TAURI-VS-ELECTRON.MD     （檔案，副檔名大寫）
├── README.txt               （檔案）
└── .DS_Store                （檔案）
```

清單上應該是：`TAURI-VS-ELECTRON.MD`、`zen-of-writing.md`——兩篇。`2026/nested.md` 不算（R-3 只掃第一層）、`notes.md/` 是資料夾不算、`images/` 不算（R-4）、`README.txt` 與 `.DS_Store` 不算（R-5）而且**不會被刪除或搬動**。

### 5.3 一列文章長什麼樣

檔案 `Blog/tauri-vs-electron.md`：

```markdown
---
title: Tauri 與 Electron 的取捨
created_at: 2026-08-20T14:32:05+08:00
category: 技術筆記
tags:
  - tauri
  - electron
---
```

那一列要顯示：標題「Tauri 與 Electron 的取捨」、建立日期 2026-08-20、分類「技術筆記」（單一字串寬容讀成一個元素的清單）、標籤 tauri 與 electron。**不標記** metadata 不完整。

檔案 `Blog/no-title.md` 內容只有 `# 隨手寫的東西`（沒有 front matter）：那一列顯示標題「no-title」（檔名去掉 `.md`），沒有日期、沒有分類標籤，並且**被標成 metadata 不完整**。

### 5.4 新增 workspace 被擋下的四種情況

vault 已經有 `Blog/`、`README.txt`：

| 輸入 | 結果 | 原因 |
| :--- | :--- | :--- |
| `Notes` | 建立 `~/Rustle/Notes/`，清單多一列（0 篇文章） | — |
| `Blog` | 擋下 | 名稱已經被用了 |
| `blog` | 擋下 | 同上——檔案系統會當成同一個名字（macOS 不分大小寫） |
| `README.txt` | 擋下 | 同上——vault 底下已經有這個名字（即使它是檔案） |
| `Blog/2026` | 擋下 | 含路徑分隔字元 |
| `..` | 擋下 | 保留名稱（而且它不是一個單層名稱） |
| `images` / `Images` | 擋下 | 保留名稱 |
| `.hidden` | 擋下 | 保留名稱——以 `.` 開頭的資料夾永遠不會出現在清單上，建立它等於建立一個看不見的東西 |
| 空字串 / 只有空白 | 擋下 | 名稱不可為空 |

四種擋下都必須**在負責檔案存取的那一層判定**，並且**沒有任何資料夾被建立**。

### 5.5 重啟還原

`.rustle/settings.json` 記著上次開的是 `Blog` 的 `zen-of-writing.md`：

| 情況 | 重啟後 |
| :--- | :--- |
| 兩者都還在 | `Blog` 被選取、`zen-of-writing.md` 被選取、欄 3 是它的正文 |
| `Blog` 還在，那篇被刪了 | `Blog` 被選取、沒有文章被選取、欄 3 是空狀態 |
| `Blog` 不在了 | 什麼都沒被選取，欄 1 照樣列出現有的 workspace |
| 沒有設定檔（第一次打開） | 什麼都沒被選取 |
| 設定檔壞了（不是合法 JSON） | 當成沒有設定檔，不要讓 App 打不開 |

### 5.6 組字中的 Enter

在「新 workspace 名稱」欄位打「筆記」：按 `ㄅ` `ㄧ` `ˇ` 之後輸入法彈出候選視窗，按 Enter 確定選字——**那一次 Enter 屬於輸入法，不可以送出表單**。選完字之後再按一次 Enter，才是「建立」。

## 7. 假設（需求文件沒寫，本切片一次裁決）

| # | 假設 | 為什麼這樣選 |
| :--- | :--- | :--- |
| A-1 | **新增 workspace 需要一個新的檔案操作 `createWorkspace`。** 地基切片既有的檔案操作裡沒有任何一個做得到這件事 | FR-1.4 是本切片覆蓋的需求，而既有操作清單裡沒有它。硬塞進別的操作會是「為了不改既有介面而扭曲設計」，那比誠實新增一個操作糟。新增的操作必須先進通用語言地圖——本切片照辦，並在 PR 說明點名所有被動到的既有介面 |
| A-2 | ~~只有真正的資料夾算 workspace，只有真正的檔案算文章~~ → **符號連結照它指向的東西算；指向 vault 外或指向不存在位置的，整筆不出現在清單上** | **code review 後由使用者裁決改寫。** 原本的保守解讀只在 workspace 那一側被實作，文章那一側接受連結，於是指向 vault 外的 `.md` 變成一列點不開的文章，而畫面給的解釋是「front matter 不完整」。改寫的三個理由：範圍檢查會解析連結之後，**vault 內的連結是可證明安全的**；把連結整批排除會讓使用者磁碟上真的存在的資料夾**無聲消失**，那正是本切片自己在別處說「更糟」的事；成本是每個連結一次解析，相對於每篇文章一次讀檔是雜訊。**一個順帶的結果，寫下來因為總有人會碰到**：連結叫什麼，workspace 就叫什麼——所以一個名為 `Photos`、指向某個 `images` 資料夾的連結**會**成為一個叫 `Photos` 的 workspace，裡面的 `.md` 也會被列成文章。這符合 R-4（保留的是**名稱** `images`，不是「任何圖片資料夾」），但它確實讓使用者有辦法把圖片資料夾攤在畫面上 |
| A-3 | **`images` 這個保留名稱的比對不分大小寫** | macOS 的檔案系統不分大小寫，`Images/` 與 `images/` 是同一個資料夾。檔名 slug 的撞名比對已經採同一立場（「counts a clash the file system would count」） |
| A-4 | **副檔名 `.md` 的比對不分大小寫**（`.MD` 也算文章） | 同上。使用者從別的工具帶進來的檔案大寫副檔名很常見，不列出來等於檔案不見了 |
| A-5 | **vault 資料夾不存在時當成「一個空的 vault」**，不是錯誤 | 第一次打開 App 時 `~/Rustle` 還不存在。FR-1.6 要顯示引導，而不是顯示讀取失敗。同理，選取的 workspace 資料夾在 App 開著的時候被外部刪掉，當成「沒有文章」 |
| A-6 | **讀不到內容的 `.md` 檔照樣列出來**，標題用檔名、並標成 metadata 不完整 | 兩個理由：欄 1 的文章數是數檔名（不讀內容）數出來的，若清單默默跳過讀不到的檔案，數字與列數會不一致；而且磁碟上存在的東西不該從畫面上無聲消失。「不知道這個檔案怎麼描述自己」正好就是「metadata 不完整」的意思 |
| A-7 | **文章清單依檔名排序** | FR-2.2 的「預設依 `created_at` 新到舊」屬於篩選與排序切片。在它到達之前，順序必須是**穩定**的，否則每次重讀清單都在跳動；檔名是唯一不需要讀檔就有的鍵 |
| A-8 | **切換 workspace 時欄 3 清空**（不還原「該 workspace 上次開啟的文章」） | FR-1.2 原文是「清空**或**載入該 workspace 上次開啟的文章」，兩者都符合。設定檔的形狀（`LastOpenedSettings`）只記一組 workspace＋文章，記不下「每個 workspace 各自上次開哪篇」；為了走另一條分支去改共用型別不值得 |
| A-9 | ~~設定檔裡的 vault 路徑是記錄，不是可改的設定~~ → **設定檔完全不記錄 vault 路徑** | **code review 後由使用者裁決改寫。** 一個每次讀寫都被執行中的 vault 覆寫的欄位，等於檔案對外宣告了一個 App 不會遵守的設定——那是會變成 bug report 的形狀。「可更換 vault」（需求文件 §2）目前**沒有主人**；哪個切片真的要做，就由它把欄位加回來 |
| A-10 | **設定檔保留它不認識的頂層欄位** | 與 front matter 的 R-8 同一條倫理：使用者手改過的檔案，不該因為 App 存了一次而掉東西。成本是幾行程式碼 |
| A-11 | **設定檔用一般寫入，不做原子寫檔** | R-11 的原子寫入是針對文章（使用者的內容）。設定檔壞掉的代價已經被「壞掉就用預設值」吸收掉了；原子寫檔是自動儲存切片的交付物，提前做一份等於兩份實作 |
| A-12 | **新增成功之後選取那個新的 workspace** | 使用者剛剛才輸入它的名字，接下來想做的事一定發生在它裡面。留在原地會多一次點擊 |
| A-13 | **失敗的讀寫在對應欄位顯示一行訊息**，不是彈窗、不是崩潰 | 需求文件沒寫讀取失敗的畫面。一行訊息是資訊量與干擾的最低組合；彈窗會擋住使用者做別的事 |
| A-14 | **「新 workspace 名稱」欄位把自己的組字狀態報告給共用的 `CompositionState`** | 那是畫面層組字狀態的唯一真實來源，且「所有需要感知組字的功能」都從它讀。順帶讓自動儲存與預覽的去抖動在使用者於這個欄位打中文時也一起暫停——那正是 FR-8.4／FR-8.5 想要的 |

## 8. 不做的技術決定（留給實作階段）

本檔不談分層、類別與檔案位置——那是 `/architecture` 的事。這裡只確認一件事：**檔案系統、front matter 解析、路徑組裝全部在負責檔案存取的那一層**（§7.3 分層原則），畫面層只透過具名的操作拿整理好的資料。
