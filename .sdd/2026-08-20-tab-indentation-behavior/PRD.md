## 1. 目標

讓「按 Tab 只做縮排」從一句話變成一個逐格對得上需求文件 §5.1 的行為，並且在吃掉 Tab 的同時把鍵盤使用者的逃脫路徑與輸入法的優先權一起顧好。

## 2. User Stories

| ID | 故事 |
| :--- | :--- |
| **US-1** | 作為寫巢狀清單的使用者，我要按 Tab 就把當前那一行縮一級、按 Shift+Tab 就退一級，這樣我不用手動數空白 |
| **US-2** | 作為整理段落的使用者，我要選取好幾行後按一次 Tab 就整批縮排，而且選取範圍還在原來那段文字上，這樣我可以連按幾次調整層級 |
| **US-3** | 作為會按錯的使用者，我要一次 Tab 在 undo 裡只算一步，這樣按一次 Cmd+Z 就完全回到按錯之前 |
| **US-4** | 作為習慣別的編輯器的使用者，我要行首空白不是整數倍時退縮會對齊到層級上，這樣縮排不會愈用愈亂 |
| **US-5** | 作為只用鍵盤的使用者，我要在 Tab 被編輯區吃掉的情況下仍然有辦法離開編輯區 |
| **US-6** | 作為用注音打字的使用者，我要在選字的時候按 Tab 不會把整行推走，因為那時候 Tab 是輸入法在翻候選頁 |
| **US-7** | 作為對縮排風格有偏好的使用者，我要能把縮排單位改成 4 個空白或真實 tab 字元，而且同一份文件只用一種 |

## 3. 業務流程

### 3.1 一次 Tab

```
使用者按下 Tab
   → 正在組字？
        └─ 是 → 什麼都不做，這一次按鍵不屬於 App（留給輸入法）
   → 剛剛按過 Esc（逃脫路徑生效中）？
        └─ 是 → 什麼都不做，這一次按鍵交給預設的焦點移動
   → 找出選取範圍涵蓋的每一行（沒有選取時就是游標所在那一行；同一行只算一次）
   → 每一行的行首各插入一個縮排單位
   → 一次寫入：多行也只產生一步 undo
   → 吃掉這次按鍵：焦點不移動
```

### 3.2 一次 Shift+Tab

```
使用者按下 Shift+Tab
   → 正在組字 / 逃脫路徑生效中 → 同 3.1
   → 找出選取範圍涵蓋的每一行
   → 每一行：量行首空白的欄數
        ├─ 0 欄 → 這一行不動
        └─ n 欄 → 退到「小於 n 的最大縮排層級」，以設定的樣式重寫這一行的行首空白
   → 所有行都沒得退 → 完全不寫入：文件不變、游標不變、undo 歷史不多一步
   → 有行可退 → 一次寫入，一步 undo
   → 不論有沒有寫入，都吃掉這次按鍵：焦點不移動
```

### 3.3 縮排單位怎麼決定

```
編輯區被建立時拿到一組縮排設定（樣式 + 寬度）
   → 沒拿到 → 用預設：2 個空白
   → 寬度不是 1~8 的整數 → 正規化回預設寬度
   → 整個編輯器只認這一組：插入用它、量欄數用它、退縮後重寫也用它
```

## 4. 驗收標準（Gherkin）

以下情境的縮排單位一律是**預設的 2 個空白**，除非情境自己註明。`|` 代表游標位置，`[` `]` 代表選取範圍的兩端，`·` 代表一個空白字元（只為了看得見，實際是空白）。

### Feature：Tab 縮排當前行

```gherkin
# TC-01
場景: 游標在行首時整行縮排，游標跟著文字走
  假設 編輯區的內容是 "寫文章"，游標在行首
  當 使用者按下 Tab
  那麼 內容是 "··寫文章"
  並且 游標仍然緊貼在 "寫" 的前面

# TC-02
場景: 游標在文字之間時仍然縮排整行，游標與文字的相對位置不變
  假設 編輯區的內容是 "寫文章"，游標在 "文" 與 "章" 之間
  當 使用者按下 Tab
  那麼 內容是 "··寫文章"
  並且 游標仍然在 "文" 與 "章" 之間

# TC-03
場景: 游標在清單項目裡時，該項目縮排一級成為子項目
  假設 編輯區的內容是 "- 第一項"，游標在行尾
  當 使用者按下 Tab
  那麼 內容是 "··- 第一項"

# TC-04
場景: 游標在行首空白區裡時，再縮一級
  假設 編輯區的內容是 "··- 第一項"，游標在第 2 個空白之後
  當 使用者按下 Tab
  那麼 內容是 "····- 第一項"

# TC-05
場景: 空白行也能縮排
  假設 編輯區的內容是一個空白行，游標在該行
  當 使用者按下 Tab
  那麼 該行變成 "··"

# TC-06
場景: 在 fenced code block 裡的行為與正文一致
  假設 編輯區的內容是三行："```ts"、"const answer = 1"、"```"，游標在第二行
  當 使用者按下 Tab
  那麼 第二行變成 "··const answer = 1"
  並且 圍籬那兩行沒有變

# TC-07
場景: 行首空白不是縮排單位的整數倍時，縮排只是再加一個單位
  假設 編輯區的內容是 "···字"（3 個空白），游標在行尾
  當 使用者按下 Tab
  那麼 內容是 "·····字"（5 個空白）

# TC-08
場景: 跨多行選取時每一行都縮排，選取範圍仍然涵蓋原來那段文字
  假設 編輯區的內容是三行 "一"、"二"、"三"，選取從第一行的 "一" 之前到第三行的 "三" 之後
  當 使用者按下 Tab
  那麼 三行分別變成 "··一"、"··二"、"··三"
  並且 選取範圍仍然從第一行的 "一" 之前到第三行的 "三" 之後

# TC-09
場景: 選取只涵蓋兩行的一部分時，那兩行都縮排
  假設 編輯區的內容是兩行 "一二"、"三四"，選取從第一行的 "二" 之前到第二行的 "四" 之前
  當 使用者按下 Tab
  那麼 兩行分別變成 "··一二"、"··三四"

# TC-10
場景: 同一行上有多個游標時，那一行只縮排一次
  假設 編輯區的內容是 "一二三"，同一行上有兩個游標
  當 使用者按下 Tab
  那麼 內容是 "··一二三"（不是縮了兩級）

# TC-39
場景: 選取範圍剛好結束在下一行的行首時，那一行沒有被涵蓋、不縮排
  假設 編輯區的內容是兩行 "一"、"二"，選取從第一行的 "一" 之前到第二行的行首
  當 使用者按下 Tab
  那麼 第一行變成 "··一"
  並且 第二行還是 "二"
```

  那麼 那一行縮排

  假設 編輯區的內容是 "字"（已在最外層）
  當 使用者按下 Shift+Tab
  那麼 內容不變

  假設 編輯區是唯讀的，內容是 "字"
  當 使用者按下 Tab
  那麼 內容不變
  並且 這次按鍵仍然被吃掉（唯讀不是把焦點交出去的理由）

# TC-24

  假設 編輯區的內容是 "con"，游標緊接在 "con" 之後
  當 使用者按下 Tab
  那麼 內容是 "··con"（只多了縮排，沒有任何字被補上或展開）

  那麼 內容只有縮排，沒有出現 "搶走"

### Feature：組字中的 Tab 屬於輸入法

```gherkin
# TC-28
場景: 組字中按 Tab 不縮排，但焦點不會因此離開編輯區
  假設 編輯區的內容是 "字"
  並且 使用者已經開始組字
  當 使用者按下 Tab
  那麼 內容不變
  並且 這次按鍵仍然被編輯區吃掉（不會被拿去移動焦點）
  # 輸入法在按鍵事件的上游：會抵達 App 的 Tab 就是輸入法已經放掉的 Tab，
  # 所以吃掉它並沒有從輸入法手上搶走任何東西，只擋住焦點被搬走。
  # 組字中失焦可能讓組字結束事件永遠不來，那會吃掉已經選好的字。

# TC-29
場景: 組字中按 Shift+Tab 不退縮，那一次按鍵也留在編輯區
  假設 編輯區的內容是 "··字"
  並且 使用者已經開始組字
  當 使用者按下 Shift+Tab
  那麼 內容不變
  並且 這次按鍵仍然被編輯區吃掉

# TC-30
場景: 組字結束後 Tab 回到縮排
  假設 編輯區的內容是 "字"
  並且 使用者開始組字之後又結束組字
  當 使用者按下 Tab
  那麼 內容是 "··字"

# TC-40
場景: 組字進行到編輯器核心不再把按鍵交給任何擴充之後，Tab 仍然不會讓焦點離開
  假設 編輯區的內容是 "字"
  並且 使用者已經開始組字
  並且 編輯器核心已經不再把這次按鍵交給任何按鍵綁定
  當 使用者按下 Tab
  那麼 內容不變
  並且 這次按鍵仍然被編輯區吃掉

# TC-41
場景大綱: 組字中不經按鍵、直接要求縮排或退縮，一樣不得修改內容
  假設 編輯區的內容是 "<內容>"
  並且 使用者已經開始組字
  當 系統的其他部分（例如工具列按鈕）直接要求 <動作>
  那麼 內容不變
  # 這條屬於 FR-8.1：組字中「任何程式碼」都不得修改文件內容，不只按鍵那條路。

  例子:
    | 動作 | 內容 |
    | 縮排 | 字   |
    | 退縮 | ··字 |
```
