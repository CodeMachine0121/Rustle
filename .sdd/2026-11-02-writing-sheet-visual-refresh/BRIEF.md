# 寫作紙張：整體畫面改版 — 需求共識

- **切片**：`feature/writing-sheet-visual-refresh`
- **日期**：2026-11-02
- **狀態**：需求已共識，可進 `/prd`

---

## Goal

寫作者覺得現在的畫面「有點難看」：四欄都長得一樣、每一欄頭上都頂著一行灰色大寫小標、文章清單是一排擠在一起的文字、狀態是一個字一個字寫出來的。這個切片**不增加新的寫作能力**，而是把同樣的四欄重新排出層次：

1. **寫作的地方像一張紙。** 編輯與預覽放在一張圓角的紙上，四周留一圈底色，眼睛一看就知道「這裡是寫字的地方」。側欄和文章清單退到後面，成為安靜的底色。
2. **文章清單變成卡片。** 每張卡片看得到標題、文章開頭的兩行、日期、標籤，狀態變成一個小色點。
3. **一條工具列。** 正在寫哪一篇、它的狀態、編輯／並排／預覽三種看法、專注模式，全部集中在紙張頂端那一條；原本每一欄頭上的大寫小標拿掉。
4. **紙張底部一條狀態列。** 位置、Vim 模式、字數、儲存狀態。
5. **搜尋有一個看得見的入口**，放在側欄最上面。

畫面參考：已確認的設計稿（四欄、紙張、卡片、工具列、狀態列、搜尋面板）。

## Requirements

### 一、版面：三層底色 + 一張紙

- 側欄、文章清單、寫作區**仍是左到右四欄**（側欄、文章、編輯、預覽），專注模式、側欄摺疊、三種看法的行為全部照舊。
- 寫作區（編輯＋預覽）放在**一張紙上**：紙的顏色是畫面底色（淡色主題為白色），四邊圓角，與視窗邊緣留一小圈距離，紙外露出的是側欄的底色。
- 側欄與文章清單**不再顯示欄位頂端的大寫小標**（「WORKSPACES」那三段的段落名稱照舊保留，因為它們是可以摺疊的段落標題，不是欄位標題）。
- 每一欄仍然有自己的名字讓讀螢幕的人知道自己在哪一欄（看不到，但聽得到）。
- **每一個佈景主題都要好看**：淡色、深色、森林三個主題，以及使用者自己加的主題，都只用主題本來就有的顏色畫出來，不另外寫死任何顏色。

### 二、文章卡片

- 每篇文章一張卡片，由上到下：
  1. **狀態色點＋標題**（標題一行，太長就以「…」截掉）；沒有狀態的文章沒有色點。
  2. **摘要**：文章正文的開頭，最多兩行，太長以「…」截掉。
  3. **細節列**：日期、標籤（每個標籤前有 `#`）、「缺少標題資料」與「不在篩選結果中」的提示照舊。在「所有文章」裡還要看得到它屬於哪個 workspace。
- **狀態色點的顏色**：進行中＝主題的連結色、暫停＝主題的警示色、已完成＝主題的成功色、已放棄＝主題的次要文字色。
- 選中的卡片像一張浮起來的紙：底色換成面板色、有細邊框和淡陰影。
- 卡片上「編輯資訊」與「刪除」兩顆小按鈕照舊，滑過卡片或用鍵盤走到時才變清楚。

### 三、摘要怎麼來

- 摘要是**正文的開頭**，不是標題、不是文章資訊區塊。
- 摘要只留**讀得懂的文字**：標題符號（`#`）、引言符號（`>`）、清單符號（`-`、`*`、`1.`、`- [ ]`）、粗體斜體與行內程式碼的記號都拿掉，連結只留文字、圖片整個拿掉，程式碼區塊整個跳過。
- **跳過正文裡的標題行**（大部分文章的第一行就是和標題一樣的 `# 標題`，再看一次沒有意義）。
- 多行接成一行，中間以一個空白隔開；最多保留 **120 個字**，超過的截掉並接上「…」。卡片上最多畫兩行，畫不下的再由畫面截掉。
- 正文是空的（或只有標題、圖片、程式碼）就**不顯示摘要那一行**，卡片不留空白。
- 摘要跟著文章清單一起讀出來：切換 workspace、新增、編輯資訊、刪除、重開 App 時更新。**正在寫的那一篇在打字時摘要不會跟著變**，下次清單重讀時才會變——這是刻意的：清單不因為每一次存檔就重排、閃動。

### 四、工具列

- 工具列在紙的最上面，左邊是**麵包屑**：`workspace / 文章標題`，後面接這篇文章的**狀態膠囊**（色點＋狀態名稱）；沒有狀態就沒有膠囊。沒有打開文章時麵包屑是空的。
- 右邊依序是：**三種看法的分段按鈕**（編輯、並排、預覽，每一顆有圖示也有字）、**專注模式**按鈕。
- 工具列永遠在紙的頂端，**不管是哪一種看法**（只看編輯、並排、只看預覽）都在同一個位置——今天它會跟著跳到不同欄位，改版後不再跳。
- 專注模式中工具列照樣在，麵包屑照樣在。
- 側欄摺疊按鈕照舊在文章清單那一欄的頂端。

### 五、狀態列（紙的底部）

- 由左到右：**Vim 模式標籤**（Vim 開著時才有，做成一個小小的反白標籤）、**位置**（`workspace ❯ 檔名`，照舊）、**字數**、失敗或外部修改的提示（照舊）、最右邊的**儲存記號**（照舊，只有記號沒有字）。
- **字數**：中文、日文的每一個字算一個字；英文與數字以「一串連在一起的字母或數字」算一個字；標點、空白、排版記號（`#`、`-`、`**` 這類寫作者自己打的符號）不算。文章資訊區塊不算（它本來就不在編輯器裡）。
- 字數**跟著打字即時更新**；中文選字中還沒送出的拼音不算。
- 中文介面寫成「1,284 字」，英文介面寫成「1,284 words」；一個字的英文寫成「1 word」。千位用逗號。
- 沒有打開文章時整條狀態列不顯示（照舊）。

### 六、側欄

- 側欄最上面一顆**搜尋按鈕**，寫著「搜尋」並標出它的鍵 `⌘T`，按下去等於按 `⌘T`：打開「依標題找文章」。
- 「所有文章」、每個 workspace、每個狀態、每個標籤各是一列，右邊靠齊數量；被選中的那一列有圓角底色。
- workspace 列前面有資料夾圖示；狀態列前面有該狀態的色點（未標記沒有色點）；標籤列前面有 `#`。
- 側欄底部的設定齒輪照舊。

### 七、字型

- 介面用系統的無襯線字（中文為蘋方）。
- 編輯器維持等寬字。
- **預覽改用襯線字**（中文為宋體），讓「在寫」和「在讀」看起來不一樣。
- 不從網路下載任何字型（這個 App 不連網）。

### 八、搜尋面板與對話框

- 「依標題找文章」與「依內文找文章」兩個面板的行為照舊，只換外觀：更大的圓角、更明顯的陰影、輸入框更大、選中的那一列有圓角底色。
- 新增文章、編輯資訊、設定、刪除確認等對話框只換外觀（圓角、陰影、間距），內容與行為不動。

## Out of Scope

- 依「本週／更早」分組卡片（設計稿上有，但它需要新的時間規則，另開切片）。
- 搜尋面板上「標題／內文」的分頁切換（兩個面板仍各用自己的鍵打開）。
- 儲存記號加上「已儲存」文字（之前的切片刻意只用記號，不改）。
- 新的佈景主題、新的顏色。
- 編輯器內的語法顏色、Vim 行為、任何快捷鍵。
- 打字時即時更新卡片摘要。

## Open Decisions

PRD 作者需決定：
- 圖示的細節（資料夾、搜尋、看法分段按鈕上用哪一個圖示）——沿用 App 現有的線條圖示風格即可。
- 紙與視窗邊緣的距離、圓角大小、陰影深淺的實際數值。

## Context / Background

- 使用者看過設計稿後說「好，開個 branch 進行開發」，並交代所有需要詢問的地方**一律採用最佳實務**，不必等回答。本文件中所有取捨都是依此原則自行決定：
  - 摘要只在清單重讀時更新（避免清單隨每次存檔閃動）。
  - 儲存記號保持無字（尊重先前切片的決定）。
  - 設計稿上的「本週／更早」分組與搜尋分頁不在本切片。
  - 字型只用系統字型（App 不連網，也不想塞進大型中文字型檔）。
  - 狀態色只借用主題既有的四種語意色，不新增主題欄位，自訂主題不必改。
- 流程：clarify → prd → architecture → implement（code-first）→ improve-codebase → contract。
- 例子裡出現的 `#`、`>`、`-`、`**`、`[文字](網址)` 是寫作者自己在文章裡打的排版記號，屬於這個 App 的業務語言（寫作者每天看得到、打得出來），不是實作細節，所以保留原樣。
