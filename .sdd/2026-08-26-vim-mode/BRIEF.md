# Vim 模式 — 需求共識

- **切片**：`feature/vim-mode`
- **日期**：2026-08-26
- **狀態**：需求已共識，可進 `/prd`

---

## Goal

給寫作區一套 **Vim 的操作方式**，讓習慣 Vim 的寫作者不必把手離開字母區就能移動、選取、修改文字。它是一個**可以在設定裡開關的選項**，預設關閉——沒開的人，這個 App 從頭到尾跟今天一模一樣。

開啟之後，寫作區隨時處在三個模式之一：**Normal**（按鍵是指令，不是打字）、**Insert**（打字）、**Visual**（有選取）。寫作者現在在哪個模式，寫在**寫作區底下那條狀態列**上，不必用猜的。

這個切片刻意只做「三個模式 + Vim 的移動與編輯按鍵」。Vim 的指令列與搜尋不在這一版。

---

## Requirements

### 一、一個可以開關的設定，預設關閉

- 設定畫面多一項「Vim 模式」，與既有的語言、主題同住一個地方。
- **預設關閉**。從來沒動過這個設定的寫作者，什麼都不會發現。
- 打開的**當下立刻生效**，不必重開 App；生效那一刻，游標所在的寫作區當場進入 **Normal 模式**。
- 關閉的當下也立刻生效，寫作區回到今天的樣子。
- 這個選擇**每個 Vault 各記一份**——與縮排、主題、語言同一條既有慣例。在一個 Vault 打開，不會影響另一個。

### 二、三個模式，以及它們怎麼換

- **Normal**：按鍵是指令。這是開啟設定、以及每次離開 Insert／Visual 之後回到的地方。
- **Insert**：打字。從 Normal 進去的方式就是 Vim 一貫的那些鍵。
- **Visual**：有選取。

**「有選取就是 Visual」是一條沒有例外的規則。** 不論選取是怎麼來的——滑鼠拖曳、Command+W 擴大選取、Shift 加方向鍵——一律進入 Visual 模式，**包含原本在 Insert 模式的時候**。反過來也一樣：選取一旦消失（點一下別處、按了方向鍵），一律回到 **Normal**。

寫作者只要記一件事：**畫面上有沒有反白，決定了是不是 Visual。**

### 三、模式寫在寫作區底下那條狀態列上

- 位置在**那條線的中間**——左邊的文章路徑與右邊的儲存指示都不動。
- 文字固定是 **`NORMAL`／`INSERT`／`VISUAL`**，**兩種介面語言都不翻譯**。Vim 的模式名稱是全世界寫 Vim 的人共用的詞，翻譯只會讓找資料的人對不起來。
- **Vim 模式關閉時，這一格什麼都不畫**——不是畫一個空白或一個「關閉中」，是整格不存在。
- 排法切成「只有預覽」時，那條狀態列本來就整條不畫，所以模式也不在。這不是為 Vim 定的規則，是既有規則的結果。

### 四、既有的快速鍵，一個都不讓

**這是這個切片最硬的一條承諾：開了 Vim 模式，今天會的每一個快速鍵，行為完全不變。**

- **Command+W（逐層擴大選取）**——任何模式下都照舊。它做完之後畫面上有選取，所以依第二條規則，模式會變成 Visual。
- **Tab／Shift+Tab（縮排／退縮）**——任何模式下都是縮排，不是 Vim 的 Tab。
- **Enter（表格續行）**——游標在表格那一行時，任何模式下都是多一列表格，不是 Vim 的「跳到下一行行首」。
- **Command+B／Command+I（粗體／斜體）**、**Command+0（字體放回預設）**、**Command+Shift+P（預覽開關）**——全部照舊。

理由是一致的：這些鍵是這個 App 教給寫作者的，一個設定不該讓它們失效。**衝突一律由 Vim 讓步。**

### 五、ESC 是一座梯子，由上往下，誰先有事誰先接

ESC 今天已經有工作在身，這個切片把它整理成**一座從裡到外的梯子**。同一座梯子在 Vim 開與不開之下**只差一層**，其餘完全相同。

由上到下依序是：

1. **片語選單開著** → 關掉選單。
2. **正在填空** → 停止填空。
3. **（只有 Vim 開著時才有這一層）不在 Normal 模式** → 回到 Normal 模式。
4. **在專注模式** → 離開專注模式。
5. **以上都不是** → 什麼都不做。

每一次 ESC **只走一層**。所以在專注模式裡、Insert 模式、選單又開著的時候，要按三次 ESC 才會離開專注模式——每一次都做一件看得見的事，而不是一次把三件事做完。

**「離開專注模式」是這個切片新加的行為。** 今天離開專注模式只能按那顆按鈕。

### 六、被讓出去的一件事：鍵盤走出寫作區的那條路

今天鍵盤使用者離開寫作區、回到文章清單的方式是**按 ESC 再按 Tab**。ESC 改成上面那座梯子之後，**這條路不再存在**。

這是**明知且接受的取捨**，寫在這裡是為了讓將來讀到的人知道它是被決定掉的，不是被漏掉的。要回到文章清單，得用滑鼠點。

### 七、輸入法組字中，一律不作用

寫作者按下按鍵、但輸入法還沒把字定下來的那段時間，**Vim 不接任何按鍵**——那一次按鍵屬於輸入法。這是這個 App 既有的一條規則，Vim 沿用，不另立一套。

## Out of Scope

- **Vim 的指令列**（`:` 開頭的那些）。這個 App 自動存檔，`:w` 沒有事情可做；關閉視窗已經有自己的快速鍵。
- **Vim 的搜尋**（`/`、`n`、`N`）。這一版不做，日後要的話另開切片。
- **讓寫作者自訂 Vim 的按鍵對應**。這一版只有「開」與「關」兩個選擇。
- **重做一條走出寫作區的鍵盤路徑**。第六條已經說明這是接受的取捨。
- **Vim 模式在預覽面板裡作用**。這個設定只影響寫作區。

## Open Decisions

留給 `/prd` 作者釐清的細節：

- Normal 模式底下按 Enter 而游標**不在表格行**時，該做什麼？（在表格行的答案已經定了：多一列表格。）
- Normal 模式底下，Vim 的哪些編輯指令會與「不讓任何既有快速鍵」相衝？目前已知的四組鍵都已定案，但逐條清點應在 PRD 完成。
- 模式標籤在狀態列上放不下時（文章路徑很長、視窗很窄）誰先被收掉？既有規則是「先收 workspace 那一段、檔名永遠完整」，模式標籤要插在這個優先序的哪裡。
- 一個 Vault 底下開著多篇文章、在文章之間切換時，模式要**帶過去**還是**回到 Normal**？
- 「離開專注模式」這一層要不要在 Vim 關著的人身上也成立？（本共識的答案是「要」，但它是一個獨立於 Vim 的新行為，PRD 需確認它不與別的切片打架。）

## Context / Background

- 這個 App 目前的設定畫面只有**語言**與**主題**兩項，Vim 模式是第三項。
- 寫作區底下那條狀態列今天有兩樣東西：左邊的文章路徑、右邊的儲存指示。模式標籤是第三樣，插在中間。
- **ESC 今天身上已經有三件工作**：關閉片語選單、停止填空、以及「按 ESC 再按 Tab 走出寫作區」。共識過程中確認第三件必須讓位，前兩件保留並排進梯子。
- 共識過程中，一度以為片語選單開著的時候焦點不在寫作區，因此 ESC 會落空。**這是誤會**：那個選單浮在游標旁邊，填空更是直接長在文章的字裡面，兩種情況下焦點都在寫作區。梯子的順序就是為了處理這件事。
- 「有選取就是 Visual」包含 Insert 模式，這**比一般 Vim 的作法更寬**——一般 Vim 在 Insert 模式下用滑鼠選字不會進 Visual。這是刻意的選擇：讓寫作者只要記「畫面上有沒有反白」，而不必再記「我剛才在哪個模式」。
