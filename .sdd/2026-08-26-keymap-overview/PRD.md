## 1. Background & Goal

### Problem Statement

Rustle 教過寫作者十來個快捷鍵，而**沒有任何一個畫面說得出它們**。寫作者只能靠記憶，或是靠不小心按到。

其中兩個特別需要一個查得到的地方：

- **`Cmd+W` 不再關閉視窗**——它是「逐層擴大選取」，關閉視窗讓到了 `Shift+Cmd+W`。按下 `Cmd+W` 發現視窗沒關的人，今天無處可查。
- **開關預覽的鍵可以在設定檔改**，所以「它現在是哪個鍵」只有設定檔知道。

### Expected Outcome

設定對話框裡多一顆按鈕，點下去看得到一張表：**這個 App 自己教的每一個快捷鍵，分成三組，鍵寫成 macOS 的符號，說明跟著介面語言。**

### Out of Scope

- **改鍵。** 這一版只能看。
- **Vim 的按鍵表。** 那是另一套完整的鍵盤語言，有全世界共通的說明可查。
- **作業系統與編輯器出廠的鍵**（還原、重做、剪下貼上、對話框的 `Enter`）——**除了被這個 App 改掉的「關閉視窗」**。
- **調字體大小的手勢**（捏合、`⌘`+滾輪）。不是按鍵。
- **搜尋這張表**、**Windows／Linux 的寫法**。

---

## 2. User Personas

- **主要角色：寫作者。** 兩種情況會來這裡：一種是按了 `Cmd+W` 卻沒關到視窗、想知道發生什麼事；另一種是想知道「這個 App 還有什麼是我不知道的」。
- **使用情境**：macOS 桌面 App，寫作中途順手打開設定看一眼。

## 3. User Stories & Acceptance Criteria

### US-01 — 從設定進到快捷鍵清單，再回來 [priority: P0]

**As a** 寫作者，**I want** 在設定裡按一顆按鈕就看到所有快捷鍵，**so that** 我不必靠記憶或不小心按到才知道這個 App 會什麼。

```gherkin
Scenario: 設定裡有這顆按鈕
  Given 寫作者打開了設定對話框
  When 寫作者看畫面
  Then 語言、主題與 Vim 模式底下有一顆寫著「快捷鍵」的按鈕

Scenario: 按下去,對話框的內容換成清單
  Given 設定對話框開著
  When 寫作者按下「快捷鍵」
  Then 快捷鍵清單出現在同一個對話框裡
  And 語言、主題與 Vim 模式三項都不在畫面上

Scenario: 返回,回到設定而且什麼都沒被改動
  Given 快捷鍵清單開著
  When 寫作者按下返回
  Then 語言、主題與 Vim 模式三項都回到畫面上
  And 三項的值與進入清單之前完全相同

Scenario: 在清單上按 ESC,整個對話框關閉
  Given 快捷鍵清單開著
  When 寫作者按下 ESC
  Then 整個設定對話框關閉
  And 下一次寫作者按下齒輪時,打開的是設定而不是清單

Scenario: 關掉再打開,回到設定那一面
  Given 寫作者看過快捷鍵清單,並且關掉了對話框
  When 寫作者再次按下齒輪
  Then 打開的是設定,不是快捷鍵清單
```

### US-02 — 清單只列這個 App 自己教的鍵 [priority: P0]

**As a** 寫作者，**I want** 這張表只列 Rustle 自己的鍵，**so that** 真正需要查的那幾條不會被我早就會的鍵淹掉。

```gherkin
Scenario: 被改掉的那個鍵找得到
  Given 快捷鍵清單開著
  When 寫作者找「逐層擴大選取」
  Then 有這一列,鍵顯示為「Cmd+W」

Scenario: 讓位之後的關閉視窗也找得到
  Given 快捷鍵清單開著
  When 寫作者找「關閉視窗」
  Then 有這一列,鍵顯示為「Shift+Cmd+W」

Scenario: 原生的鍵不在清單裡
  Given 快捷鍵清單開著
  When 寫作者找「還原」與「重做」
  Then 清單裡沒有這兩列

Scenario: Vim 開著也不會多出任何一列
  Given Vim 模式是開啟的
  And 快捷鍵清單開著
  When 寫作者看清單
  Then 清單的每一列與 Vim 模式關閉時完全相同

Scenario: 三組,由上到下
  Given 快捷鍵清單開著
  When 寫作者看分組
  Then 由上到下依序是「寫作」、「畫面」、「視窗」三組
```

### US-03 — 鍵寫成符號，說明跟著語言 [priority: P0]

**As a** macOS 上的寫作者，**I want** 鍵寫成我在每個 App 選單裡都看得到的那種符號，**so that** 我一眼就認得出來要按什麼。

```gherkin
Scenario: 說明跟著介面語言
  Given 介面語言是中文,快捷鍵清單開著
  When 寫作者看「粗體」那一列
  Then 說明是中文

Scenario: 鍵名不跟著介面語言
  Given 介面語言是英文,快捷鍵清單開著
  When 寫作者看同一列
  Then 鍵仍然顯示為「Cmd+B」

Scenario: 鍵寫成鍵上印的字
  Given 快捷鍵清單開著
  When 寫作者看「縮排」那一列
  Then 鍵顯示為「Tab」,不是「⇥」

Scenario: 每一列只寫那個鍵做什麼
  Given 快捷鍵清單開著
  When 寫作者看每一列的說明
  Then 每一條都是一個名詞,沒有一條是句子
```

### US-04 — 預覽開關顯示現在真正在用的鍵 [priority: P0]

**As a** 改過設定檔的寫作者，**I want** 這張表說的是我現在真正在用的那個鍵，**so that** 唯一該給我答案的地方不會給我一個假的答案。

```gherkin
Scenario: 沒改過設定的人看到預設值
  Given 這個 Vault 的設定沒有說開關預覽要用哪個鍵
  And 快捷鍵清單開著
  When 寫作者看「開關預覽」那一列
  Then 鍵顯示為「Shift+Cmd+P」

Scenario: 改過設定的人看到自己改的值
  Given 這個 Vault 的設定說開關預覽是「Cmd+Alt+K」
  And 快捷鍵清單開著
  When 寫作者看那一列
  Then 鍵顯示為「Option+Cmd+K」

Scenario: 設定寫了讀不懂的值,顯示 App 實際會回應的那個鍵
  Given 這個 Vault 的設定裡,開關預覽那一格寫著讀不懂的東西
  And 快捷鍵清單開著
  When 寫作者看那一列
  Then 鍵顯示為「Shift+Cmd+P」
```

## 4. Business Flow & Logic

### 核心業務規則

**規則一：列進這張表的判準是「這是 Rustle 教給寫作者的嗎」。**

| 列 | 不列 |
| :--- | :--- |
| 縮排、退縮、表格續行、片語選單、粗體、斜體、逐層擴大選取、`Esc` 的梯子 | 還原、重做、剪下、複製、貼上、全選 |
| 開關預覽、字體放回預設 | 對話框的 `Enter` |
| **關閉視窗**——因為它是**被這個 App 改掉的**原生鍵 | Vim 的任何一個鍵 |

**「關閉視窗」不是規則一的例外，而是規則一的結果**：`Cmd+W` 被拿去做別的事，`Shift+Cmd+W` 是這個 App 教的新答案。

**規則二：這張表的內容不隨模式改變。** Vim 開或關，每一列都相同。`Esc` 那一列的說明因此寫成兩種情況下都成立的話。

**規則三：鍵用符號，說明用語言。** 符號不是語言，兩種介面語言看到的符號一模一樣。

**規則四：可設定的那一列問設定，不問常數。** 設定讀不懂時顯示的是**這個 App 實際會回應的那個鍵**——與其它地方讀設定的寬容規則同一條。

### 清單內容

**規則五：一列只寫那個鍵做什麼，寫完就停。**

**這張表是拿來掃的，不是拿來讀的。** 寫作者打開它是為了找**一個**鍵，而找法是眼睛沿著一欄短名稱往下走。一欄句子沒有人掃得動——第一版寫的是「縮排／退縮；填空時是下一個／上一個空格」那種，那不是表格，是段落。

所以每一列都是一個**名詞**。一個鍵在第二種情境下做什麼（`Tab` 在填空時是下一個空格），寫作者是**在那裡按下去**發現的，不是在這裡讀一個子句學到的。

`Tab` 與 `Shift+Tab` 因此**分成兩列**——它們本來就是兩個鍵，擠成一列才需要那個分號。

**寫作**

| 鍵 | 說明 |
| :--- | :--- |
| `Tab` | 縮排 |
| `Shift+Tab` | 退縮 |
| `Enter` | 續行 |
| `/` | 片語選單 |
| `Cmd+B` | 粗體 |
| `Cmd+I` | 斜體 |
| `Cmd+W` | 擴大選取 |
| `Esc` | 退出 |

**畫面**

| 鍵 | 說明 |
| :--- | :--- |
| （設定值，預設 `Shift+Cmd+P`） | 開關預覽 |
| `Cmd+0` | 字體回預設 |

**視窗**

| 鍵 | 說明 |
| :--- | :--- |
| `Shift+Cmd+W` | 關閉視窗 |

### 邊界情況

| 情況 | 行為 |
| :--- | :--- |
| 對話框關掉再打開 | 一律回到設定那一面。哪一面在看不跨開關記住——它不是一個偏好 |
| 專注模式 | 齒輪本來就不在畫面上，所以這顆按鈕也不在。既有規則的結果 |
| 清單很長裝不下 | 對話框內捲動；設定那一面不受影響 |

## 5. UI/UX Design & Interaction

- **按鈕**：設定對話框最下面，在 Vim 模式底下。文案：中文「快捷鍵」／英文「Keyboard Shortcuts」。
- **清單畫面**：與設定同一個對話框、同樣的寬度與外框。最上面一列是返回加上標題「快捷鍵」。
- **每一列**：左邊說明，右邊鍵。鍵用等寬字，與說明分得開。
- **分組標題**：與設定面板的標題同一種樣子（小字、字距拉開、muted 色）。
- **返回**：一個向左的箭頭圖示加上可讀給輔助科技的名稱，比照這個產品既有的圖示按鈕。
- **沒有空狀態**：這張表永遠有東西。
- **沒有載入狀態**：不取任何非同步資料。

---

## 6. Non-Functional Requirements

- **顏色一律取自當前主題**，不得自帶顏色。
- **每一個讀者看得到的字都來自介面文案表**，符號除外——符號不是這個 App 說的話。
- **不影響寫作區**：這個功能完全活在設定對話框裡。
- **分析事件**：本專案無分析追蹤，N/A。

---

## 7. Dependencies & Risks

**外部依賴**：無。不新增任何套件。

| 風險 | 處置 |
| :--- | :--- |
| **這張表會與程式碼漂移。** 有人改了某個鍵卻忘了改表 | 表的內容是**一份可測的資料**，而不是散在畫面裡的字串；驗收情境逐條釘住關鍵的幾列。真正的保險是把它寫進通用語言地圖，讓「改鍵要同步改表」成為明說的規矩 |
| 預覽那一列與實際綁定的鍵不一致 | 那一列問的是**同一個**解析設定的物件，不是自己再解析一次 |
