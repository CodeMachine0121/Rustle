# Vim 模式下 Tab 永遠是縮排 — 需求共識

- **切片**：`feature/tab-always-indents-in-vim-mode`
- **日期**：2026-09-08
- **上游**：`.sdd/2026-09-08-zen-key-sidebar-fold-and-settings-key/`（本切片推翻它接受的一項取捨）
- **狀態**：需求已共識，可進 `/prd`

---

## Goal

**Vim 模式開著的時候，`Tab` 永遠是縮排，沒有例外。**

上一個切片把「離開專注模式」從 `Esc` 身上拆下來，順手拿掉了「不管有沒有人接手都吃掉這個按鍵」那一層。結果是編輯器自己的「`Esc` 之後那一次 `Tab` 交出去移動焦點」又活了過來——**包含 Vim 的常態模式**，因為 Vim 對常態模式的 `Esc` 明說沒它的事、不接手。

那個切片接受了這個代價並寫進風險表。使用者裁決：**不接受**。理由很直接——Vim 使用者一天按幾百次 `Esc`，其中一大半是「按了保險」的習慣動作；接著按 `Tab` 想縮排，卻發現游標不見了、焦點跑到別的欄位去，這是一天裡最刺的那種打斷。

---

## Requirements

### 一、Vim 模式開著時，`Tab` 只有一種意思

- 不論剛才按了什麼，**`Tab` 一律縮排**。
- 特別是：按了 `Esc`（不論在常態模式按、還是從輸入模式退出來）之後緊接著按 `Tab`，**還是縮排**。

### 二、Vim 模式關著時，一切照舊

- 「沒人要的 `Esc` 之後那一次 `Tab` 移動焦點」**照舊留著**。那是編輯器因為吃掉 `Tab` 而欠鍵盤使用者的路，不開 Vim 的人只有這一條。
- 片語選單、填空、設定面板、篩選框對 `Esc` 的既有反應，一個字都不改。

### 三、`Esc` 本身的意思不變

- 這個切片**不把任何功能加回 `Esc`**。`Esc` 仍然只做 Vim 退回常態模式、關選單、停填空。
- 改的只有一件事：Vim 模式開著時，沒人要的那一次 `Esc` **留在編輯器裡**，而不是交出去武裝那條路。

### 四、接受的代價

- **Vim 模式開著時，只用鍵盤的人沒有辦法用 `Tab` 離開寫作區。** 這是使用者明知並選擇的：Vim 本身就是一套完整的鍵盤語言，開著它的人本來就不靠 `Tab` 走位；而縮排是每一段都會用到的動作。
- 這條代價寫在這裡，不留給下一個人重新發現。

## Examples (Specification by Example)

| # | Given（只列相關資料） | When | Then |
|---|---|---|---|
| 1（happy）| Vim 模式開著、常態模式 | 按 `Esc`，再按 `Tab` | **縮排**（今天是移動焦點） |
| 2（happy）| Vim 模式開著、輸入模式 | 按 `Esc` 退回常態，再按 `Tab` | 縮排（今天就是，不變） |
| 3（happy）| Vim 模式開著 | 直接按 `Tab` | 縮排（不變） |
| 4（branch）| **Vim 模式關著** | 按 `Esc`，再按 `Tab` | **移動焦點**（不變） |
| 5（branch）| **Vim 模式關著** | 按 `Esc`，按一個別的鍵，再按 `Tab` | 縮排（不變，那條路只有一次按鍵寬） |
| 6（boundary）| Vim 模式開著、片語選單開著 | 按 `Esc` | 選單關掉（不變） |
| 7（boundary）| Vim 模式開著、填空進行中 | 按 `Esc` | 停止填空（不變） |
| 8（boundary）| Vim 模式開著、專注模式開著 | 按 `Esc` | 專注模式仍然開著（不變） |
