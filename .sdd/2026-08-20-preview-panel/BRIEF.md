# 需求共識 — 預覽面板（第四欄）

- **切片**：Wave 3，`feature/preview-panel`
- **日期**：2026-08-20
- **輸入**：需求文件 §4.1（版面示意圖）、§4.6（FR-5.1 ~ FR-5.5、FR-5.7、FR-5.10 ~ FR-5.12）、§6.2（FR-8.5、FR-8.7）、§6.3（T-8）、§7.3（安全基線與 Markdown 渲染器、HTML 淨化器的選型）、§7.4（自訂 protocol 那一列）、NFR-2、NFR-3、NFR-6
- **狀態**：需求已定案（v0.3），本階段不回頭問使用者。需求文件留白處由本檔第 7 節裁決，並同步寫進 PR 說明

---

## 1. 這個切片要解決的問題

需求文件 §1 的第五個核心主張是「**寫作時看得到成品**」：編輯區維持 Markdown 原始碼（§1.1 明確不做 Typora 式打字即渲染，理由之一正是替換式 widget 會打斷組字），所以「看得到成品」這件事**整個押在預覽面板上**。沒有它，這個產品只剩一個看不到結果的純文字編輯器。

但這個切片的難處不在「把 Markdown 變成 HTML」，而在三件互相拉扯的事：

1. **這是一個安全需求，不是排版需求。** FR-5.11 要渲染的是「使用者可能從任何地方貼進來的文字」，而它跑在一個握有檔案系統能力的桌面 App 裡。預覽面板是這個 App 唯一一個「把外來內容變成可渲染 HTML」的地方，也就是唯一一個 XSS 有意義的入口。
2. **渲染工作不能搶走輸入法的時間。** FR-8.5／T-8 要求組字期間不重繪——一個候選視窗被渲染工作擋住的產品，違反 NFR-5（文字輸入正確性是最高優先的非功能需求）。
3. **它要留給隔壁兩條切片的接縫，而不是擋住它們。** 捲動同步（FR-5.8）需要行號、貼上圖片（FR-5.9）需要圖片來源改寫，兩者都不屬於本切片，但都建在本切片的渲染輸出上。

## 2. 對誰有價值

| 角色 | 拿到什麼 |
| :--- | :--- |
| 使用者（James，每天用中文寫文章） | 打字的同時右邊就看到成品；不想看的時候一個按鍵收起來，編輯區佔滿寬度；下次開 App 記得他的選擇 |
| 使用者（會從網頁、Word、別的編輯器貼東西進來） | 貼進來的原始 HTML 不會在他自己的 App 裡執行任何東西，也不會偷偷連出去 |
| 捲動同步切片 | 每個區塊元素上已經有正文行號，不必回頭改渲染管線 |
| 貼上圖片切片 | 相對路徑的圖片來源原樣留在輸出裡，只要在渲染那一刻改寫成 `rustle:` URL 即可 |
| 可拖曳分隔線切片 | 第四欄已經是版面上的一欄，開關與持久化都在，只差寬度 |

## 3. 成功的樣子（可觀察的行為）

1. 選一篇文章 → 右邊第四欄出現渲染好的內容：標題是標題、清單是清單、表格是表格、程式碼有語法高亮、任務清單有勾選框。
2. 打字 → 停手約 0.15 秒後預覽跟上；連續打字期間不會一個字重繪一次。
3. **用注音打字、盯著候選視窗想 3 秒**——預覽完全沒有動；選完字之後才更新。
4. 正文裡的 `<script>`、`onerror=`、`javascript:` 連結、`<iframe>`、外部圖片網址，在預覽裡**一個都不生效**：沒有程式碼被執行，沒有任何一個連向外面的請求。
5. 按面板標題列的關閉鈕，或按 `Cmd/Ctrl + Shift + P` → 整欄收起來，編輯區立刻吃掉那塊寬度；邊緣留著一個把手，看得出預覽還在。
6. 按把手或再按一次快捷鍵 → 面板回來。
7. 關掉 App 再開 → 面板還是上次那個狀態（開或關）。
8. 沒有選取文章時，預覽面板顯示的空狀態**跟編輯區一模一樣**，而且面板裡沒有任何可以打字的地方。
9. 系統切到深色模式 → 預覽的底色與文字色跟著換，程式碼高亮也換。
10. 正文永遠只有正文：front matter 不會出現在預覽裡。

## 4. 邊界：本切片明確不做

| 不做 | 誰做 |
| :--- | :--- |
| 編輯區與預覽之間的**可拖曳分隔線**、寬度比例持久化（FR-5.6） | Wave 4 `feature/preview-scroll-sync-and-resizable-divider` |
| **捲動同步**（FR-5.8） | 同上。本切片只負責把行號寫進 HTML（那是它的前提） |
| **`images/` 圖片真的顯示出來**（FR-5.9）、`rustle:` protocol handler 的實作 | Wave 4 `feature/paste-image-to-workspace`。本切片只負責「相對路徑不被淨化掉」「`rustle:` 是允許的圖片來源」 |
| 設定畫面（讓使用者用 GUI 改快捷鍵或縮排） | 目前**沒有主人**。本切片把快捷鍵做成設定檔欄位（使用者手改 `.rustle/settings.json`），不自己長一個設定畫面出來 |
| 預覽裡的目錄（TOC）、數學式、圖表、腳註、emoji | 需求文件沒有要求，不自己加 |
| 匯出 HTML／列印 | 需求文件 §1.1 的非目標 |
| 裸網址自動連結（GFM autolink literal） | 沒有人。FR-5.10 點名的 GFM 擴充只有四項，見假設 A-3 |
| 在預覽裡點任務清單的勾選框改動正文 | 需求文件沒有要求。預覽是唯讀的，見假設 A-4 |

### 5.2 淨化（FR-5.11）——這一節就是驗收的重點

| # | 正文裡有 | 預覽裡必須 |
| :--- | :--- | :--- |
| 1 | `<script>window.pwned = true</script>` | 沒有 `<script>`，**連裡面的文字都不留**，而且 `window.pwned` 依然是 undefined |
| 2 | `<img src="x" onerror="window.pwned = true">` | 沒有任何 `on…` 屬性 |
| 3 | `<div onclick="…">`、`<p onmouseover="…">`、`<body onload="…">` | 同上：事件屬性一律不存在 |
| 4 | `[點我](javascript:window.pwned = true)` | 連結文字留著，`href` 不存在 |
| 5 | `<a href="JaVaScRiPt:alert(1)">`、`<a href="java&#9;script:alert(1)">` | 同上（大小寫、控制字元、HTML 實體都繞不過去） |
| 6 | `<iframe src="…">`、`<object>`、`<embed>` | 元素完全不存在 |
| 7 | `<img src="https://example.com/pixel.png">` | `src` 不存在——**不得發出任何對外請求**（NFR-2） |
| 8 | `<img src="data:image/svg+xml;base64,…">` | `src` 不存在（見假設 A-5） |
| 9 | `<svg><script>…</script></svg>` | `<svg>` 與它的內容都不存在 |
| 10 | `<base href="https://evil.example/">` | 不存在 |
| 11 | `<meta http-equiv="refresh" content="0;url=…">` | 不存在 |
| 12 | `<style>body{display:none}</style>`、`style="background:url(https://…)"` | 都不存在（連 `style` 屬性都不允許） |
| 13 | `<form>`、`<input>`、`<textarea>`、`<button>` | 預覽裡**沒有任何可輸入或可送出的元素**（FR-4.8 的精神） |
| 14 | `<link rel="stylesheet" href="https://…">` | 不存在 |
| 15 | `<a href="https://example.com">正常連結</a>` | **保留**：外部連結不是「載入外部資源」，而且點下去由既有的導覽政策交給系統瀏覽器 |
| 16 | `![](images/8f3c.png)` | `src` **原樣保留**為相對路徑（這是 FR-5.9 的接縫） |
| 17 | `<img src="rustle://…">` | 保留（那正是圖片切片渲染時會改寫成的形態） |

## 6. 這個切片跟輸入法的關係

| 條文 | 本切片怎麼滿足 |
| :--- | :--- |
| **FR-8.5**（組字中不重繪） | 重繪走**地基切片已經有的** `CompositionAwareDebounce`（150ms）。不自己做第三個計時器 |
| **FR-8.7**（組字中的快捷鍵屬於輸入法） | 開關預覽的快捷鍵在組字中不作用 |
| **FR-8.1／FR-8.2**（組字中不改文件、不重建游標附近的畫面元素） | 預覽面板**完全不碰編輯器的文件**，也不在編輯區裡加任何裝飾。它只加一個回報文件內容變更的監聽 |

人工回歸清單受影響的項目：

| 項目 | 影響 |
| :--- | :--- |
| **T-8**（組字停留超過 2 秒） | 這一項在自動儲存切片交付後只剩「預覽不重繪」還沒有主人。**本切片交付後它才是完整的驗收**，清單要改 |
| T-1 ~ T-4、T-12 | 預覽面板現在會在打字期間做事，理論上可能搶主執行緒。重跑時要順便看候選視窗有沒有延遲 |

## 7. 假設（需求文件留白處，本切片自行裁決）

| # | 空白 | 裁決 | 理由 |
| :--- | :--- | :--- | :--- |
| A-1 | FR-5.4 的「工具列按鈕」指哪一顆按鈕（App 沒有工具列） | **面板標題列的關閉鈕（開著時）＋ 收合後的把手（關著時）**，兩個狀態各有一顆看得見的按鈕 | 需求文件 §4.1 的兩張示意圖畫的就是這兩顆：`PREVIEW [✕]` 與收合後的 `◀ 預覽`。另外在 App 標題列再加一顆等於同一件事有三個入口 |
| A-2 | 快捷鍵的 `Cmd/Ctrl` 怎麼判平台、「可於設定調整」調在哪 | `Mod` **同時接受 Cmd 與 Ctrl**，不做平台判斷；設定值放 `.rustle/settings.json` 的 `previewPanel.toggleShortcut`（預設 `Mod+Shift+P`） | NFR-1 要求三平台一致，而「兩個都收」比「猜使用者在哪個平台」少一個會壞的地方。設定檔是使用者手改的檔案（見設定檔文件物件的註解），所以「可於設定調整」不需要等一個設定畫面 |
| A-3 | FR-5.10 的「GFM 擴充」要做到哪 | **只做需求點名的四項**：表格、任務清單、刪除線、fenced code 語法高亮。不開裸網址自動連結、不開排版美化（typographer）、單一換行不變 `<br>` | 括號裡那四項就是需求給的清單。自動連結會把使用者寫的純文字網址變成連結，那是「幫使用者改內容」，需求沒有要求 |
| A-4 | 任務清單的勾選框用什麼元素、可不可以點 | **不可互動的標記**（`role="checkbox"` + `aria-checked` 的 span），**不用 `<input>`**；點它不會改正文 | 兩個理由：（1）FR-4.8 的精神是「畫面上不該有沒有主人的可輸入區域」，預覽是唯讀的；（2）不允許 `<input>` 之後，使用者貼進來的 `<input type="text">` 就沒有任何路徑能在預覽裡變成一個輸入框 |
| A-5 | 圖片 `src` 允許哪些形態 | **只允許相對路徑與 `rustle:`**；`http(s)`、`data:`、`file:` 一律移除 | NFR-2 要求完全離線、FR-5.11 明文禁止外部資源載入；R-17 規定正文只存相對路徑，所以合法的圖片來源只有這兩種。`data:` 一併擋掉是因為 SVG-in-data-URL 是淨化器的經典繞過面，而它不在任何一條需求的路徑上 |
| A-6 | 連結 `href` 允許哪些 scheme | 相對、`http`、`https`、`mailto` | 連結不是「載入」，點下去由地基切片的導覽政策接手（外部一律交給系統瀏覽器）。其餘 scheme（`javascript:`、`data:`、`vbscript:`、`file:`）沒有任何正當用途 |
| A-7 | 開啟另一篇文章要不要等去抖動 | **不等，立刻渲染** | FR-5.7 的去抖動是為了「打字過程不掉字不卡頓」。開檔是一次性動作，等 150ms 只是讓人多看 150ms 的空白 |
| A-8 | 面板收合時還要不要渲染 | **不渲染**（沒有人看得到），但正文變更照樣收下，展開時立刻正確 | 收合時渲染是純浪費，而它浪費的正是 FR-8.5 想保護的主執行緒 |
| A-9 | 行號從 0 還是 1 起算、寫在哪一層元素上 | **0 起算**（Markdown 解析器回報的原始行號），寫在**區塊層**元素上（`<p>`、`<h2>`、`<li>`、`<pre>`、`<blockquote>`…） | 不自己加一，因為多一個換算就多一個對不上的可能；捲動同步要的是「這塊 HTML 對應正文哪一行」，區塊層是唯一有這個對應的層級 |
| A-10 | 設定檔寫不進去時面板怎麼辦 | **best-effort**：畫面照開關，只是不跨重啟，且不對使用者示警 | 沿用 vault 切片對「記住上次位置」的既有裁決：寫作當下跳一個關於「明天的還原」的警告，比那個損失更糟 |
| A-11 | FR-5.12 的「一致的空狀態」是同一個元件還是同一段文字 | **同一個元件、逐字相同的文字** | 「一致」最保守的讀法。用一條「同一段文字在畫面上出現兩次」的斷言守著，任何一邊改字都會紅 |
| A-12 | 預覽要不要自己剝 front matter | **不剝** | 正文進到編輯區之前 front matter 已經被剝掉（FR-4.1，front matter 切片的職責）。在這裡再剝一次等於把同一條規則放兩個地方，而且會把使用者正文裡合法的 `---` 水平線吃掉 |
| A-13 | 面板寬度 | 沿用版面切片的 50/50，`previewPanel.widthRatio` 本切片不讀不寫 | FR-5.6 是別的切片。它接上去的時候，欄位已經在設定檔裡等著 |
| A-14 | Markdown 渲染器要不要開啟原始 HTML 的解析 | **要開** | FR-5.11 說的是「原始 HTML 一律淨化後渲染」，不是「原始 HTML 一律不渲染」。關掉它會讓使用者寫的 `<kbd>`、`<sup>` 之類的東西變成純文字 |

## 8. 已知不做、但要記錄的取捨

- **淨化不能只有一層。** 本切片放兩層獨立的網（成熟的淨化套件 + 一道自己的重新解析檢查），CSP 是第三層。第二層在正常情況下永遠不會抓到東西——那是它的目的，不是它沒用：淨化器的輸出被 HTML 解析器重新解析成另一個樣子（mXSS）正是這類漏洞的形狀，而重新解析一次就看得到。
- **語法高亮引入了一個需求文件沒有點名的依賴**（語法高亮函式庫）。FR-5.10 明文要求 fenced code 語法高亮，而 Markdown 渲染器本身通常不做高亮（只提供掛勾）。取捨與代價寫在 PR 說明。
- **「編輯區真的吃掉那塊寬度」沒有自動化測試。** 無頭測試環境沒有版面計算，欄寬在測試裡量不到。自動化守得住「收合後預覽內容不在畫面上、把手還在」，寬度那一半在實機驗證與發佈檢查清單。
- **NFR-6 的深淺色同樣量不到**：無頭測試環境不計算樣式。實機切換系統深淺色兩種模式，量實際顯示的顏色。
- **NFR-3 的 50ms 不用單元測試量。** 無頭環境的數字沒有意義，而視窗失焦時 GUI 框架可能嚴重節流計時器、整個暫停逐幀回呼——量出來的是儀器的假象（實作時須確認所選 GUI 框架的行為）。以實機量測。
