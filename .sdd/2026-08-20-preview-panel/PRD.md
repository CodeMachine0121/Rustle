# 需求規格 — 預覽面板（第四欄）

- **切片**：Wave 3，`feature/preview-panel`
- **上游文件**：[BRIEF.md](BRIEF.md)、需求文件 §4.1／§4.6／§7.3／§7.4
- **覆蓋需求 ID**：FR-5.1、FR-5.2、FR-5.3、FR-5.4、FR-5.5、FR-5.7、FR-5.10、FR-5.11、FR-5.12、NFR-6；橫切約束 FR-8.5、FR-8.7；相關非功能 NFR-2、NFR-3
- **不覆蓋**：FR-5.6（分隔線）、FR-5.8（捲動同步）、FR-5.9（圖片真的顯示）——見 BRIEF §4
- **人工回歸項目**：T-8（本切片交付後才是完整驗收）、T-1 ~ T-4／T-12（重跑時順便看候選視窗有無延遲）
- **詞彙**：一律依通用語言地圖

## 1. 目標

讓使用者在寫 Markdown 原始碼的同時看到成品，而且這件事**不以三樣東西為代價**：不以輸入法的正確性為代價（組字中不重繪）、不以 App 的安全為代價（外來 HTML 一律淨化、完全離線）、不以編輯區的寬度為代價（不想看就收起來，而且下次還記得）。

## 2. User Stories

| ID | 故事 |
| :--- | :--- |
| **US-1** | 作為寫文章的使用者，我要在打字的同時看到渲染好的成品，這樣我不用在腦內編譯 Markdown |
| **US-2** | 作為會用表格、任務清單、程式碼片段的使用者，我要這些語法在預覽裡就是它們該有的樣子 |
| **US-3** | 作為會從瀏覽器與別的編輯器貼東西進來的使用者，我要貼進來的內容**不可能**在我的 App 裡執行程式碼或連出去 |
| **US-4** | 作為用注音打字的使用者，我要在盯著候選視窗選字的時候，預覽完全不要動 |
| **US-5** | 作為需要專心的使用者，我要一個按鍵就把預覽收起來讓編輯區佔滿寬度，而且看得出來預覽還在、隨時叫得回來 |
| **US-6** | 作為每天開這個 App 的使用者，我要它記得我上次是開著還是關著預覽 |
| **US-7** | 作為還沒選文章的使用者，我要預覽面板跟編輯區說同一句話，而不是給我一塊沒有歸屬的空白 |
| **US-8** | 作為半夜寫作的使用者，我要預覽跟著系統的深色模式一起換，包括程式碼高亮 |
| **US-9** | 作為之後要接捲動同步的開發者，我要渲染輸出裡就帶著正文行號，不必回頭改渲染管線 |

## 3. 業務流程

### 3.1 一次重繪

```
編輯區的文件有變更
   → 報給「被預覽的正文」
   → 組字中？
        └─ 是 → 倒數暫停（組字結束後接著走完剩下的時間）
   → 停手 150ms
   → 公布新的正文
   → 面板收合中？
        └─ 是 → 不渲染（沒有人看得到）
   → 正文 → Markdown 解析 → 產生 HTML（區塊元素帶上正文行號、fenced code 上高亮）
   → 第一層淨化：標籤與屬性白名單、事件屬性一律移除、URL scheme 逐一檢查
   → 第二層淨化：重新解析一次淨化結果，把任何不在白名單裡的東西再剝一次
   → 放進第四欄
```

### 3.2 開啟一篇文章 / 沒有文章

```
使用者點一篇文章
   → 正文載入（front matter 已在負責檔案存取的那一層剝掉）
   → 立刻公布給預覽（不等去抖動），並取消上一篇還沒公布的待處理更新
   → 渲染

使用者切換 workspace（等於關掉當前文章）／還沒選文章
   → 沒有正文
   → 預覽面板顯示與編輯區一致的空狀態，面板裡沒有任何可輸入的元素
```

### 3.3 一次開關

```
使用者按面板標題列的關閉鈕／收合後的把手／設定的快捷鍵
   → 組字中？
        └─ 是 → 什麼都不做（這一次按鍵屬於輸入法）
   → 翻轉「面板是否可見」
   → 有讀到設定嗎？
        ├─ 有 → 把整份設定連同新的可見狀態寫回設定檔（其餘欄位一字不改）
        └─ 沒有 → 只改畫面，不寫檔（下次重啟回到預設）

App 啟動
   → 讀設定檔 → 依 previewPanel.visible 決定第四欄開或關（讀不到就開著）
```

## 4. 驗收標準（Gherkin）

「預覽」指第四欄；「正文」指編輯區手上的內容（front matter 已剝離）。

### Feature：把正文渲染成成品（FR-5.1、FR-5.10）

```gherkin
# TC-01
場景: 標題與段落
  假設 正文是 "## 取捨" 空一行 "攤開來看："
  當 預覽渲染這份正文
  那麼 預覽裡有一個第二層標題，內容是 "取捨"
  並且 有一個段落，內容是 "攤開來看："

# TC-02
場景: CommonMark 的行內語法
  假設 正文含有粗體、斜體、行內程式碼與連結
  當 預覽渲染這份正文
  那麼 粗體是 strong、斜體是 em、行內程式碼是 code、連結是 a 且 href 是原本那個相對位址

# TC-03
場景: CommonMark 的區塊語法
  假設 正文含有無序清單、有序清單、引用與水平線
  當 預覽渲染這份正文
  那麼 分別得到 ul、ol、blockquote 與 hr

# TC-04
場景: GFM 刪除線
  假設 正文是 "~~不做~~"
  當 預覽渲染這份正文
  那麼 預覽裡有一個刪除線元素（s），內容是 "不做"

# 註：HTML 有兩個表示「劃掉的文字」的元素，s 與 del。原選用的 Markdown 渲染器產生的是 s，
# 而 FR-5.10 要求的是「刪除線」這個結果，不是某一個標籤名。改寫成 del 只是把
# 上游的選擇換成我們的偏好，還多一條要維護的渲染規則，所以照它的輸出驗。
# 兩個標籤在淨化白名單裡都允許，因為使用者也可能自己貼 del 進來。

# TC-05
場景: GFM 表格
  假設 正文是一個兩欄兩列的表格
  當 預覽渲染這份正文
  那麼 預覽裡有一個 table，表頭在 thead、資料列在 tbody

# TC-06
場景: GFM 任務清單
  假設 正文是 "- [ ] 還沒做" 與 "- [x] 做完了"
  當 預覽渲染這份正文
  那麼 兩個清單項目各有一個勾選框標記
  並且 第一個是未勾選、第二個是已勾選
  並且 兩個都不是表單元素、都不能被點擊改變

# TC-07
場景: fenced code block 有語言時上語法高亮
  假設 正文是一個標了 "ts" 的 fenced code block，內容是 "const answer = 1"
  當 預覽渲染這份正文
  那麼 預覽裡有一個 pre 包著 code
  並且 那個 code 標著這個語言
  並且 內容被切成帶高亮類別的片段（不是一整塊純文字）

# TC-08
場景: fenced code block 沒有語言時原樣顯示
  假設 正文是一個沒有標語言的 fenced code block，內容是 "<b>不是粗體</b>"
  當 預覽渲染這份正文
  那麼 預覽裡有一個 pre 包著 code，文字就是 "<b>不是粗體</b>"
  並且 那不是一個真的 b 元素

# TC-09
場景: 認不出來的語言不會讓渲染失敗
  假設 正文是一個標了 "klingon" 的 fenced code block
  當 預覽渲染這份正文
  那麼 得到一個沒有高亮的 pre／code，內容原樣，沒有拋出任何錯誤

# TC-10
場景: 正文裡的 "---" 是水平線，不是 front matter
  假設 正文的第一行是 "---"，後面是一行文字
  當 預覽渲染這份正文
  那麼 預覽裡有一條水平線與那行文字
  並且 預覽沒有把任何內容當成 metadata 藏起來

# TC-11
場景: 空正文
  假設 正文是空字串
  當 預覽渲染這份正文
  那麼 預覽是空的
```

### Feature：外來 HTML 一律淨化（FR-5.11、NFR-2）

```gherkin
# TC-12
場景: script 元素連內容都不留
  假設 正文含有 "<script>window.pwned = true</script>"
  當 預覽渲染這份正文
  那麼 預覽裡沒有 script 元素
  並且 預覽裡也沒有 "window.pwned = true" 這段文字

# TC-13
場景大綱: 事件屬性一律移除
  假設 正文含有 <元素>
  當 預覽渲染這份正文
  那麼 預覽裡沒有任何以 "on" 開頭的屬性

  例子:
    | 元素 |
    | <img src="images/a.png" onerror="window.pwned = true"> |
    | <div onclick="window.pwned = true">點我</div> |
    | <p onmouseover="window.pwned = true">滑過</p> |
    | <a href="https://example.com" onfocus="window.pwned = true">連結</a> |

# TC-14
場景大綱: 危險 scheme 的連結不留 href
  假設 正文含有一個 href 是 <位址> 的連結
  當 預覽渲染這份正文
  那麼 連結的文字還在
  並且 那個連結沒有 href 屬性

  例子:
    | 位址 |
    | javascript:window.pwned = true |
    | JaVaScRiPt:alert(1) |
    | java&#9;script:alert(1) |
    | vbscript:msgbox(1) |
    | data:text/html,<script>alert(1)</script> |
    | file:///etc/passwd |
    | //evil.example/x |

# TC-15
場景: Markdown 語法寫出來的 javascript 連結一樣不留 href
  假設 正文是 "[點我](javascript:window.pwned = true)"
  當 預覽渲染這份正文
  那麼 預覽裡有 "點我" 這段文字，而且它沒有 href

# TC-16
場景大綱: 會載入外部資源或改變頁面行為的元素完全不存在
  假設 正文含有 <元素>
  當 預覽渲染這份正文
  那麼 預覽裡沒有 <標籤名> 元素

  例子:
    | 元素 | 標籤名 |
    | <iframe src="https://evil.example"></iframe> | iframe |
    | <object data="https://evil.example/x.swf"></object> | object |
    | <embed src="https://evil.example/x"> | embed |
    | <base href="https://evil.example/"> | base |
    | <meta http-equiv="refresh" content="0;url=https://evil.example"> | meta |
    | <link rel="stylesheet" href="https://evil.example/x.css"> | link |
    | <style>body{display:none}</style> | style |
    | <svg><script>window.pwned = true</script></svg> | svg |
    | <math><mtext></mtext></math> | math |

# TC-17
場景: style 屬性不存在（它足以載入外部資源）
  假設 正文含有 "<p style=\"background:url(https://evil.example/x.png)\">字</p>"
  當 預覽渲染這份正文
  那麼 那個段落還在，但沒有 style 屬性

# TC-18
場景大綱: 圖片來源只允許相對路徑與 vault 資產 scheme
  假設 正文含有一個 src 是 <來源> 的圖片
  當 預覽渲染這份正文
  那麼 圖片的 src <結果>

  例子:
    | 來源 | 結果 |
    | images/8f3c.png | 原樣保留 |
    | rustle://vault/Blog/images/8f3c.png | 原樣保留 |
    | https://evil.example/pixel.png | 不存在 |
    | http://evil.example/pixel.png | 不存在 |
    | data:image/svg+xml;base64,PHN2Zz48c2NyaXB0Pjwvc2NyaXB0Pjwvc3ZnPg== | 不存在 |
    | file:///etc/passwd | 不存在 |
    | //evil.example/pixel.png | 不存在 |

# TC-19
場景: 外部連結保留下來，因為它不是載入
  假設 正文是 "[說明](https://example.com/doc)"
  當 預覽渲染這份正文
  那麼 預覽裡有一個連結，href 是 "https://example.com/doc"

# TC-20
場景: 預覽裡沒有任何可輸入或可送出的元素
  假設 正文含有 form、input、textarea、button、select
  當 預覽渲染這份正文
  那麼 預覽裡沒有這些元素中的任何一個

# TC-21
場景: 一整份充滿惡意內容的正文，一次驗完
  假設 正文是那份惡意 Markdown 樣本（涵蓋上面每一種手法）
  當 預覽渲染這份正文
  那麼 淨化結果裡沒有 script、iframe、object、embed、base、meta、link、style、svg、form、input
  並且 沒有任何以 "on" 開頭的屬性
  並且 沒有任何 javascript:／data:／vbscript: 的 URL
  並且 沒有任何指向 http(s) 的 src

# TC-22
場景: 第二道網自己也擋得住（不依賴第一道）
  假設 一段已經含有 script、事件屬性與 javascript: 連結的 HTML 直接交給第二道檢查
  當 第二道檢查處理它
  那麼 那些元素與屬性都不在結果裡
```

### Feature：重繪是去抖動的，而且組字中不重繪（FR-5.7、FR-8.5）

```gherkin
# TC-23
場景: 打字之後 150 毫秒才重繪
  假設 預覽正在顯示某篇文章的正文
  當 編輯區的文件變成新的內容
  那麼 在 149 毫秒時預覽顯示的還是舊內容
  並且 到 150 毫秒時預覽顯示新內容

# TC-24
場景: 連續打字期間只重繪一次
  假設 預覽正在顯示某篇文章的正文
  當 使用者每 50 毫秒改動文件一次，連續五次
  那麼 期間預覽一次都沒有更新
  並且 最後一次改動之後 150 毫秒，預覽更新成最後那個內容（總共一次）

# TC-25
場景: 組字中倒數暫停
  假設 使用者改動了文件，倒數開始
  當 100 毫秒後開始組字，並在組字狀態停留 2000 毫秒
  那麼 這 2000 毫秒內預覽都沒有更新
  當 組字結束
  那麼 再過剩下的 50 毫秒預覽才更新

# TC-26
場景: 組字中改動文件也不會偷偷重繪
  假設 使用者正在組字
  當 文件在組字期間變成新的內容，並停留 2000 毫秒
  那麼 預覽沒有更新
  並且 組字結束後 150 毫秒才更新

# TC-27
場景: 開啟另一篇文章立刻顯示，且不被上一篇的待處理更新蓋掉
  假設 使用者改動了 A 篇的文件（倒數進行中）
  當 100 毫秒後開啟 B 篇文章
  那麼 預覽立刻顯示 B 篇的正文（不必等 150 毫秒）
  當 再過 500 毫秒
  那麼 預覽顯示的仍然是 B 篇的正文
```

### Feature：開關與收合（FR-5.2、FR-5.3、FR-5.4）

```gherkin
# TC-28
場景: 面板開著時是版面上的第四欄
  假設 設定說預覽面板是開著的
  當 畫面出現
  那麼 版面上有一個預覽區塊，標題是 "PREVIEW"
  並且 區塊裡有一顆關閉預覽的按鈕

# TC-29
場景: 按關閉鈕收起整個區塊
  假設 預覽面板開著，正在顯示一篇文章的內容
  當 使用者按下關閉預覽
  那麼 預覽的內容不再出現在畫面上
  並且 畫面上仍然有一顆開啟預覽的把手

# TC-30
場景: 按把手把面板叫回來
  假設 預覽面板是收合的
  當 使用者按下開啟預覽
  那麼 預覽區塊回來，並且立刻顯示當前正文的渲染結果

# TC-31
場景: 快捷鍵開關
  假設 預覽面板開著
  當 使用者按下 Mod+Shift+P
  那麼 面板收合
  當 使用者再按一次 Mod+Shift+P
  那麼 面板展開

# TC-32
場景: Cmd 與 Ctrl 都算 Mod
  假設 預覽面板開著
  當 使用者按下 Ctrl+Shift+P 或 Cmd+Shift+P
  那麼 兩者都會收合面板

# TC-33
場景: 快捷鍵可以在設定裡改
  假設 設定檔把預覽開關快捷鍵設成 "Mod+Alt+K"
  當 使用者按下 Mod+Alt+K
  那麼 面板收合
  當 使用者按下 Mod+Shift+P
  那麼 面板不動（那個組合已經不是快捷鍵了）

# TC-34
場景大綱: 設定裡的快捷鍵無法解讀時退回預設
  假設 設定檔的預覽開關快捷鍵是 <設定值>
  當 使用者按下 Mod+Shift+P
  那麼 面板收合

  例子:
    | 設定值 |
    | 空字串 |
    | "???" |
    | "Shift" |
    | "Mod+Shift+" |

# TC-35
場景: 組字中的快捷鍵屬於輸入法
  假設 預覽面板開著，而使用者正在組字
  當 使用者按下 Mod+Shift+P
  那麼 面板不動
  當 組字結束後再按一次
  那麼 面板收合

# TC-36
場景: 只有真正的組合鍵有效
  假設 預覽面板開著
  當 使用者按下 Shift+P（沒有 Mod）或 Mod+P（沒有 Shift）
  那麼 面板不動
```

### Feature：開關狀態跨重啟保留（FR-5.5）

```gherkin
# TC-37
場景: 收起面板會寫回設定檔
  假設 設定檔說面板是開著的，縮排是 4 個空白，並記著上次開啟的位置
  當 使用者收起面板
  那麼 設定被寫回，其中預覽面板的可見狀態是關
  並且 縮排設定與上次開啟的位置一字不改

# TC-38
場景: 重新啟動後照設定檔還原
  假設 設定檔說預覽面板的可見狀態是關
  當 畫面出現
  那麼 面板是收合的，畫面上只有那顆開啟預覽的把手

# TC-39
場景: 設定讀不出來時面板照樣可用
  假設 讀設定的通道失敗
  當 畫面出現
  那麼 面板是開著的（預設）
  當 使用者按下關閉預覽
  那麼 面板收合，而且沒有任何寫設定的請求送出

# TC-40
```
