# 寫作區與預覽區各自的字體大小 — Product Requirements Document

**Status:** Draft
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** 寫作者本人（唯一使用者）

---

## 1. Background & Goal

### Problem Statement

寫作區與預覽區的字體大小是**寫死的**：寫作區 `14.5px`、預覽區約 `14.9px`。寫作者沒有任何辦法改。

一個人整天看著這兩塊，而字要多大只有他自己知道——螢幕、距離、眼睛、當天的精神狀態都不一樣。而且「兩邊該一樣大」這個假設本來就不成立：寫作區是等寬字體的原始碼，預覽區是排好的文章，同一個數字在兩邊看起來不一樣大。

還有一個藏著的問題：預覽區的標題大小是相對**整個視窗的基準字體**算的，不是相對它們所在的那一段文章。所以就算把預覽的基準字體調大，標題也會留在原地——調出一篇標題比內文小的文章。

### Expected Outcome

- 寫作者能用手邊的裝置各自調整兩塊的字體大小：滑鼠按著 Cmd／Ctrl 滾滾輪，觸控板用平常那個放大縮小的手勢。
- **收放是絲滑的**：手指在動的時候字就在動，不會等一段才跳一格。
- 兩種裝置走完同樣距離會到差不多的大小；往回做一次剛好回到原點。
- 調過的大小跨重啟記住。
- 預覽區放大時，標題、程式碼、引言、表格**全部等比例跟著大**。
- 縮放**絕不弄丟**寫作者打到一半的東西。

### Out of Scope

- 側欄、文章清單、對話框、按鈕、狀態列的字體大小——它們是介面，不是內容。
- 從設定畫面用數字輸入字體大小。這一版只有手勢與放回預設。
- 整個 App 的等比例縮放——作業系統與 App 外殼自己就有。
- 換字型。只調大小。
- 每篇文章各自記自己的字體大小——這是寫作者的偏好，不是文章的屬性。
- 行高、字距、欄寬。行高本來就是字體大小的倍數，會自己跟著走。

## 2. User Personas

- **Primary Role:** 寫作者（本專案唯一的角色，也是唯一的使用者）。
- **Usage Context:** macOS 桌面上的本機 App。滑鼠與觸控板都可能是當下手邊的裝置，而且會換。中文輸入為主，所以任何動作都不能打斷正在選的字。整天開著，字體大小是調一次用很久的偏好。

## 3. User Stories & Acceptance Criteria

### US-01 — 手勢作用在指標所在的那一塊上，兩塊各自獨立 [priority: P0]

**As a** 寫作者，**I want** 調整我此刻正在看的那一塊的字體大小，**so that** 我不用先選中誰，也不會誤調另一塊。

```gherkin
Scenario: 放大寫作區
  Given 寫作區與預覽區都是預設字體大小
  When 寫作者把指標放在寫作區上並做放大手勢
  Then 寫作區的字體大小變大一級
  And 預覽區的字體大小完全沒變

Scenario: 放大預覽區
  Given 寫作區與預覽區都是預設字體大小
  When 寫作者把指標放在預覽區上並做放大手勢
  Then 預覽區的字體大小變大一級
  And 寫作區的字體大小完全沒變

Scenario: 兩塊各自記著自己的大小
  Given 寫作區已經被放大三級
  When 寫作者把指標放在預覽區上並做縮小手勢
  Then 預覽區縮小一級
  And 寫作區仍然是放大三級的大小

Scenario: 手勢落在別的欄位上
  Given 寫作區與預覽區都是預設字體大小
  When 寫作者把指標放在側欄或文章清單上並做放大手勢
  Then 兩塊的字體大小都沒變
  And 整個畫面也沒有跟著放大
```

### US-02 — 滑鼠與觸控板走同一條路，快慢相當 [priority: P0]

**As a** 寫作者，**I want** 不管手邊是滑鼠還是觸控板都能調，**so that** 我換裝置時不用改習慣。

```gherkin
Scenario: 滑鼠滾一格
  Given 指標在寫作區上
  When 寫作者按著 Cmd 往上滾一格滾輪
  Then 寫作區的字明顯變大了一點

Scenario: 觸控板捏一次
  Given 指標在寫作區上
  When 寫作者在觸控板上做一次捏開的手勢
  Then 寫作區的字在手指移動的過程中一路變大，沒有停頓也沒有跳格
  And 走完同樣距離的一格滑鼠與一次捏合，到達差不多的大小

Scenario: 往回做一次就回到原點
  Given 指標在寫作區上
  And 字體大小離最大與最小都還有距離
  When 寫作者做一次放大手勢，再做一次同樣距離的縮小手勢
  Then 字體大小回到原本的大小

Scenario: 頂到邊界之後往回做
  Given 寫作區的字體大小已經被推到最大
  When 寫作者繼續做放大手勢，再做同樣距離的縮小手勢
  Then 字體大小不會回到推之前的大小——推在最大值上的那段行程就是花掉了
  And 那與這台機器上其他縮放的行為一致：字停住了，寫作者就會停手

Scenario: 沒按 Cmd 或 Ctrl 就滾滾輪
  Given 指標在寫作區上
  When 寫作者不按任何鍵就滾滾輪
  Then 字體大小完全沒變
  And 寫作區照常上下捲動

Scenario: 整個畫面不跟著縮放
  Given 指標在寫作區上
  When 寫作者做放大手勢
  Then 只有寫作區的字變大
  And 側欄、按鈕、欄位寬度都與手勢前一模一樣
```

### US-03 — 上限與下限，而且只有一個地方在管 [priority: P0]

**As a** 寫作者，**I want** 字不會被調到看不見或大到只剩一個字，**so that** 一次滾過頭不會把畫面弄壞。

```gherkin
Scenario: 已經最小還繼續縮
  Given 寫作區已經在最小的字體大小
  When 寫作者做縮小手勢
  Then 字體大小仍然是最小
  And 沒有繞回最大

Scenario: 已經最大還繼續放
  Given 寫作區已經在最大的字體大小
  When 寫作者做放大手勢
  Then 字體大小仍然是最大

Scenario: 設定檔裡手寫了一個荒謬的大數字
  Given 設定檔裡的寫作區字體大小遠大於允許的最大值
  When 寫作者打開 App
  Then 寫作區開在最大值
  And 那與「從預設一路放到底」的結果完全相同

Scenario: 設定檔裡手寫的不是數字
  Given 設定檔裡的寫作區字體大小是一段文字
  When 寫作者打開 App
  Then 寫作區開在預設字體大小
```

### US-04 — 放回預設值 [priority: P1]

**As a** 寫作者，**I want** 一個把字體大小放回原點的動作，**so that** 我調過頭時不必憑感覺一格一格滾回來。

```gherkin
Scenario: 放回預設
  Given 寫作區被放大五級
  When 寫作者把指標放在寫作區上並按 Cmd 加 0
  Then 寫作區回到預設字體大小

Scenario: 只放回指標所在的那一塊
  Given 寫作區被放大兩級，預覽區被縮小一級
  When 寫作者把指標放在預覽區上並按 Cmd 加 0
  Then 預覽區回到預設字體大小
  And 寫作區仍然是放大兩級的大小

Scenario: 已經是預設值
  Given 寫作區已經是預設字體大小
  When 寫作者按 Cmd 加 0
  Then 什麼都沒變

Scenario: 組字中的那一次按鍵屬於輸入法
  Given 寫作者正在用輸入法選字
  And 寫作區被放大三級
  When 寫作者按 Cmd 加 0
  Then 字體大小仍然是放大三級
  And 那一次按鍵留給輸入法
```

### US-05 — 記住，但永遠不擋住畫面 [priority: P0]

**As a** 寫作者，**I want** 調好的大小下次打開還在，**so that** 我不用每天重新調一次。

```gherkin
Scenario: 跨重啟記住
  Given 寫作區被放大兩級
  When 寫作者關掉 App 再打開
  Then 寫作區還是放大兩級的大小

Scenario: 兩塊各自被記住
  Given 預覽區被縮小一級，寫作區沒有被調過
  When 寫作者關掉 App 再打開
  Then 預覽區還是縮小一級
  And 寫作區是預設字體大小

Scenario: 設定檔完全讀不到
  Given 設定檔讀不到
  When 寫作者打開 App 並放大寫作區
  Then 兩塊都開在預設字體大小
  And 放大照樣生效
  And 那個大小活不過下一次重啟

Scenario: 設定檔寫不進去
  Given 設定檔寫不進去
  When 寫作者放大寫作區
  Then 寫作區的字就是變大了

Scenario: 不順手改掉別的偏好
  Given 分隔線被拖到某個位置，預覽是開著的，上次開的是某一篇文章
  When 寫作者只調了預覽區的字體大小
  Then 設定檔裡的分隔線位置、預覽開關、上次開的文章都沒有被改動
```

### US-06 — 預覽區放大時整篇一起大 [priority: P0]

**As a** 寫作者，**I want** 放大預覽時整篇文章等比例變大，**so that** 標題還是標題，而不是變得比內文小。

```gherkin
Scenario: 標題跟著基準字體走
  Given 預覽區裡有一級標題、二級標題與內文
  When 寫作者把預覽區放大三級
  Then 三者都等比例變大
  And 一級標題仍然明顯大於二級標題，二級標題仍然明顯大於內文

Scenario: 引言、程式碼與表格也跟著
  Given 預覽區裡有一段引言、一個程式碼區塊與一個表格
  When 寫作者放大預覽區
  Then 三者的字都跟著變大
  And 沒有任何一塊留在原本的大小

Scenario: 只有預覽區
  Given 預覽區被放大
  When 寫作者看側欄與文章清單
  Then 它們的字體大小完全沒變
```

### US-07 — 縮放不能弄壞寫作區 [priority: P0]

**As a** 寫作者，**I want** 縮放的時候我打的東西一個字都不會掉，**so that** 我可以隨時調大小而不必先存檔。

```gherkin
Scenario: 打到一半的東西不受影響
  Given 寫作者剛打了一段還沒存進檔案的字
  And 游標停在那段字的中間
  When 寫作者把寫作區放大三級
  Then 那段字一個字都沒少
  And 游標還在原來的位置
  And 復原可以一路退回這段字之前的內容

Scenario: 字變大之後游標與捲動仍然對得上
  Given 寫作區被放大到很大
  When 寫作者看游標與捲動位置
  Then 游標畫在它該在的位置
  And 捲動的位置與內容對得上，沒有錯位

Scenario: 兩邊字體大小不同時捲動同步照舊
  Given 並排，而且寫作區與預覽區的字體大小不同
  When 寫作者捲動其中一邊
  Then 另一邊仍然跟到對應的那一行

Scenario: 組字中的手勢不屬於輸入法
  Given 寫作者正在用輸入法選字
  When 寫作者用觸控板做放大手勢
  Then 字體大小變大
  And 正在選的那一段字沒有被打斷或吃掉
```

## 4. Business Flow & Logic

### 主要流程

1. 寫作者把指標移到想調的那一塊上。
2. 按著 Cmd／Ctrl 滾滾輪，或在觸控板上捏開／捏合。
3. 那一塊的字體大小一級一級變，夾在最小與最大之間。
4. 停手之後，那個大小被寫進設定檔；下次打開還是它。
5. 調過頭了就按 Cmd／Ctrl 加 `0`，那一塊回到預設。

### 核心規則

- **兩個大小，兩個獨立的值。** 寫作區一個、預覽區一個，互不影響。
- **手勢屬於指標所在的那一塊。** 落在別處就什麼都不做——包含不讓整個畫面縮放。
- **預設值 15px，範圍 10px 到 28px。** 兩塊共用同一組。15 而不是現在的 14.5／14.88，差半個像素看不出來。
- **夾住的規則只有一個地方在管。** 手勢調到的值、設定檔讀進來的值、放回預設，全部走同一條。手改設定檔寫 999 的結果，與一路放到底完全相同。
- **手勢要求的是「多少比例」，不是「變成幾像素」。** 一次手勢的好幾個事件會在畫面重畫之前全部到達，所以要求一個大小的一方會拿同一個舊數字算三次，只動一次。要求比例的一方不必知道現在多大，而持有大小的一方永遠知道，所以幾個事件會**相乘疊加**。
- **每一個事件都要求一點東西，不管多小。** 這是「絲滑」的實作形式：手指在動的時候字就在動。等一段才動一次就是棘輪。
- **一個滾動單位對應一個固定比例**，而那個比例是**為觸控板選的**：一次捏合大約多四分之一。更輕的設定（一次捏合約多十分之一）看得到變化，但摸起來不像字跟著手指走。觸控板送出幾十個小量，同一個算式把它們變成幾十個小變化。**不看裝置，只看比例**：這是「不用為兩種裝置分開寫」的實作形式，而且一格滑鼠與一次捏合走完同樣的距離就要到同樣的地方。
- **滑鼠因此是粗的：一格約多三分之二，整個範圍只隔兩格多。** 這是取捨而不是疏漏——同一個算式服務兩種裝置（那正是這裡不偵測裝置的理由），而要天天用它的人選了觸控板。
- **往回做一次剛好回到原點**——只要沒有頂到邊界。比例的反比是精確的，而且**手勢進行中不做任何捨入**：一個小到不足十分之一像素的請求仍然是一個請求。捨入只發生在寫進設定檔的時候。
- **頂在邊界上的那段行程是花掉的。** 記住它可以讓往回走精確回到原點，代價是一個寫作者看不見的死區——而看不見的死區是這個設計最不該有的東西。字停住了，寫作者就會停手，這台機器上其他的縮放也是這樣。
- **字體大小精細到十分之一像素。** 整整一個像素在十五像素上是七個百分點，那會被眼睛讀成一階；十分之一是半個百分點，讀不出來，而且仍是設定檔放得下的數字。
- **放回預設用寫死的 `Cmd/Ctrl+0`。** 不做成可設定：「重設縮放」有全世界通用的按鍵，而預覽的開關沒有——那個之所以可設定，正因為沒有通用做法。
- **預覽區整篇等比例。** 標題、程式碼、引言、表格的大小一律相對**它們所在的那段文章**，不是相對整個視窗。
- **寫檔是為了活過重啟，不是為了生效。** 畫面先變，檔案後寫；寫不進去不影響這一次。
- **縮放不重建寫作區。** 字體大小不經過建立編輯器的那條路。
- **縮放後寫作區要重新量測自己。** 行高變了，不重新量測游標與捲動就會錯位。

### 為什麼有兩種設定大小的方式

「多少比例」是手勢用的（見上一節）。「變成幾像素」是設定檔讀進來時、以及日後從設定畫面用數字輸入時用的——那些場合說得出確切的數字，而且不會在同一個瞬間連續發生好幾次。兩者都走同一條夾住規則。

### 邊界與例外

- **已在最小還縮、已在最大還放**：什麼都不發生，不繞回另一端。
- **設定檔的值不是數字、或超出範圍**：不是數字用預設，超出範圍夾到那一端。
- **設定檔讀不到**：兩塊都用預設開，照樣可以調，只是活不過重啟。
- **設定檔寫不進去**：畫面上該多大就是多大。
- **沒按 Cmd／Ctrl 滾滾輪**：那是普通捲動，字體大小不動。
- **組字中**：捏合手勢照樣作用（手勢不可能屬於輸入法）；`Cmd/Ctrl+0` 讓開（按鍵可能屬於輸入法）。
- **只有預覽或只有編輯的排法**：不在畫面上的那一塊收不到手勢，也不需要——它的大小仍然被記著，回來時就是那個大小。

## 5. UI/UX Design & Interaction

### Prototype Link

無設計稿。這一節的文字即規格。

### 關鍵互動

- **沒有任何新的畫面元素。** 沒有按鈕、沒有滑桿、沒有數字。這個功能的整個介面就是手勢本身。
- **回饋是即時的字體大小本身。** 不顯示「16px」這種提示：寫作者要的是字看起來對，不是一個數字。
- **在最小或最大時沒有任何提示。** 字就是不再變，那已經足夠說明。
- **游標形狀不變**，指標不因為按著 Cmd 而改變外觀。

### 版面

- 寫作區與預覽區各自的字體大小是它們**自己那一塊**的事，兩塊之外的一切（欄寬、側欄、按鈕、狀態列、對話框）完全不受影響。
- 預覽區內所有相對大小（標題、程式碼、引言）都相對它所在的文章，所以放大是整篇一起放大。

## 6. Non-Functional Requirements

- **輸入法（IME）**：縮放不得重建寫作區。捏合手勢在組字期間照樣作用；`Cmd/Ctrl+0` 在組字期間讓開。
- **不弄丟東西**：縮放前後，寫作區的內容、游標位置、復原歷史三者都必須完好。
- **反應速度**：縮放是本機的重排，寫作者不應感覺到延遲。連續的手勢不得每一步都寫檔——一次手勢一次寫檔。
- **正確性**：縮放後游標與捲動不得錯位。
- **相容性**：macOS 桌面。滑鼠與觸控板兩種裝置都要能用。
- **分析追蹤**：N/A。

## 7. Dependencies & Risks

### External Dependencies

- **設定檔的形狀要多兩個數字。** 那是專案文件列為「需要調整形狀的切片可以改、但要在 PR 說明」的那一類。
- 沒有新的檔案操作、沒有新的第三方套件。

### Known Risks

| 風險 | 說明 |
| :--- | :--- |
| **縮放可能重建寫作區** | 這一切片最大的風險，跟上一個切片同一個形狀。字體大小若經過建立編輯器的那條路，每一級都會重建一次編輯器——復原歷史、組字中的字、上次存檔後打的每個字全丟。US-07 就是為它寫的。 |
| **畫面整體被縮放** | 所用的 GUI 層或系統若預設會把 Cmd+滾輪與捏合手勢當成「縮放整個畫面」，必須明確擋下；否則寫作者會看到側欄、按鈕、欄寬一起變——那是另一件事，而且會蓋掉這個功能。 |
| **行高變了但沒重新量測** | 寫作區的游標位置與捲動是量測出來的。字體大小變了而沒有要求重新量測，游標會畫在錯的地方。 |
| **兩種裝置的快慢差太多** | 若直接用滾動量當像素數，滑鼠一格會跳一大截、觸控板幾乎不動。「一個滾動單位對應一個固定比例」是為了這件事：兩種裝置只差在量的大小與頻率。 |
| **連續手勢把設定檔寫爛** | 一次捏合會送出幾十個事件。每一個都寫檔就是幾十次整份設定檔覆寫。 |
| **兩層對「多精細」的答案不一致** | 已經發生過一次：常數共用了，算術各寫一份，於是負責寫設定檔的那一層捨到整數像素而畫面留到十分之一——寫作者捏到 17.3，隔天拿回 17。共用的必須是**規則**，不只是數字。 |
| **預覽區的標題留在原地** | 已知且已寫成需求：那些大小現在相對整個視窗，必須改成相對它所在的文章。 |
