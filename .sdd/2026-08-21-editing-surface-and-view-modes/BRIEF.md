# 寫作介面整理與檢視模式 — Requirements Brief

## Goal

把 Rustle 的畫面從「什麼都用文字寫出來」整理成「該用圖示的地方用圖示、該安靜的地方安靜」。

文章卡片上要看得到「這篇進行到哪了」，卡片上能做的兩件事（改 metadata、刪掉）改成右上角與右下角的圖示；清單上方那一列不再提供排序，只留一個漏斗形狀的篩選框與一個新文章圖示。新增 workspace 從「常駐在側欄底下的輸入框」改成「按圖示、跳視窗填名字」。

畫面最上方那條儲存狀態搬到寫作區的最下面，長成一條 statusline：左邊是 `workspace ❯ 檔名` 的箭頭麵包屑，右邊只有一個圖示——正在存就轉圈，存好了就是綠色勾勾，一個字都不寫。

寫作區本身的字體與配色改成 Xcode 那種風格。最後，寫作區的標題那一條左邊放一顆 Zen 按鈕（按下去把左邊兩欄藏起來，只留寫作的地方），右邊放三顆檢視模式按鈕：只有編輯、編輯與預覽並排、只有預覽——取代現在那個藏在最右邊的長條鈕與預覽標題上的叉叉。

目的只有一個：讓寫作者眼睛落在文章上，而不是落在一堆說明文字與按鈕上。

## Requirements

### 文章卡片

- 文章卡片上要看得到這篇文章的**狀態**，跟日期、標籤同一行、同一種形式。
- 那一行**一律靠左緊貼**，不居中。
- 狀態排在那一行的**最前面**，接著才是日期與標籤。
- 沒有狀態的文章也要寫出來，寫「No Status」——側欄有五種說法，卡片上就有五種說法。
- 「metadata 不完整」與「開著的」這兩個標記照舊出現在那一行的尾端。
- 卡片**右上角**是改 metadata，用一支鉛筆的圖示。
- 卡片**右下角**是刪掉，用一個垃圾桶的圖示。
- 兩個圖示平常安靜，滑鼠移到卡片上才明顯；但用鍵盤走也要走得到，不必先把滑鼠移過去。
- 按鉛筆開的是原本那個 metadata 編輯視窗；按垃圾桶跳的是原本那個刪除確認，內容一字不改。

### 文章清單上方那一列

- **排序整個拿掉**。不再有排序選單，寫作者不能改順序。
- 清單固定**最新建立在最前面**。
- 篩選框裡放一個**漏斗**圖示，提示字改成 `filter`。原本的放大鏡與「篩選…」字樣都拿掉。
- 篩選框旁邊放一個**新文章**圖示（一張紙加一支鉛筆）。原本清單底下那顆文字按鈕拿掉。
- 這一列**一直都在**，就算目前範圍裡一篇文章都沒有。
- 目前範圍裡沒有文章時，底下照舊另外顯示「建立第一篇文章」。
- 在 All Notes 底下按新文章圖示，照舊被擋下並說明原因，不會讓人白填一次表單。

### 新增 workspace

- 側欄裡**常駐的名稱輸入框拿掉**，換成一個新增圖示。
- 按下圖示才跳出視窗，視窗裡有名稱欄位、建立、取消。
- 名字沒人用過就建立成功、視窗關閉。
- 名字被退回時視窗留著不關，裡面說明原因，名字留在欄位裡讓人改。
- 取消或關閉時把填到一半的名字丟掉，下次打開是空白的。

### 儲存狀態列

- 畫面最上方那條**整個拿掉**。
- 寫作區的最下面放一條 statusline：
  - 左邊：`workspace ❯ 檔名`，用箭頭分隔，寫的是檔名而不是文章標題。
  - 右邊：一個圖示，**不寫任何字**。
- 正在存的時候顯示轉圈的動畫。從寫作者打完字那一刻起就開始轉，一路轉到真的存完。
- 存完之後換成一個綠色勾勾，**一直留著**，不會自己消失。
- 「已儲存」這三個字不再出現在畫面上。
- 沒有打開任何文章時，這條什麼都不顯示。
- 儲存失敗的訊息，以及「這個檔案在 Rustle 之外被改動過」加上覆寫／重新載入兩個選擇，都長在**同一條**上。

### 寫作區的字體與配色

- 寫作區改成 Xcode 那種風格：等寬字體，加上 Xcode 的語法配色。
- 淺色與深色各有一套，跟著系統走，跟現在一樣。
- 側欄、文章清單、預覽區**都不變**。
- 沒有語法的純散文照舊是普通正文的顏色，不被上色。

### 檢視模式

- 寫作區的標題那一條，**最右邊**放三顆圖示按鈕：只有編輯、編輯與預覽並排、只有預覽。
- 目前是哪一種，那一顆要標出來。
- 選「只有預覽」時寫作區整個不見，這三顆按鈕跟著搬到預覽區的標題那一條。
- 現在最右邊那個長條的「預覽」按鈕，以及預覽標題上的叉叉，**都拿掉**。
- 預覽的鍵盤快速鍵**留著**，切換的是「並排」與「只有編輯」。
- 並排時分隔線拖到哪裡要記住：切走再切回來，分隔線回到原本的位置。

### Zen Mode

- 寫作區的標題那一條，**最左邊**放一顆兩個斜對角箭頭的圖示。
- 按下去把側欄（All Notes、Workspaces、狀態、標籤）與文章清單**整個藏起來**，只留寫作的地方，佔滿整個視窗。
- 圖示這時改成向內收的樣子；**再按同一顆就回到正常畫面**。
- Zen Mode 開著時，三顆檢視模式按鈕**照舊能用**：可以只有編輯、可以並排、也可以只有預覽。
- 在 Zen Mode 裡按 Esc，照舊只是把鍵盤交出編輯器，**不會**退出 Zen Mode。
- Zen Mode **不記住**：關掉 App 再打開，回到正常畫面。

### 圖示的樣子

- 畫面上所有圖示一律**單色細線條**，跟旁邊的文字同一個色系。
- 不使用彩色 emoji。現在畫面上的 🔍 與 `＋` 全部換掉，改版後畫面上不留任何 emoji。
- 唯一有顏色的是那個綠色勾勾——它就是在報「好了」——但它同樣是線條圖示，不是 emoji。

## Out of Scope

- 檔案怎麼讀怎麼寫、front matter 怎麼解析——一行都不動。
- 自動儲存的時機邏輯（多久存一次、輸入法組字時暫停）——不動，這次只改它怎麼被看見。
- 預覽怎麼把 Markdown 變成畫面、貼圖進 workspace——不動。
- 文章的狀態有哪四個、怎麼選、側欄怎麼過濾——上一個切片已經定案，這次只是把狀態畫到卡片上。
- 排序這個功能本身——這次是拿掉，不是改進；日後要回來是另一個切片。
- 讓寫作者自己挑寫作區的字體或配色——這次只給 Xcode 那一種。

## Open Decisions

Items the PRD author should resolve:

- 線條圖示從哪裡來：先找現成的圖示集，找不到合用的才自己畫。這是技術選擇，留給 `/architecture`。
- 麵包屑太長時怎麼收（workspace 名字很長、檔名很長）：從中間省略、還是只省檔名以外的部分。
- 綠色勾勾用哪一個綠：沿用畫面上既有的顏色，還是為它另外定一個。
- Zen Mode 藏起來的兩欄，回來時要不要保留原本的寬度（現在寬度是固定的，這條可能自動成立）。
- Xcode 那套配色的具體顏色值要對到 Markdown 的哪些語法（標題、粗體、連結、引用、程式碼、Markdown 自己的符號）。

## Context / Background

- 寫作者原本以為畫面最上方寫的「Articles」是一個固定的字，其實那是當時打開的那篇文章的標題。搬到底部之後改寫 `workspace ❯ 檔名`，就不會再有這個誤會。
- 「已儲存」這三個字原本打算「過幾秒自動消失」，討論後決定**根本不要這三個字**：一個綠勾已經把事情說完了。
- 麵包屑的樣子是照著終端機 statusline 那種箭頭分隔的做法來的。
- 三顆檢視模式按鈕原本打算放在寫作區標題的旁邊，後來確定放**最右邊**，最左邊留給 Zen。
- 排序原本打算改成一顆三條橫線的圖示，再討論後決定**整個拿掉**，那個位置讓給漏斗形狀的篩選框。
- Zen Mode 的離開方式刻意**不用 Esc**：Esc 在寫作區裡本來就是「把鍵盤交出去」的鍵，兩件事共用一個鍵會互相搶。
- Zen Mode 刻意**不記住**：打開 App 卻發現側欄與文章清單都不見了，會像東西壞掉。預覽開不開有記住，那是因為它不會讓人找不到自己的文章。
