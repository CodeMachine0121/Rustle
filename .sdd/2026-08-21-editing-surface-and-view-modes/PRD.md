# 寫作介面整理與檢視模式 — Product Requirements Document

**Status:** Implemented
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** 寫作者本人（唯一使用者）

---

## 1. Background & Goal

### Problem Statement

Rustle 目前把每一件事都用文字寫在畫面上，結果寫作者的眼睛落在按鈕與說明文字上，而不是落在文章上：

- 文章卡片上看不到「這篇進行到哪了」，那件事只在側欄與 metadata 表單裡才問得到；而卡片上能做的兩件事（改 metadata、刪掉）是兩顆文字按鈕，佔掉卡片一整行。
- 清單上方擺著一個排序選單，但寫作者從來沒有真的想改順序；篩選框裡塞著一個放大鏡與「篩選…」三個字。
- 新增 workspace 的名稱欄位**常駐**在側欄底下，不管有沒有要新增都佔著位置。
- 畫面最上方那條寫著「〈文章標題〉 已儲存」。寫作者把當時打開那篇文章的標題誤認成一個固定的字，也就是說那條沒有成功說出「我正在寫哪個檔案」。
- 想收起預覽得把滑鼠移到預覽區的標題上點叉叉；想打開預覽得去畫面最右邊按一條窄長的按鈕。兩個入口都藏得很深，而且長得不像同一件事的兩面。
- 沒有任何辦法把左邊兩欄暫時收掉、專心寫一篇文章。

### Expected Outcome

這是個人自用的寫作工具，成功與否沒有數字可量，判準是可觀察的結果：

- 寫文章的時候，畫面上與「這篇文章」無關的文字明顯變少：清單卡片上的兩顆文字按鈕、排序選單、常駐的名稱欄位、標題列上的「已儲存」全部不再出現。
- 「我正在寫哪個檔案、有沒有落地」在寫作區的最下面一眼看得到，而且不會再被誤讀成別的東西。
- 切換三種排法（只有編輯／並排／只有預覽）與進出 Zen Mode，都在同一條上、同一組按鈕、一次點擊之內。
- 切換這些排法的時候，**寫到一半的東西一個字都不會掉**，游標與復原歷史都還在。

### Out of Scope

- 檔案怎麼讀怎麼寫、front matter 怎麼解析——一行都不動。
- 自動儲存的時機規則（停手多久才寫、組字中不寫、切換文章前先寫）——不動；這次只改它怎麼被看見。
- 預覽怎麼把正文變成畫面、貼上圖片、捲動同步——不動。
- 文章的狀態有哪四個、怎麼選、側欄怎麼過濾——上一個切片已定案，這次只是把狀態畫到卡片上。
- 排序這個功能本身——這次是拿掉，不是改進。日後要做回來是另一個切片。
- 讓寫作者自己挑寫作區的字體或配色——這次只給 Xcode 那一種。
- 全文搜尋——篩選框的比對範圍不變。

## 2. User Personas

- **Primary Role:** 寫作者（本專案唯一的角色，也是唯一的使用者）。
- **Usage Context:** macOS 桌面上的本機 App，離線可用。整天開著，一次專注寫一篇文章，中間穿插在多個 workspace 之間找舊文章。中文輸入為主，所以組字期間畫面不可以在游標旁邊亂動。滑鼠與鍵盤都用；寫作區吃掉 Tab，所以離開寫作區的路徑是先按 `Esc` 再按 `Tab`。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 卡片上看得到狀態，metadata 一律靠左 [priority: P0]

**As a** 寫作者，**I want** 在文章清單上直接看到每篇文章進行到哪了，而且那一行資訊靠左讀得順，**so that** 我不必逐篇打開或靠側欄過濾才知道哪幾篇還沒寫完。

```gherkin
Scenario: 有狀態、有日期、有標籤的文章
  Given 一篇文章的狀態是 Active、建立日期是 2026-08-21、標籤是 #go 與 #api
  When 寫作者看文章清單
  Then 這張卡片的第二行從左邊起依序顯示 Active、2026-08-21、#go、#api
  And 這一行貼著卡片的左邊緣，不居中

Scenario: 沒有狀態的文章
  Given 一篇文章沒有狀態
  When 寫作者看文章清單
  Then 這張卡片第二行的最左邊顯示「No Status」
  And 後面接著它的日期與標籤

Scenario: 只有狀態可說的文章
  Given 一篇文章沒有標籤、也沒有建立日期
  When 寫作者看文章清單
  Then 這張卡片第二行只有狀態一項
  And 這一項仍然貼著卡片的左邊緣

Scenario: 狀態與既有標記同時出現
  Given 一篇文章的 metadata 不完整
  And 這篇文章正在寫作區裡被寫
  And 篩選框裡的字對不上這篇文章
  When 寫作者看文章清單
  Then 狀態仍然在第二行的最前面
  And 「metadata 不完整」與「開著的」兩個標記出現在同一行的尾端
```

### US-02 — 卡片上的兩件事變成右上角與右下角的圖示 [priority: P0]

**As a** 寫作者，**I want** 改 metadata 與刪掉這兩件事以圖示待在卡片的角落，**so that** 卡片上留給文章本身的空間變多，而且不會誤按。

```gherkin
Scenario: 圖示在卡片的兩個角落
  Given 文章清單上有一篇文章
  When 寫作者把滑鼠移到那張卡片上
  Then 卡片右上角出現一支鉛筆的圖示
  And 卡片右下角出現一個垃圾桶的圖示

Scenario: 按右上角改 metadata
  Given 文章清單上有一篇文章
  When 寫作者按那張卡片右上角的鉛筆圖示
  Then 跳出這一篇的 metadata 編輯視窗

Scenario: 按右下角刪掉
  Given 文章清單上有一篇文章
  When 寫作者按那張卡片右下角的垃圾桶圖示
  Then 跳出刪除確認，說明這篇會移到系統垃圾桶、而它用到的圖片一張都不會被刪除

Scenario: 只用鍵盤也走得到那兩個圖示
  Given 滑鼠不在任何一張卡片上
  When 寫作者用鍵盤依序走過文章清單
  Then 那張卡片的鉛筆與垃圾桶圖示都停得下來
  And 不需要先把滑鼠移過去
```

### US-03 — 清單上方只留漏斗篩選框與新文章圖示，排序退場 [priority: P0]

**As a** 寫作者，**I want** 清單上方只有「縮小範圍」與「開新的一篇」這兩件事，**so that** 我不用在一個從來不改的排序選單旁邊找新文章按鈕。

```gherkin
Scenario: 清單上方那一列的內容
  Given 目前這個 workspace 裡有 5 篇文章
  When 寫作者看文章清單的上方
  Then 只有一列：一個帶漏斗圖示、提示字為「filter」的篩選框，以及一個新文章圖示
  And 畫面上沒有排序選單
  And 篩選框裡沒有放大鏡，也沒有「篩選…」這幾個字

Scenario: 清單的順序固定
  Given 目前這個 workspace 裡有 5 篇文章
  When 寫作者看清單的順序
  Then 建立時間最新的排在最前面
  And 沒有任何辦法可以改成別的順序

Scenario: 範圍裡一篇文章都沒有
  Given 目前這個 workspace 裡沒有任何文章
  When 寫作者看文章清單
  Then 上方那一列照樣顯示，位置與有文章時相同
  And 下面另外顯示「建立第一篇文章」的引導
  And 那段引導沒有自己的按鈕——上方那個圖示就是入口

Scenario: 在 All Notes 之下按新文章
  Given 寫作者目前看的是 All Notes
  When 寫作者按新文章圖示
  Then 這個動作被擋下，並說明必須先選一個 workspace
  And 沒有任何表單被打開
  And 沒有任何檔案被建立
```

### US-04 — 新增 workspace 改成先按圖示、再跳視窗填名字 [priority: P0]

**As a** 寫作者，**I want** 側欄不要常駐一個我大部分時間都不用的名稱欄位，**so that** 側欄留給 workspace 清單本身。

```gherkin
Scenario: 側欄不再常駐名稱欄位
  Given 寫作者看側欄的 Workspace 區
  When 這一區展開著
  Then 沒有常駐的名稱輸入欄位
  And 只有一個新增圖示

Scenario: 按圖示才跳視窗
  Given 寫作者在側欄的 Workspace 區
  When 寫作者按新增圖示
  Then 跳出一個視窗，裡面有名稱欄位、建立、取消

Scenario: 填一個沒人用過的名字
  Given 新增 workspace 的視窗開著
  And 寫作者填的名字目前沒有任何 workspace 在用
  When 寫作者送出
  Then 這個 workspace 被建立
  And 視窗關閉

Scenario: 填一個已經存在的名字
  Given 新增 workspace 的視窗開著
  And 寫作者填的名字已經有 workspace 在用
  When 寫作者送出
  Then 視窗留著不關
  And 視窗裡顯示這個名字為什麼被擋下
  And 剛才填的名字還留在欄位裡可以直接改

Scenario: 放棄一個填到一半的名字
  Given 新增 workspace 的視窗開著，名字打了一半
  When 寫作者取消或關閉這個視窗
  Then 視窗關閉，填到一半的名字被丟掉
  And 下一次打開這個視窗時欄位是空白的
```

### US-05 — 儲存狀態搬到寫作區最下面，長成麵包屑加一個圖示 [priority: P0]

**As a** 寫作者，**I want** 在寫字的地方正下面看到「我在寫哪個檔案、有沒有落地」，**so that** 我不會再把文章標題誤認成一個固定的字，也不必抬頭去畫面最上方找。

```gherkin
Scenario: 存好的樣子
  Given 寫作者打開了 workspace「Blog」裡的 my-first-post.md
  And 內容已經存進檔案
  When 寫作者看寫作區的最下面
  Then 左邊顯示「Blog ❯ my-first-post.md」，兩段以箭頭分隔
  And 右邊顯示一個綠色勾勾的圖示
  And 這一條上一個字都沒有

Scenario: 開始打字就轉圈
  Given 寫作者打開的文章目前已經存好
  When 寫作者在寫作區打了一個字
  Then 綠色勾勾換成轉圈的動畫
  And 這個動畫從打字那一刻起一路轉到內容真的存進檔案為止

Scenario: 存完換回綠勾並留著
  Given 寫作者剛打完字、內容正在存
  When 內容存進檔案了
  Then 轉圈的動畫換回綠色勾勾
  And 這個綠色勾勾一直留著，不會自己消失
  And 畫面上任何地方都不出現「已儲存」這幾個字

Scenario: 沒有打開任何文章
  Given 寫作者沒有打開任何文章
  When 寫作者看寫作區的最下面
  Then 那裡沒有麵包屑，也沒有任何儲存圖示

Scenario: 只有預覽時被擋下
  Given 寫作者打開的文章有一個還沒回答的外部改動警示
  And 目前是只有預覽
  When 寫作者點另一篇文章
  Then 排法切回並排，寫作區回到畫面上
  And 那條警示與覆寫、重新載入兩個選擇就在寫作區下方
  And 寫作者仍然停在原本那篇文章

Scenario: 麵包屑裝不下
  Given 開著的文章屬於一個名字很長的 workspace
  And 這個檔名也很長
  When 這一條的寬度裝不下兩段
  Then 檔名完整顯示，一個字都不省
  And workspace 那一段被截短並以省略號結尾

Scenario: 儲存失敗
  Given 寫作者在寫作區打了字
  When 內容存不進檔案
  Then 寫作區最下面那一條上長出失敗的說明
  And 那個圖示換成警示色的驚嘆記號，不再繼續轉圈

Scenario: 檔案在 Rustle 之外被改過
  Given 開著的文章在寫作期間被 Rustle 以外的程式改過
  When 寫作者看寫作區的最下面
  Then 同一條上長出「這個檔案在 Rustle 之外被改動過」的警示
  And 同一條上提供覆寫與重新載入兩個選擇

Scenario: 畫面最上方那條退場
  Given App 已經打開，並且有一篇文章正在寫
  When 寫作者看畫面的最上方
  Then 那裡沒有任何顯示文章標題或儲存狀態的橫條
```

### US-06 — 寫作區的字體與配色換成 Xcode 那一種 [priority: P1]

**As a** 寫作者，**I want** 寫字的地方看起來像 Xcode，**so that** 寫 Markdown 的手感跟我平常寫程式的手感一致。

```gherkin
Scenario: 淺色
  Given 系統目前是淺色外觀
  And 寫作區裡有標題、粗體、連結與程式碼
  When 寫作者看寫作區
  Then 文字是等寬字體
  And 各種語法用的是 Xcode 淺色預設主題的那幾個顏色

Scenario: 深色
  Given 系統從淺色切換到深色外觀
  When 寫作者看寫作區
  Then 各種語法換成 Xcode 深色預設主題的那幾個顏色
  And 每一種顏色在深色底上都讀得清楚

Scenario: 其他欄位不受影響
  Given 系統是任一種外觀
  When 寫作者同時看側欄、文章清單與預覽區
  Then 這三處的字體與配色與改版前完全相同

Scenario: 純散文不被上色
  Given 寫作區裡有一行沒有任何語法的散文
  When 寫作者看那一行
  Then 它是正文本身的顏色，沒有被額外上色
```

### US-07 — 標題那一條上有 Zen 按鈕與三顆檢視模式按鈕 [priority: P0]

**As a** 寫作者，**I want** 三種排法與 Zen 這四件事集中在同一條上，**so that** 我不必去畫面最右邊找一條窄長的按鈕，也不必把滑鼠移到預覽標題上點叉叉。

```gherkin
Scenario: 標題那一條的內容
  Given 目前是並排（寫作區與預覽同時在畫面上）
  When 寫作者看寫作區的標題那一條
  Then 最左邊是一顆兩個斜對角箭頭的圖示
  And 最右邊是三顆檢視模式圖示：只有編輯、並排、只有預覽
  And 三顆之中「並排」那一顆被標成目前這個

Scenario: 切成只有編輯
  Given 目前是並排
  When 寫作者按三顆之中的第一顆
  Then 預覽收起來，寫作區佔滿原本兩欄的寬度
  And Zen 按鈕與三顆檢視模式圖示仍然在寫作區的標題那一條上
  And 「只有編輯」那一顆被標成目前這個

Scenario: 切成只有預覽
  Given 目前是並排
  When 寫作者按三顆之中的第三顆
  Then 寫作區整個不在畫面上
  And 預覽佔滿原本兩欄的寬度
  And Zen 按鈕與三顆檢視模式圖示一起搬到預覽區的標題那一條上
  And 鍵盤落在新位置上「只有預覽」那一顆，所以沒有滑鼠的寫作者回得去

Scenario: 從只有預覽切回並排
  Given 目前是只有預覽
  When 寫作者按三顆之中的第二顆
  Then 寫作區回到畫面上，與預覽並排
  And Zen 按鈕與三顆檢視模式圖示回到寫作區的標題那一條上

Scenario: 只有預覽時沒有儲存狀態列
  Given 目前是只有預覽
  When 寫作者看內容區的最下面
  Then 那裡沒有麵包屑，也沒有儲存圖示

Scenario: 分隔線的位置被記住
  Given 目前是並排，而且寫作者已經把分隔線拖到某個位置
  When 寫作者切成只有編輯，再切回並排
  Then 分隔線回到寫作者原本拖好的那個位置

Scenario: 舊的兩個入口退場
  Given App 已經打開
  When 寫作者看畫面最右邊與預覽區的標題
  Then 畫面最右邊沒有那條窄長的「預覽」按鈕
  And 預覽區的標題上沒有關閉用的叉叉

Scenario: 預覽的鍵盤快速鍵還在
  Given 目前是並排
  When 寫作者按預覽的鍵盤快速鍵
  Then 變成只有編輯
  And 再按一次又變回並排

Scenario: 從只有預覽按快速鍵
  Given 目前是只有預覽
  When 寫作者按預覽的鍵盤快速鍵
  Then 變成並排
  And 寫作區回到畫面上
```

### US-08 — Zen Mode：藏掉左邊兩欄，只留寫作的地方 [priority: P0]

**As a** 寫作者，**I want** 一鍵把側欄與文章清單收掉，**so that** 我要專心寫一篇長文的時候，畫面上只剩這篇文章。

```gherkin
Scenario: 進入 Zen Mode
  Given 目前是正常畫面、並排
  When 寫作者按 Zen 按鈕
  Then 側欄（All Notes、Workspaces、狀態、標籤）與文章清單都不在畫面上
  And 寫作區與預覽佔滿整個視窗
  And Zen 按鈕的圖示從向外張的箭頭換成向內收的箭頭

Scenario: 離開 Zen Mode
  Given 目前在 Zen Mode
  When 寫作者再按同一顆 Zen 按鈕
  Then 側欄與文章清單回到畫面上
  And 畫面回到進入 Zen Mode 之前的樣子

Scenario: Zen Mode 之下照樣能選檢視模式
  Given 目前在 Zen Mode、並排
  When 寫作者按三顆之中的第三顆
  Then 整個視窗只剩預覽
  And 仍然在 Zen Mode
  And Zen 按鈕與三顆檢視模式圖示都在預覽區的標題那一條上

Scenario: Esc 不會退出 Zen Mode
  Given 寫作者正在 Zen Mode 裡打字
  When 寫作者按 Esc
  Then 鍵盤交出寫作區（下一次 Tab 會移動焦點）
  And 仍然在 Zen Mode

Scenario: Zen Mode 之下的鍵盤逃脫路徑
  Given 寫作者正在 Zen Mode 裡打字
```

## 4. Business Flow & Logic

### 主要流程

1. 寫作者從側欄挑一個 workspace（或 All Notes）。
2. 文章清單上方那一列固定在那裡：漏斗篩選框、新文章圖示。清單按建立時間新到舊排。
3. 寫作者在卡片上一眼看到標題、狀態、日期、標籤；要改 metadata 按右上角鉛筆，要刪掉按右下角垃圾桶。
4. 點一張卡片就把那篇文章打開在寫作區。寫作區最下面那一條開始說「`workspace ❯ 檔名`」與一個綠色勾勾。
5. 寫作者打字 → 綠勾換成轉圈 → 內容落地 → 換回綠勾並留著。
6. 需要看渲染結果就按三顆之中的第二顆或第三顆；需要專心就按最左邊的 Zen 按鈕。兩件事互不干涉。

### 核心規則

- **文章清單的順序是固定的**：建立時間新到舊。寫作者無法改。
- **狀態一律說出來**：五種說法（Active、On Hold、Completed、Dropped、No Status），沒有狀態的文章寫「No Status」，不是留白。
- **卡片那一行的順序固定**：狀態 → 日期 → 標籤 → 既有標記（「metadata 不完整」、「開著的」）。整行左靠。
- **儲存指示有三態**：轉圈（還沒落地）、綠勾（已落地）、警示（存不進去）。轉圈從打字那一刻起就開始，包含停手等待期與組字暫停期——寫作者要知道的是「這件事還沒落地」，不是 App 背後此刻在做什麼。**第三態是必要的**：若只有前兩態，存不進去時會永遠轉圈，那是在告訴寫作者他們的字正在路上，而它們哪裡都沒去。
- **「這個檔案在 Rustle 之外被改動過」不是失敗**：什麼都還沒寫，而且寫作者有兩個答案要給，所以指示仍然是轉圈。
- **麵包屑寫檔名不寫標題**，並且截短時**先犧牲 workspace 那一段**，檔名永遠完整。
- **檢視模式與 Zen Mode 是兩個互相獨立的維度**：Zen 之下三種檢視照樣能選；切檢視模式不會改變 Zen 的開關。
- **只有預覽時，寫作區不在畫面上，所以儲存狀態列也不畫。** Zen 按鈕與三顆檢視模式按鈕跟著搬到預覽區的標題那一條。
- **但被擋下時，寫作區一定要回來。** 自動儲存會擋住「未回答外部改動警示」或「上次寫檔失敗」時的離開，而那兩個答案就在儲存狀態列上。只有預覽時那條不在畫面上，所以**擋下的同時把排法切回並排**——寫作者被一個看不到的東西擋住、又沒有出路，是死路。切回來不寫進設定檔：這不是寫作者選的排法。
- **「開著的」不是「這篇開著」的標記**：它解釋一個例外——這一列不符合篩選，但因為編輯區正握著它而留在畫面上。所以它只會在有篩選時出現。
- **Zen Mode 不跨重啟**；預覽的開關狀態照舊跨重啟（既有行為不變）。
- **`Esc` 不綁 Zen Mode**：`Esc` 在寫作區已經是離開寫作區的第一步，兩件事共用一個鍵會互相搶。
- **預覽的鍵盤快速鍵切換的是「並排」與「只有編輯」**，不會切到「只有預覽」。從「只有預覽」按它時，把寫作區交回來（變成並排）而不是連預覽一起收掉——按下它的人是為了看到寫作區。
- **「只有預覽」不跨重啟**：設定檔只記「預覽在不在畫面上」這一個答案，所以「只有預覽」被記成「預覽在」，重啟後回到並排。
- **文章清單的固定順序有完整的定序規則**：建立時間新到舊；沒有時間的排最後（那是資訊缺漏，不是最新）；時間相同時依標題、再依 workspace、再依檔名，所以每次畫出來的順序都一樣。
- **空的 workspace 不再有第三個「新文章」入口**：上方那一列一直都在，所以空狀態只給引導文字，不再放一顆字一模一樣的按鈕。

### 邊界與例外

- **範圍裡沒有文章**：清單上方那一列照樣在，下面另外顯示「建立第一篇文章」。
- **在 All Notes 之下按新文章**：擋在按鈕那一下並說明原因，不打開表單、不建立檔案。
- **名字被擋下（新增 workspace）**：視窗不關、原因寫在視窗裡、名字留在欄位裡。
- **視窗被取消**：填到一半的名字丟掉，下次打開是空白的。
- **儲存失敗**：說明長在寫作區最下面那一條上。
- **檔案在 Rustle 之外被改過**：警示與覆寫／重新載入兩個選擇長在同一條上；既有的「未回答警示前不放人換文章」規則不變。
- **組字中**：切換檢視模式或 Zen Mode 不打斷正在選的字。
- **Zen Mode 之下沒有打開文章**：照舊顯示「還沒有選取文章」，Zen 按鈕仍可按著回去挑文章。
- **Zen Mode 之下用鍵盤**：`Esc` 之後的 `Tab` 停在標題那一條上的按鈕，鍵盤使用者不會被鎖在 Zen 裡。

## 5. UI/UX Design & Interaction

### Prototype Link

無設計稿。這一節的文字即規格。

### 版面

- 畫面最上方那條橫條**整條移除**；原本它佔的高度歸還給下面的欄位。
- 寫作區與預覽區各自的標題那一條，結構是：**最左邊 Zen 按鈕 → 區塊名稱 → 最右邊三顆檢視模式按鈕**。同一時間只有一個區塊帶著這一組按鈕（並排與只有編輯時在寫作區、只有預覽時在預覽區）。
- 寫作區最下面新增一條狀態列：**左邊麵包屑、右邊儲存指示**。失敗說明與外部改動警示長在同一條上。
- 文章清單上方那一列：**漏斗篩選框（吃掉剩下的寬度）＋ 新文章圖示（固定寬度）**。這一列一直都在。
- 文章卡片：標題一行（最多兩行）、metadata 一行（左靠）、**右上角鉛筆、右下角垃圾桶**。

### 關鍵互動

- **卡片上的兩個圖示**：平常低調（半透明、無邊框），滑鼠移到卡片上或該圖示拿到鍵盤焦點時才變明顯。**永遠在文件裡**，所以鍵盤走得到。
- **三顆檢視模式按鈕**：目前這個要有明顯的「按著」樣子。
- **Zen 按鈕**：圖示在「向外張的斜箭頭」與「向內收的斜箭頭」之間切換，本身就說出下一次按會發生什麼。
- **儲存指示**：轉圈是持續旋轉的動畫；綠勾是靜態的。兩者尺寸相同，切換時這一條的寬度與高度都不變。
- **空狀態**：範圍裡沒有文章 → 「建立第一篇文章」（原本的引導不變）；沒有打開文章 → 「還沒有選取文章」（原本的引導不變，Zen Mode 之下也一樣）。
- **載入中**：本機檔案讀寫沒有可感知的等待，沿用現況不新增載入樣式。唯一的進行中狀態就是儲存指示的轉圈。

- 沒有語法可標的散文維持正文顏色。
- 只套寫作區；側欄、文章清單、預覽區完全不動。

## 6. Non-Functional Requirements

- **輸入法（IME）**：組字期間游標附近不得有畫面重繪。切換檢視模式或進出 Zen Mode 不得打斷正在選的字。
- **不弄丟東西**：切換檢視模式或進出 Zen Mode 前後，寫作區的內容、游標位置、復原歷史三者都必須完好。
- **反應速度**：切換檢視模式與進出 Zen Mode 都是本機的畫面重排，寫作者不應感覺到等待。
- **鍵盤可達**：卡片上的兩個圖示、清單上方那一列、標題那一條上的四顆按鈕，都要能只用鍵盤到達與操作。Zen Mode 之下必須有鍵盤退出的路徑。
- **顏色對比**：Xcode 兩套配色在各自的底色上都要讀得清楚；綠色勾勾在淺色與深色底上都要看得出是綠的。
- **相容性**：macOS 桌面。離線可用，不連任何外部服務。
- **分析追蹤**：N/A——個人自用，不埋任何事件。
- **安全性**：這一切片不新增任何檔案讀寫或對外通訊，預覽的淨化政策不動。

## 7. Dependencies & Risks

### External Dependencies

- **線條圖示的來源**：先找現成的圖示集，找不到合用的才自己畫。**選哪一套是技術決定，留給 `/architecture`**；本文件只約束它們看起來的樣子。
- **Xcode 預設主題的顏色值**：需要把 Default Light 與 Default Dark 的實際顏色抄進專案。這是一組常數，不是外部依賴。

### Known Risks

| 風險 | 說明 |
| :--- | :--- |
| **切換排法可能重建寫作區** | 這是本切片最大的風險。專案的既有紀錄已經寫明「重建寫作區會斷組字、也會斷復原歷史」。US-09 就是為它而寫的驗收標準。 |
| **只有預覽時寫作區離開畫面** | 寫作區離開畫面就等於被拆掉，回來時是全新的。US-07 與 US-09 必須一起成立：切回來時內容、游標、復原歷史都要在。 |
| **Zen Mode 讓鍵盤使用者無路可走** | 側欄與文章清單是離開寫作區之後 `Tab` 的落點。兩欄一藏，落點就只剩標題那一條上的四顆按鈕——US-08 明訂它必須是落點。 |
| **狀態與既有標記擠在同一行** | 卡片第二行現在要放五種東西（狀態、日期、標籤、metadata 不完整、開著的）。窄欄之下會折行，需要確認折行後仍然左靠、讀得順。 |
| **綠色勾勾的綠** | 專案目前沒有一個「成功」的顏色。要嘛沿用既有色票裡最接近的，要嘛為它新定一個——兩套主題都要顧到。留給 `/architecture` 決定它從哪來，但「看得出是綠的」是本文件的要求。 |
