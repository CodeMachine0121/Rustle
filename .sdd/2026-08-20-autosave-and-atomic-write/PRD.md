# 需求規格 — 自動儲存、原子寫檔與外部改動偵測

- **切片**：Wave 2，`feature/autosave-and-atomic-write`
- **上游文件**：[BRIEF.md](BRIEF.md)、需求文件 §3.3、§3.2、§7.4、NFR-4
- **覆蓋需求 ID**：R-10、R-11、R-12、FR-4.6、FR-8.4；連帶維持 R-6（`updated_at` 每次儲存更新）、R-8（只覆寫認識的欄位）；橫切約束 FR-8.1、FR-8.7
- **人工回歸項目**：**T-8**（組字停留超過 2 秒不得觸發自動儲存——本切片交付後才是真正的驗收）、**T-11**（組字中切換文章／workspace）
- **詞彙**：一律依通用語言地圖

---

## 1. 目標

讓「使用者寫的字一定會安全地進到磁碟上那個檔案裡」成為一件不需要使用者思考的事：

- 不用按存檔（R-10）
- 存的過程壞不掉（R-11）
- 別人改過的檔案不會被無聲蓋掉（R-12）
- 而且看得出現在到底存了沒有（FR-4.6）

## 2. User Stories

| ID | 故事 |
| :--- | :--- |
| **US-1** | 作為寫文章的使用者，我要停手一秒之後檔案自己存好，這樣我不用一直按 Cmd+S，也不會忘記按 |
| **US-2** | 作為用注音打字的使用者，我要在盯著候選視窗想事情的時候不要有任何儲存動作，這樣我的組字不會被打斷 |
| **US-3** | 作為會邊寫邊跳文章的使用者，我要在切換文章、切換 workspace、關閉視窗的時候，剛剛寫的東西已經進磁碟 |
| **US-4** | 作為會遇到機器當機的使用者，我要我的文章永遠是完整的舊版或完整的新版，絕不是半截檔案 |
| **US-5** | 作為同時用 Obsidian／Git 的使用者，我要 Rustle 發現檔案被外部改過時先問我，讓我選覆寫或重新載入，而不是幫我決定 |
| **US-6** | 作為需要確認的使用者，我要在標題列看到現在這篇的標題與「已儲存／未儲存的變更」 |
| **US-7** | 作為在 front matter 裡放了自己欄位與註解的使用者，我要每次自動儲存只動 `updated_at`，其他一個位元都不要動 |

## 3. 業務流程

### 3.1 一次自動儲存

```
編輯區的正文變了
   → 沒有開啟任何文章？ → 什麼都不做
   → 標記「未儲存的變更」（標題列立刻反映）
   → 排定一次 1 秒後的儲存（沿用組字感知的去抖動器）
        ├─ 期間又有輸入 → 倒數重新開始
        ├─ 期間開始組字 → 倒數暫停（停多久都不會觸發）
        └─ 組字結束     → 接著走完剩下的時間
   → 倒數走完 → 儲存（見 3.2）
```

### 3.2 一次儲存

```
（畫面層）帶著：文章的 workspace 與檔名、當前正文、載入時記下的檔案修改時間、
             以及「使用者是否已授權覆寫」
   → 已經有一個未回答的外部改動警示，而且這次不是使用者授權的覆寫？
        └─ 是 → 不送出（避免警示被自己吃掉）
   → 正在組字？ → 等到組字結束
   → 已經有一次儲存在飛？ → 排在它後面，不並行
   → 送出 saveBody 通道

（負責檔案存取的那一層）
   → 名稱 → vault 範圍檢查 → 符號連結解析後再檢查
   → 讀出檔案：內容 + 修改時間
   → 這次的預期修改時間 =
        使用者授權覆寫 ? 檔案現在的修改時間 : 畫面層帶來的「上次已知修改時間」
   → 把正文與新的 updated_at 接回 front matter（其他欄位、註解、鍵順序、換行、BOM 不動）
   → 寫檔（原子）：
        1. 讀一次檔案修改時間，與預期不符 → 什麼都不寫，回報「偵測到外部改動」
        2. 相符 → 寫暫存檔（同目錄）→ fsync → 權限對齊原檔
        3. **再讀一次修改時間**，這時才是最後一刻：不符 → 刪掉暫存檔，回報「偵測到外部改動」
        4. 仍然相符 → rename 換掉原檔
        5. 中途任何一步失敗 → 刪掉暫存檔，把失敗往上傳（原檔一個位元都沒動）
   → 回覆：新的 updated_at、新的檔案修改時間、是否偵測到外部改動

（畫面層）
   → 偵測到外部改動 → 顯示警示與兩個選擇；「上次已知修改時間」不更新；停止自動儲存
   → 失敗           → 顯示失敗訊息；變更仍算未儲存
   → 成功           → 更新「上次已知修改時間」；若正文在這期間沒再變過，狀態變「已儲存」
```

### 3.3 切換文章、切換 workspace、關閉視窗

```
切換文章 / 切換 workspace（清掉當前文章）
   → 先把當前文章的未存變更寫完（沒有未存變更就什麼都不做）
   → 外部改動警示還沒被回答 → **不換**，畫面留在原地，警示與兩個選擇繼續在眼前
   → 寫檔失敗，而且這是第一次嘗試 → **不換**，失敗訊息留在眼前
   → 寫檔失敗，但已經擋過一次 → 換，未存修改被放掉（第二次是知情的）
   → 否則 → 換成新的文章 / 清空

關閉視窗
   → 沒有未存變更 → 直接關
   → 有未存變更   → 取消這一次關閉
                   → 讓當前焦點元素失焦（讓輸入法收掉組字，T-11）
                   → 等儲存寫完
                   → 變更真的上了磁碟 → 關閉視窗
                   → 沒上（寫檔失敗，或警示未回答）→ 不關，讓使用者看見原因
   → 再一次嘗試關閉 → 一律放行（不再攔、不再失焦、不再儲存）
```

### 3.4 外部改動的兩個選擇

```
警示出現後，使用者選：
  覆寫       → 以檔案現在的修改時間為預期，重送一次儲存
                （若在這一瞬間檔案又被改了 → 再次拒絕，警示留著）
  重新載入   → （組字中的話先等組字結束——它會換掉編輯區的內容）
                → 讀出磁碟上的正文交給編輯區
                → 未存變更與警示一併清掉，「上次已知修改時間」換成磁碟上的
```

## 4. 驗收標準（Gherkin）

### Feature：自動儲存的時機（R-10、FR-8.4）

```gherkin
# TC-01
場景: 停止輸入一秒之後寫檔
  假設 編輯區開著一篇文章，沒有未儲存的變更
  當 使用者輸入了一些字
  並且 一秒之內沒有再輸入
  那麼 這篇文章被儲存了一次，帶的是使用者剛輸入的正文

# TC-02
場景: 連續輸入只在停手之後存一次
  假設 編輯區開著一篇文章
  當 使用者每 0.9 秒輸入一次，連續三次
  那麼 期間沒有任何儲存發生
  當 使用者停手一秒
  那麼 總共只儲存了一次

# TC-03
場景: 組字期間倒數暫停，停留多久都不儲存
  假設 使用者輸入了一些字，倒數已經走了 0.4 秒
  當 使用者開始組字
  並且 停留 10 秒
  那麼 沒有任何儲存發生

# TC-04
場景: 組字結束後接著走完剩下的時間，而不是重新計時
  假設 承 TC-03 的情況
  當 使用者結束組字
  那麼 再過 0.599 秒仍然沒有儲存
  並且 再過 0.001 秒（合計剩下的 0.6 秒）之後儲存了一次

# TC-05
場景: 組字中發生的輸入，等組字結束才開始倒數
  假設 使用者正在組字
  當 編輯區的正文變了
  並且 過了 10 秒
  那麼 沒有任何儲存發生
  當 使用者結束組字並過了一秒
  那麼 儲存了一次

# TC-06
場景: 切換文章之前先把上一篇寫完
  假設 編輯區開著一篇文章且有未儲存的變更
  當 使用者換到另一篇文章
  那麼 上一篇在換過去之前已經被儲存

# TC-07
場景: 切換 workspace（不再有開啟的文章）之前先寫完
  假設 編輯區開著一篇文章且有未儲存的變更
  當 使用者切換到另一個 workspace，編輯區不再有開啟的文章
  那麼 那一篇在關掉之前已經被儲存

# TC-08
場景: 關閉視窗之前先寫完，而且是寫完才關
  假設 編輯區開著一篇文章且有未儲存的變更
  當 視窗要關閉
  那麼 這一次關閉被取消
  並且 文章被儲存
  並且 儲存完成之後視窗才真的關閉

# TC-09
場景: 沒有未儲存的變更時，切換與關閉都不寫檔
  假設 編輯區開著一篇文章，沒有未儲存的變更
  當 使用者換到另一篇文章 / 視窗要關閉
  那麼 沒有任何儲存發生
  並且 關閉視窗那一次不被取消

# TC-10
場景: 沒有開啟文章時的輸入不會觸發儲存
  假設 編輯區沒有開啟任何文章
  當 正文變了並且過了一秒
  那麼 沒有任何儲存發生

# TC-11
場景: 組字中被要求立即儲存，等組字結束才寫
  假設 編輯區開著一篇文章且有未儲存的變更
  並且 使用者正在組字
  當 要求立即儲存（切換或關閉）
  那麼 組字結束之前沒有任何儲存發生
  當 使用者結束組字
  那麼 儲存發生了，並且要求立即儲存的那個動作在寫完之後才算完成
```

### Feature：原子寫檔（R-11、NFR-4）

```gherkin
# TC-12
場景: 寫入的內容真的進到那個檔案裡
  假設 vault 裡有一篇文章
  當 儲存新的檔案內容
  那麼 檔案內容變成新的
  並且 回報的檔案修改時間是這個檔案現在的修改時間

# TC-13
場景: 成功寫入之後不留暫存檔
  假設 vault 裡有一篇文章
  當 儲存成功
  那麼 該 workspace 目錄裡只有那篇文章，沒有任何暫存檔

# TC-14
場景: 寫不出去的時候，原檔逐位元不變
  假設 vault 裡有一篇文章，而它所在的目錄無法寫入
  當 嘗試儲存新的內容
  那麼 儲存失敗
  並且 那篇文章的內容與原本逐位元相同
  並且 目錄裡沒有留下暫存檔

# TC-15
場景: 目標檔案是唯讀的，內容照樣被換掉，權限保持原樣
  假設 vault 裡有一篇文章，檔案權限是唯讀（0444）
  當 儲存新的內容
  那麼 檔案內容變成新的
  並且 檔案權限仍然是唯讀（0444）

# TC-16
場景: 文章是 vault 內的符號連結，寫的是它指向的檔案
  假設 vault 裡有一篇文章，另一個 workspace 有一個指向它的符號連結
  當 透過那個符號連結儲存新的內容
  那麼 被指向的那個檔案內容變成新的
  並且 那個符號連結還是一個符號連結

# TC-17
場景: 逃出 vault 的儲存一律拒絕，而且什麼都不寫
  假設 給定的檔名會逃出 vault，或文章是指向 vault 外的符號連結
  當 嘗試儲存
  那麼 儲存被拒絕
  並且 vault 外的那個檔案沒有被改動
```

### Feature：外部改動偵測（R-12）

```gherkin
# TC-18
場景: 修改時間與記憶中的一致就正常寫入
  假設 檔案的修改時間與畫面層帶來的「上次已知修改時間」相同
  當 儲存
  那麼 內容被寫入
  並且 回覆說沒有偵測到外部改動
  並且 回覆帶的是寫入之後的新修改時間

# TC-19
場景: 修改時間不符就不寫入，並且回報偵測到外部改動
  假設 檔案在載入之後被別的程式改過
  當 儲存
  那麼 檔案內容沒有被改動
  並且 回覆說偵測到外部改動
  並且 回覆帶的「上次已知修改時間」仍然是畫面層原本帶來的那個
       （警示不會因為這次回覆而自動解除）

# TC-20
場景: 警示還沒被回答之前不再自動嘗試儲存
  假設 上一次儲存回報了外部改動
  當 使用者又輸入了一些字並停手超過一秒
  那麼 沒有任何新的儲存請求送出

# TC-21
場景: 使用者選「覆寫」就寫進去
  假設 上一次儲存回報了外部改動
  當 使用者選擇覆寫
  那麼 送出的儲存請求帶著「已授權覆寫」
  並且 負責檔案存取的那一層以檔案現在的修改時間為預期，寫入成功
  並且 警示解除，狀態變成已儲存

# TC-22
場景: 使用者選「重新載入」就拿磁碟上的內容
  假設 上一次儲存回報了外部改動
  當 使用者選擇重新載入
  那麼 交出磁碟上的正文
  並且 警示解除
  並且 沒有未儲存的變更

# TC-23
場景: 覆寫的那一瞬間檔案又被改了，還是拒絕
  假設 使用者授權覆寫
  並且 讀出檔案之後、寫入之前，檔案又被改了一次
  當 寫入
  那麼 什麼都沒被寫進去
  並且 回覆說偵測到外部改動
```

### Feature：存下去的內容（R-6、R-8）

```gherkin
# TC-24
場景: 每次儲存都更新 updated_at
  假設 一篇文章的 front matter 有 updated_at
  當 儲存
  那麼 檔案裡的 updated_at 是儲存那一刻的時間（ISO 8601 含時區）

# TC-25
場景: 除了 updated_at 與正文，其他一個位元都不動
  假設 一篇文章的 front matter 有 Rustle 不認識的欄位、自訂的鍵順序與註解
  當 儲存新的正文
  那麼 未知欄位、鍵順序、註解、其他 Rustle 欄位的值全部原樣保留
  並且 正文換成新的

# TC-26
場景: 沒有 front matter 的檔案，儲存後有了 updated_at
  假設 一篇文章完全沒有 front matter
  當 儲存新的正文
  那麼 檔頭多出一個只有 updated_at 的 front matter 區塊
  並且 正文換成新的

# TC-27
場景: front matter 是壞的 YAML 也存得進去，而且不改壞區塊
  假設 一篇文章的 front matter 是 YAML 解析不動的內容
  當 儲存新的正文
  那麼 正文換成新的
  並且 那個區塊逐字保留（沒有被重新序列化，也沒有加上 updated_at）

# TC-28
場景: CRLF 與 BOM 都保留
  假設 一篇文章以 BOM 開頭並且用 CRLF 換行
  當 儲存
  那麼 存完之後 BOM 還在
  並且 front matter 仍然用 CRLF 換行
```
