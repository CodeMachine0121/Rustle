# 需求規格 — Metadata 編輯與破壞性操作

- **切片**：Wave 4, `feature/metadata-editing-and-destructive-operations`
- **日期**：2026-08-20
- **上游**：[BRIEF.md](BRIEF.md)（需求共識與假設）
- **覆蓋需求**：FR-1.5、FR-2.6、FR-2.7、R-8（呼叫端）、R-18、NFR-4（垃圾桶）、FR-8.6／FR-8.7（新增欄位）、T-9（延伸）
- **狀態**：驗收標準已定案，可進入 `/architecture`

本檔只談**對外可觀察的行為**。物件、通道、資料夾一律不出現在這裡。

---

## 1. 目標

讓寫作者在 App 裡**改得動 metadata、刪得掉東西**，而且：

1. metadata 只透過 GUI 表單改，`created_at`／`updated_at` 唯讀，檔案裡其他任何東西一個位元都不動。
2. 刪除一律進**系統垃圾桶**，刪 workspace 前的確認說出**真實的**文章數與圖片數。
3. 刪文章**不刪圖片**。
4. 動到正在編輯的那個檔案之前，未存的變更先落磁碟；落不了就整件事不發生，並說得出原因。
5. 失敗有一個**專屬的錯誤出口**，不再假扮成某一欄的讀取失敗。

## 2. User Stories

| ID | Story |
| :--- | :--- |
| **US-1** | 作為寫作者，我要事後改得動文章的標題、分類、標籤，而且是在同一個 GUI 表單裡改，這樣我永遠不必在編輯區看到 YAML |
| **US-2** | 作為寫作者，我要建立時間與更新時間看得到但改不了，這樣它們永遠是事實而不是我填的字 |
| **US-3** | 作為在檔案裡自己加過欄位與註解的寫作者，我要改 metadata 只動我改的那幾個欄位，這樣 Rustle 不會擦掉我手寫的東西 |
| **US-4** | 作為正在編輯某一篇的寫作者，我要改它的 metadata 之後仍然在那一篇裡，而且不要跳出「檔案被外部改動」的警示 |
| **US-5** | 作為寫作者，我要刪得掉文章，而且它進系統垃圾桶而不是消失 |
| **US-6** | 作為貼過圖的寫作者，我要刪文章不會刪掉別篇也在用的圖 |
| **US-7** | 作為寫作者，我要重新命名 workspace，而且重名或不合法的名稱會被擋下並說出原因 |
| **US-8** | 作為寫作者，我要刪 workspace 前看到「會刪掉幾篇文章、幾張圖片」，而且那個數字是真的 |
| **US-9** | 作為正在編輯的寫作者，我要破壞性操作之前未存的段落一定先落磁碟；落不了就什麼都不要發生 |
| **US-10** | 作為寫中文的寫作者，我要新增的每一個輸入欄位的 `Enter` 都屬於輸入法，不誤送出、不誤生 chip、不誤關對話框 |
| **US-11** | 作為使用者，我要操作失敗時看到一則說得出「哪個操作、為什麼」的提示，而不是一句與事實不符的「讀不到這個 workspace」 |

## 3. 業務流程

### 3.1 一次 metadata 編輯

```
欄 2 那一列按「編輯 metadata」
   │
   ├─ 表單開啟，三個欄位帶著這篇文章現在的值
   │  建立時間與更新時間以文字顯示（無欄位）
   │
   ├─ 使用者改標題／加減 chip
   │
   └─ 按「儲存」
        │
        ├─ 標題是空白 → 儲存鈕停用（畫面層）；硬送 → 負責檔案存取的那一層拒絕，檔案不動
        │
        ├─ 這一篇正開著嗎？
        │    是 → 先讓自動儲存把正文寫出去
        │           ├─ 被拒絕（警示未回答／上次寫檔失敗）→ 什麼都不寫，錯誤提示說出原因
        │           └─ 過關 → 往下
        │    否 → 直接往下
        │
        ├─ 寫檔：只改 title／category／tags／updated_at
        │    └─ 檔案剛剛被別的程式改過 → 什麼都不寫，錯誤提示說出原因
        │
        ├─ 重讀文章清單（那一列跟著更新）
        │
        └─ 這一篇正開著 → 用新的檔案修改時間重新開啟它（標題列跟著換標題）
             表單關閉
```

### 3.2 一次刪除文章

```
欄 2 那一列按「刪除」
   └─ 二次確認：「移到系統垃圾桶」「圖片不會被刪除」
        ├─ 取消／Esc → 什麼都不發生
        └─ 確認
             ├─ 這一篇正開著 → 先關掉它（會先儲存，可能被拒絕；被拒絕就什麼都不刪）
             ├─ 移到系統垃圾桶（永不永久刪除）
             ├─ 重讀文章清單與 workspace 清單
             └─ 這一篇正開著 → 編輯區清空、沒有任何一列被選取
```

### 3.3 一次重新命名 workspace

```
欄 1 那一列按「重新命名」→ 就地出現輸入欄（帶著現在的名字）
   ├─ Esc → 取消
   └─ Enter／按「重新命名」
        ├─ 這是正在使用的 workspace 嗎？
        │    是 → 先關掉開著的文章（會先儲存，可能被拒絕；被拒絕就什麼都不改）
        │    否 → 直接往下
        ├─ 名稱被擋下（空白／路徑分隔字元／保留名稱／已被使用）→ 說出原因，資料夾不動
        └─ 資料夾就地改名
             ├─ 重讀 workspace 清單
             └─ 原本被選取的是它 → 仍然選取它（新名字），文章清單重新列出，編輯區清空
```

### 3.4 一次刪除 workspace

```
欄 1 那一列按「刪除」
   ├─ 先去磁碟數：N 篇文章、M 張圖片
   │    └─ 數不出來（權限不足…）→ 不開確認，走錯誤提示
   ├─ 二次確認：「將刪除 N 篇文章與 M 張圖片」「整個資料夾會移到系統垃圾桶」
   │    ├─ 取消／Esc → 什麼都不發生
   │    └─ 確認
   │         ├─ 這是正在使用的 workspace → 先關掉開著的文章（可能被拒絕）
   │         ├─ 再數一次，然後把整個資料夾移到系統垃圾桶
   │         ├─ 重讀 workspace 清單
   │         └─ 原本被選取的是它 → 沒有 workspace 被選取，文章清單與編輯區清空
```
