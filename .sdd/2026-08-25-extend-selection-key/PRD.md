## 1. Background & Goal

### Problem Statement

寫作區今天**沒有任何用鍵盤選一段結構的方法**。要選起一整個連結、一整段粗體、一整個清單，只有一條路：用滑鼠拖，而且要拖得剛剛好。拖過頭就多選一個字，拖不夠就少一個記號——而少了記號的選取，剪下之後正文裡會留下半截星號或半個中括號。

寫作區的核心其實一直會做「逐層擴大選取」這件事，它原本綁在斜體那個鍵上。`feature/editing-surface-marks-and-emphasis` 把那個鍵改成斜體，並在文件裡寫明那個行為是**刻意退場**的——當時的判斷是「寫作者按這個鍵是要斜體，沒有人在找另一件事」。那個判斷對，缺的是給它一個自己的鍵。

而寫作者想要的那個鍵是 **Command+W**——它今天被作業系統出廠選單的「關閉視窗」佔著，按下去會直接關掉視窗。所以這個切片有兩半：**一半是把鍵讓出來，一半是把行為接上去。**

### Expected Outcome

- **按一下 Command+W，選取範圍往外長一層**：詞 → 它所在的連結或強調 → 那一段話 → 整個清單 → 整篇文章。
- **連按三下到得了整段**——這是「一層怎麼數」的判準，不是感覺。
- **Command+W 從此在這個 App 的任何地方都不會關掉視窗。** 關視窗改成 Shift+Command+W。
- **除了「關閉視窗」那一格，作業系統選單上每一列的行為與快速鍵都沒有變**——複製、貼上、還原、重做、縮放、開發者工具、結束 App，一個都不動。
- **這個鍵一個字都不寫進文章。** 它只移動選取，正文、前置資料、檔名、圖片一律不受影響。

### Out of Scope

「縮回來」的反向鍵、選單文字跟著介面語言切換、重新設計選單有哪幾列、快速鍵可自訂、滑鼠與觸控板的對應手勢、選取範圍的顏色與外觀、預覽區裡的選取。理由逐項見 BRIEF。

## 2. User Personas

- **Primary Role:** 寫作者——Rustle 唯一的使用者角色。
- **Usage Context:** 寫作途中，兩手都在鍵盤上，要選起剛寫好的一段東西來改寫、剪下或加記號。**這個鍵與輸入法搶鍵**：它是一個帶修飾鍵的字母鍵，某些輸入法在組字中自己會用，所以組字中一律不動作——與粗體、斜體、Tab 同一條規矩。
- **Secondary context（同一個人）：** 這個 App 第一次有自己的應用程式選單。寫作者對作業系統的標準鍵有肌肉記憶（複製、貼上、還原、結束），這次改動不得讓其中任何一個失效。

## 3. User Stories & Acceptance Criteria

### US-01 — 第一下選起游標所在的那個詞 [priority: P0]

**As a** 寫作者，**I want** 沒有選取時按這個鍵會先選起游標所在的那個詞，**so that** 我不必先用滑鼠點兩下就能開始選。

```gherkin
Scenario: 游標在英文字中間，第一下選起整個字
  Given 正文裡有一行「this is important today」
  And 游標停在「important」的「p」和「o」之間，沒有任何選取
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的正好是「important」這八個字元

Scenario: 游標在中文裡，第一下選起連續的那一整串中文
  Given 正文裡有一行「這是重點的地方」
  And 游標停在「重」和「點」之間，沒有任何選取
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的正好是「這是重點的地方」這七個字

Scenario: 中文那一串到標點就停
  Given 正文裡有一行「這是重點，那不是」
  And 游標停在「重」和「點」之間，沒有任何選取
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的正好是「這是重點」
  And 逗號與逗號後面的字都沒有被選到

Scenario: 空行上什麼都不做
  Given 正文有兩段話，中間隔著一行空行
  And 游標停在那一行空行上
  When 寫作者按下逐層擴大選取的快速鍵
  Then 仍然沒有任何選取，游標停在原處
  And 正文一個字都沒有變

Scenario: 只有空白的一行，同樣什麼都不做
  Given 正文有兩段話，中間隔著一行只有幾個空白字元的行
  And 游標停在那一行上
  When 寫作者按下逐層擴大選取的快速鍵
  Then 仍然沒有任何選取，游標停在原處

Scenario: 游標緊鄰標點時，沒有詞可選，直接往外長一層
  Given 正文裡有一段話「today.」
  And 游標停在句號的右邊，沒有任何選取
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的是「today.」這一整段話
  And 句號沒有被單獨選成一段

Scenario: 程式碼區塊裡照常選字
  Given 正文裡有一個程式碼區塊，其中一行是「const total = 1」
  And 游標停在「const」的中間，沒有任何選取
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的正好是「const」
  And 程式碼區塊的內容一個字都沒有變
```

### US-02 — 再按一下，選取往外長一層 [priority: P0]

**As a** 寫作者，**I want** 每按一次選取就長成包住它的下一個結構，**so that** 我可以按幾下就精準選起整個連結或整段引言，不必用滑鼠拖。

```gherkin
Scenario: 從連結文字長成整個連結
  Given 正文裡有一行「去看 [今天的天氣](https://example.com) 吧」
  And 「天氣」兩個字正被選著
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的是「[今天的天氣](https://example.com)」整段，中括號與小括號都在內

Scenario: 從整個連結長成整段話
  Given 正文裡有一行「去看 [今天的天氣](https://example.com) 吧」
  And 「[今天的天氣](https://example.com)」正被選著
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的是「去看 [今天的天氣](https://example.com) 吧」整行

Scenario: 從清單的一項長成整個清單
  Given 正文裡有一個三項的清單
  And 第二項整項正被選著
  When 寫作者按下逐層擴大選取的快速鍵
  Then 三項連同它們的記號全部被選起來

Scenario: 長成一段強調時，兩邊的記號一起被選進去
  Given 正文裡有一行「這是 **重點** 喔」
  And 「重點」兩個字正被選著
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的是「**重點**」，前後各兩個星號都在內

Scenario: 連按三下到得了整段
  Given 正文裡有一段話，其中含一個連結
  And 游標停在連結文字中間，沒有任何選取
  When 寫作者連續按下逐層擴大選取的快速鍵三次
  Then 被選起來的至少是那一整段話

Scenario: 滑鼠拖出來的選取，直接從那一段往外長
  Given 寫作者用滑鼠拖選了「今天的天」四個字
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的範圍比「今天的天」更大
  And 選取沒有先縮回成一個詞
```

### US-03 — 長到最外面就停住 [priority: P1]

**As a** 寫作者，**I want** 選取長到整篇之後再按就不動，**so that** 我按過頭時不會突然被丟回某個看不懂的狀態。

```gherkin
Scenario: 全選之後再按，什麼都不做
  Given 整篇正文正被選著
  When 寫作者按下逐層擴大選取的快速鍵
  Then 整篇正文仍然被選著，範圍一個字元都沒有變

Scenario: 短文章連按很多次，停在最外層
  Given 整篇正文只有一行「today」
  And 游標停在「today」中間，沒有任何選取
  When 寫作者連續按下逐層擴大選取的快速鍵五次
  Then 被選起來的是「today」整行
  And 選取範圍不曾縮小過

Scenario: 用滑鼠點別的地方，層次重新從詞開始
  Given 寫作者已經按了兩次，選取正停在中間某一層
  And 寫作者用滑鼠點到另一段的「important」中間
  When 寫作者按下逐層擴大選取的快速鍵
  Then 被選起來的正好是「important」這個詞
```

### US-04 — 這個鍵只在寫作區有意義，而且到處都不關視窗 [priority: P0]

**As a** 寫作者，**I want** 這個鍵在寫作區以外什麼都不做，**so that** 我在側欄或對話框裡誤按時，不會整個視窗連同未存的修改一起消失。

```gherkin
Scenario: 組字中不動作
  Given 寫作者正在用注音輸入法組字，還沒選定字
  When 寫作者按下逐層擴大選取的快速鍵
  Then 組字狀態不受干擾，候選字仍然在
  And 選取範圍沒有改變

Scenario: 焦點在文章清單時什麼都不做
  Given 焦點在側欄的文章清單上
  When 寫作者按下逐層擴大選取的快速鍵
  Then 視窗仍然開著
  And 文章清單的選取沒有改變

Scenario: 對話框開著時什麼都不做
  Given 建立文章的對話框開著，焦點在標題欄位
  When 寫作者按下逐層擴大選取的快速鍵
  Then 視窗仍然開著
  And 對話框仍然開著，欄位裡的字沒有變

Scenario: 焦點在預覽區時什麼都不做
  Given 焦點在預覽區
  When 寫作者按下逐層擴大選取的快速鍵
  Then 視窗仍然開著
```

## 4. Business Flow & Logic

### 主流程

```
按下逐層擴大選取的快速鍵
  │
  ├─ 焦點不在寫作區 ────────────▶ 什麼都不做（視窗一定不關）
  │
  ├─ 寫作者正在組字 ────────────▶ 什麼都不做
  │
  ├─ 目前沒有選取，且游標旁邊有詞 ─▶ 選起那個詞
  │
  └─ 其餘一律往外長一層 ──┬─ 外面還有一層 ─▶ 選取長成外面那一層
     （有選取、或旁邊沒有詞）└─ 外面沒有了 ─▶ 什麼都不做
```

### 核心規則

1. **「一層」由正文自己的結構決定，不另立一套。** 這個 App 不發明第二種「什麼算一層」——正文是 Markdown，Markdown 的結構就是層次。這也是為什麼強調的記號會一起被選走：那對星號在結構上屬於那段強調，不是旁邊的字。
2. **「那個詞是哪個詞」與粗體、斜體鍵共用同一條規則。** 中文沒有空白可以分詞，所以「那個詞」是連續的那一整串中文，到標點或空白才停。**兩處不得各有一套答案**，否則同一個游標位置按粗體與按這個鍵會選到不同的東西。
3. **這個鍵只移動選取，永遠不改正文。** 所以它不必像粗體鍵那樣避開程式碼區塊——粗體鍵避開是因為它會插入星號，這個鍵插入不了任何東西。
4. **只有一條分岔。** 「沒有選取而且游標旁邊有詞」是唯一的特別待遇，其餘每一種情況都走同一條路：往外長一層。空行上什麼都不做，不是因為有一條「空行的規則」，而是因為一行空行不屬於任何結構，外面沒有一層可以長；標點旁邊會選起整段，也是同一條路走出來的結果。**兩個結果，一條規則。**
5. **「這一下是哪一種」只決定一次，由寫作者所在的那個游標決定。** 只有一個游標時，這句話就只是「這裡有沒有詞」。有好幾個游標時，它本來也可以逐個游標各自決定，而刻意不這樣做：**往外長一層是編輯器自己沿著結構往上走，而它只接受「一整份選取」，從來不接受單一個游標**。逐個決定就得在這裡自己寫第二份「往上走」，也就是對「什麼算一層」給出第二個答案——那正是這個功能存在的目的所要避免的。代價寫在邊界表裡，而且是寫作者說得出口的一句話：**這一下是選詞還是往外長，看你人在哪。**
6. **層次沒有記憶。** 「現在在第幾層」不是一個被記住的狀態，而是每次都從當前選取往外看一層。所以寫作者用滑鼠點到別處之後，下一次按鍵自然從詞開始，不必有人去清掉什麼。
7. **Command+W 在這個 App 裡不再屬於視窗。** 它是寫作區的鍵；焦點不在寫作區時它安靜地什麼都不做，而不是退回去關視窗。

### Edge Cases

| 情況 | 行為 |
| :--- | :--- |
| 空行、或只有空白字元的行 | 什麼都不做。沒有詞可選，而空行不屬於任何結構，外面沒有一層可以長 |
| 游標緊鄰標點 | 沒有詞可選，所以往外長一層——選起那一整段話。標點不會被單獨選成一段 |
| 程式碼區塊裡 | 照常選字、照常往外長。這個鍵不寫入任何東西，沒有理由特別待它 |
| 滑鼠拖出來的選取 | 直接從那一段往外長，不先縮回一個詞 |
| 選取已經是整篇 | 什麼都不做，維持全選 |
| 寫作者正在組字 | 什麼都不做 |
| 焦點在寫作區以外 | 什麼都不做，視窗一定不關 |
| **文章唯讀** | **照常選取。** 這個鍵不寫入任何東西，而「選得起來」正是讀一篇不能改的文章時最需要的能力——選不起來就複製不走。寫作區其他幾把鍵（縮排、粗體、斜體、表格續行）在唯讀時一律不動作，因為**它們每一把都會寫進那一行**；那個理由到不了這一把 |
| 沒有開啟任何文章 | 什麼都不做——空的正文沒有詞、也沒有結構 |
| **好幾個游標，而它們不是每一個旁邊都有詞** | 這一下是「選詞」還是「往外長」，由**寫作者所在的那個游標**決定，整份文件一致。所在的游標有詞 → 每個游標各自取自己的詞，沒有詞的那個維持不動；所在的游標沒有詞 → 全部一起往外長。**旁邊沒有詞的游標就等下一下**——見核心規則 4 之後的說明 |

---

## 5. UI/UX Design & Interaction

- **沒有任何新的畫面元素。** 沒有按鈕、沒有選單列、沒有提示、沒有動畫、沒有聲音。這個功能唯一看得見的東西，就是選取範圍本身變大了。
- **選取範圍的外觀完全沿用既有的。** 「有選取時不畫游標所在行的底色」那條既有規則照樣成立，所以逐層長大的每一層都看得見。
- **應用程式選單**：這個 App 第一次有自己的選單，但它刻意長得跟出廠的一模一樣，只有「關閉視窗」那一列旁邊標示的快速鍵不同。寫作者不該察覺到選單換了主人。
- **空狀態／載入中／錯誤狀態：** 均不適用。這個鍵不讀任何東西、不寫任何東西、不會失敗。

---

## 6. Non-Functional Requirements

- **反應速度：** 按下去到選取改變，寫作者感覺不到延遲。連按不得掉鍵——按五下就要長五層（除非中途已到最外層）。
- **不寫入：** 這個鍵在任何情況下都不得改動正文一個字元，因此也不得在還原歷史裡留下任何一步。
- **輸入法安全：** 組字中一律不動作。這是全 App 對每一個按鍵一律成立的規則，升級外殼或編輯器核心前必須連同既有的輸入法回歸清單一起驗。
- **相容性：** 本版只保證 macOS 上的這組鍵。這個 App 目前只在 macOS 上打包，而這個 App 自己的選單也**只在 macOS 裝上**——其他平台維持出廠選單（連同它的 Control+W），理由見 §7。
- **不新增追蹤事件。** 這個 App 不做任何使用行為蒐集。

## 7. Dependencies & Risks

### Dependencies

- **寫作區核心既有的逐層擴大選取能力。** 不新增任何第三方依賴——這個能力本來就在，只是目前沒有鍵綁著它。
- **「那個詞是哪個詞」的既有答案**，由粗體與斜體鍵所在的切片建立。這次共用它，不另寫一套。
- **應用程式選單**：本切片第一次建立。這是唯一一項真正新增的東西。

### Risks

| 風險 | 影響 | 處置 |
| :--- | :--- | :--- |
| **自己寫選單時漏掉出廠有的一列** | 寫作者發現複製、貼上或還原突然沒反應——比原本的問題嚴重得多 | 以出廠選單為基礎逐列比對；驗收情境明列「標準編輯鍵照舊」「還原重做照舊」「縮放與開發者工具照舊」三條，缺一不可 |
| **Command+W 在某個角落仍然關掉視窗** | 未存的修改連同視窗一起消失 | 焦點在寫作區以外的四種情況（文章清單、對話框、預覽區、組字中）各有一條驗收情境，明確斷言「視窗仍然開著」 |
| **「一層」跳太大或太碎** | 跳太大＝按一下就整段，等於沒有層次；太碎＝按十下還在原地 | 以「連按三下到得了整段」為可驗收的判準，而不是靠感覺 |
| **與輸入法搶鍵** | 組字中誤動選取，選字被打斷 | 沿用全 App 既有的組字規則，並列為驗收情境 |
| **寫作者把「開關預覽面板」那個可自訂的快速鍵設成同一組鍵** | 一次按下同時觸發兩個功能。那個鍵的監聽掛在整個視窗上、不看焦點在哪，所以它會贏在任何地方 | **本切片不處理，但記在這裡。** 這是「這個 App 有一個可自訂的鍵、卻沒有一份鍵位總表」這件事的第一個症狀；要處理就是另一個切片的事（一份總表、設定時擋下已被佔用的組合），不是在這裡加一條特例 |

### 8.1 BRIEF 的三個 Open Decisions，本文件的裁決

| 問題 | 裁決 | 理由 |
| :--- | :--- | :--- |
| **「一層」到底怎麼數** | **不另立一套層次，用正文自己的結構。** 可驗收的判準是「連按三下到得了整段」 | 發明第二套層次就等於要為每一種 Markdown 形狀各回答一次「這算不算一層」，而正文本來就有結構。判準寫成可驗收的次數，才不是感覺 |
| **空行上什麼都不做，是否涵蓋「只有空白的行」** | **涵蓋。** 一行只有空白字元時，同樣什麼都不做 | 寫作者眼中那就是一行空行。兩者行為不同會變成「看起來一樣的兩行，按同一個鍵結果不同」。而且這不必特別寫一條規則——兩者都不屬於任何結構，同一條路自然走到同一個結果 |
| **游標旁邊沒有詞可以選時怎麼辦**（`/architecture` 之前補問的） | **不選詞，直接往外長一層。** 不另外發明「往旁邊找最近的詞」 | 「哪個詞」這條規則與粗體、斜體鍵共用，而它在兩邊都不是字時的答案就是「沒有」。硬補一條往旁邊找，等於在這個 App 裡養出第二套分詞規則，兩把鍵在同一個游標位置會選到不同的東西——那正是這份文件一開始就禁止的 |
| **程式碼區塊裡的「一層」怎麼長** | **照常長，不設特例。** 選到區塊本身之後繼續往外長到整篇 | 粗體鍵避開程式碼是因為它會插入星號、會弄壞程式碼；這個鍵插入不了任何東西。沒有傷害就沒有特例的理由，而一致比特例好記 |
