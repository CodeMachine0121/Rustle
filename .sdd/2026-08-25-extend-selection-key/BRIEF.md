# 逐層擴大選取的快速鍵 — 需求共識

- **切片**：`feature/extend-selection-key`
- **日期**：2026-08-25
- **狀態**：需求已共識，可進 `/prd`

---

## Goal

給寫作區一個鍵，讓寫作者用鍵盤把選取範圍**一層一層往外長**：從游標所在的那個詞，長到它所在的連結或強調，再長到那一段話，再長到整個清單，最後長到整篇文章。今天要選一段有結構的東西只能用滑鼠拖，拖到哪裡算哪裡；有了這個鍵，「選起這整個連結」是一個可以按出來的動作，而不是一次要拖得剛剛好的手勢。

這個鍵是 **Command+W**。它今天被作業系統選單的「關閉視窗」佔著，所以這個切片同時要把那一列的快速鍵讓開，改成 **Shift+Command+W**。

「逐層擴大選取」這件事本身，寫作區的核心早就會做——上一個切片把它原本綁的那個鍵（Command+I）拿去做斜體，並且**刻意讓那個行為退場**。這次是換一個更好按的鍵請它回來，而不是發明新東西。

---

## Requirements

### 一、沒有選取時，第一下選游標所在的那個詞

- 游標停在一個字中間、還沒有選任何東西時，按這個鍵，**先選起那個詞**。
- 中文沒有空白可以分詞，所以「那個詞」實務上是**連續的那一整串中文**，到標點或空白才停。這與粗體／斜體鍵在沒有選取時的判斷是**同一條規則**，兩處不得各有一套答案。
- 游標旁邊**沒有詞可以選**時（緊鄰標點、或停在空行上），這一下**不選詞，直接往外長一層**——與「已經有選取」走同一條路。
- 其結果是：停在**空行**上按下去**什麼都不做**（一行空行不屬於任何結構，外面沒有一層可以長），而停在**標點旁邊**按下去會選起**那一整段話**。這兩件事看起來不同，但它們是同一條規則的兩個結果，而不是兩條規則。

### 二、再按一下，往外長一層

- 每按一次，選取就長成**包住它的下一個結構**：詞 → 它所在的連結或強調 → 那一段話 → 整個清單或整段引言 → 整篇文章。
- 長到一段強調時，**兩邊的記號一起被選進去**——記號是那段強調的一部分，選了字卻沒選記號，接下來要剪下或刪除都會留下半截。
- 寫作者用滑鼠拖出來的一段字，也可以直接用這個鍵**從那一段往外長**，不會先跳回「一個詞」。

### 三、長到最外面就停住

- 整篇文章都被選起來之後再按，**什麼都不做**，維持全選。不繞回最裡面、不縮小、不出聲。
- 寫作者用滑鼠點到別的地方之後，**之前長到哪一層就不算數了**：下一次按這個鍵，從新的位置重新從「那個詞」開始。

### 四、這個鍵只在寫作區有意義

- 焦點不在寫作區時（側欄的文章清單、預覽區、任何對話框的欄位），這個鍵**什麼都不做**。
- 而且在那些地方**視窗一樣不會關掉**——這是這個切片最重要的一條：Command+W 從此不再是任何地方的「關視窗」。
- 寫作者正在用注音、拼音等輸入法組字時**什麼都不做**，選字不受干擾。這是這個 App 對每一個按鍵一律成立的規則，不是這一項的特例。

### 五、關視窗改成 Shift+Command+W

- 系統選單裡「關閉視窗」那一列**留著**，滑鼠點得到，只是旁邊寫的快速鍵改成 **Shift+Command+W**。
- 按 Shift+Command+W 的結果與今天按 Command+W 完全一樣。
- **只動這一格。** 複製、貼上、還原、重做、縮放、開發者工具、結束 App，以及作業系統選單上其餘每一列，全部維持出廠的樣子。這個 App 今天沒有自己的選單，這次第一次有了，而它的職責只是把那一格讓開，不是趁機重新設計選單。

## Examples (Specification by Example)

每個例子只列會影響結果的東西，其餘一概不列。

### Rule 1：沒有選取時，第一下選游標所在的那個詞

| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 游標停在 `important` 的中間 | 按這個鍵 | `important` 整個字被選起來 |
| 2 (happy) | 游標停在「這是重點的地方」的「重」和「點」之間 | 按這個鍵 | **「這是重點的地方」整串中文**被選起來——到標點或空白才停 |
| 3 (boundary) | 游標停在一行**空行**上，旁邊一個字都沒有 | 按這個鍵 | **什麼都不做**。沒有詞可以選，而一行空行外面也沒有一層可以長 |
| 4 (boundary) | 一段話寫著 `today.`，游標停在句號後面 | 按這個鍵 | 沒有詞可以選，所以**直接往外長一層**：**那一整段話**被選起來。標點不會被單獨選成一段 |
| 5 (exception) | 游標在程式碼區塊裡的 `const` 中間 | 按這個鍵 | `const` 被選起來。**程式碼區塊照常運作**——這個鍵只選字、不寫入任何東西，與會插入記號的粗體鍵不同 |

### Rule 2：再按一下，選取往外長一層

| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 一行寫著 `去看 [今天的天氣](https://example.com) 吧`，「天氣」被選起來 | 按這個鍵 | 選取長成 `[今天的天氣](https://example.com)` **整個連結** |
| 2 (happy) | 承上，整個連結被選起來 | 再按一次 | 選取長成**整行那一段話** |
| 3 (happy) | 一個清單裡的某一項，該項整項被選起來 | 按這個鍵 | 選取長成**整個清單** |
| 4 (boundary) | `**重點**` 裡的「重點」被選起來 | 按這個鍵 | 選取長成 `**重點**`，**兩邊的星號一起選進去** |
| 5 (exception) | 寫作者用滑鼠拖了一段字（沒經過這個鍵） | 按這個鍵 | 從**拖出來的那一段**往外長一層，不會先跳回「一個詞」 |

### Rule 3：長到最外面就停住

| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 整篇文章都被選起來了 | 再按一次 | **什麼都不做**，維持全選。不繞回去、不縮小 |
| 2 (boundary) | 整篇文章只有一行字，游標在那個詞裡 | 連按很多次 | 一路長到整行後停住，之後每一次都什麼都不做 |
| 3 (boundary) | 選取正在中間某一層，寫作者用滑鼠點了別的地方 | 再按這個鍵 | 從**新的游標位置**重新選那個詞——之前長到哪一層不算數了 |

### Rule 4：什麼時候這個鍵不動作

| # | Given | When | Then |
|---|---|---|---|
| 1 (exception) | 寫作者正在用注音選字，還沒選完 | 按這個鍵 | **什麼都不做**，選字不受干擾 |
| 2 (exception) | 焦點在側欄的文章清單上 | 按這個鍵 | **什麼都不做**，而且**視窗不會關掉** |
| 3 (exception) | 建立文章的對話框開著，焦點在標題欄位 | 按這個鍵 | **什麼都不做**，視窗不會關掉 |
| 4 (exception) | 焦點在預覽區 | 按這個鍵 | **什麼都不做**，視窗不會關掉 |

### Rule 5：關視窗改成 Shift+Command+W

| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | App 開著 | 按 **Shift+Command+W** | 視窗關閉，結果與今天按 Command+W 完全一樣 |
| 2 (happy) | 寫作者打開系統選單找「關閉視窗」 | 看那一列 | 那一列還在，旁邊寫的快速鍵是 **Shift+Command+W** |
| 3 (boundary) | 寫作者按 Command+Q | — | App 結束，這條路徑一個字都沒變 |
| 4 (boundary) | 寫作者按複製、貼上、還原、縮放、開發者工具 | — | **全部照舊**。這次只動「關閉視窗」那一格 |

## Out of Scope

| 不做 | 為什麼 |
| :--- | :--- |
| **「縮回來」的反向鍵** | 明確不做。只做往外長；按過頭就重按一次游標。反向要記住每一層的歷史，工作量約翻倍，而寫作者有更便宜的出路 |
| **選單文字跟著介面語言切換** | 這個 App 第一次有自己的選單，這次只負責把一格快速鍵讓開。選單要不要說中文是另一件事 |
| **重新設計選單有哪幾列** | 維持出廠的樣子。每砍一列就可能砍掉一個作業系統使用者預期的標準行為 |
| **這個鍵可以自訂** | 這個 App 已經有一個可以改的快速鍵（開關預覽面板那個），所以「開先例」不是理由——真正的理由是沒有人要求，而多一個可改的鍵就多一種寫作者把兩個功能設成同一個鍵的方式 |
| **滑鼠或觸控板上的對應手勢** | 沒有要求。這是一個鍵盤動作 |
| **選取範圍的顏色與外觀** | 既有切片已經處理過「選取一定看得見」，這次不動 |
| **正文檔案、前置資料、檔名、圖片資料夾** | 一律不因這個切片而不同。這個鍵一個字都不寫進文章 |
| **預覽區裡的選取** | 預覽區是拿來看的，這個鍵在那裡什麼都不做 |

## Open Decisions

留給 PRD 作者決定：

- **「一層」到底怎麼數**：詞與整段話之間，有哪些層是寫作者感覺得到的、哪些是多餘的中間站。判準是「連按三下應該要到得了整段」，而不是「按了六下還在原地附近」。
- **空行上什麼都不做，是不是也涵蓋「只有空白的行」**：一行裡只有幾個空白字元，看起來是空的但實際上不是。
- **程式碼區塊裡的「一層」怎麼長**：程式碼在文章裡是一整塊，中間的結構不是 Markdown 的。長到區塊本身就停，還是照樣往外長到整篇。

## Context / Background

- **這個能力不是新造的。** 寫作區的核心本來就會逐層擴大選取，而且原本綁在斜體那個鍵上；`feature/editing-surface-marks-and-emphasis` 把那個鍵改成斜體，並在文件裡寫明那個行為是**刻意退場**的。這次是換一個鍵請它回來，不是重新發明。
- **「那個詞是哪個詞」有現成的答案。** 粗體與斜體鍵在沒有選取時，已經要回答同一個問題，並且已經決定中文的答案是「連續的那一整串」。兩處必須是同一條規則，不能各有一套。
- **這個 App 今天沒有自己的選單。** 用的是作業系統給的出廠選單，Command+W 就在裡面。所以「搶下這個鍵」不是攔截一次按鍵，而是這個 App 第一次擁有自己的選單——這也是為什麼「其餘每一列維持原樣」是一條需求而不是一句廢話：一份自己的選單只要漏寫一列，寫作者就會發現複製或貼上突然沒反應。
- **只有一個視窗。** 關掉它之後 App 仍然留在系統的常駐列上，這一點不因這次改動而不同。
