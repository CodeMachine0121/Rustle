## 1. Background & Goal

### Problem Statement

Rustle 已經有 Vim 模式，但**它的剪貼簿是一座孤島**。

寫作者在寫作區用 Vim 的按鍵複製走一段文字，切到瀏覽器、通訊軟體或任何其他 App 按貼上——什麼都沒有出來，貼出來的是十分鐘前用標準複製鍵複製的舊東西。反過來，在網頁上複製一段字回到寫作區按 Vim 的貼上鍵，貼出來的也不是剛剛複製的那一段。

於是寫作者每一次複製都得先想一件事：**「我等一下要在哪裡貼？」** 要在 Rustle 裡貼就用 Vim 的鍵，要拿出去貼就得改用標準複製鍵——而標準複製鍵需要先用滑鼠或方向鍵選好範圍，Vim 模式存在的理由（手不離開字母區）當場作廢。

這不是一個「缺少的功能」，而是**一個已交付功能的破口**：Vim 模式承諾「手不離開字母區就能操作文字」，而文字的進出是操作文字裡最常做的一件事。

### Expected Outcome

**複製就是複製，不分哪一套鍵。** 開著 Vim 模式時：

1. 用 Vim 的鍵複製或刪掉的文字，**切到任何其他 App 立刻貼得到**。
2. 在任何其他 App 複製的文字，**回到寫作區按 Vim 的貼上鍵立刻貼得進來**。
3. 具名暫存格**仍然各自獨立**——把東西放旁邊別被蓋掉這件事沒有被犧牲。
4. 專門用來「刪掉不留痕跡」的垃圾桶暫存格**仍然不留痕跡**。
5. **Vim 模式關著的人，App 與今天完全相同**；設定畫面也**不多任何一項**。

### Out of Scope

- **圖片。** 系統剪貼簿上的圖片一律不由 Vim 的貼上鍵處理。把圖片貼進文章的方式與今天完全相同。
- **新的設定項。** 相通行為跟著 Vim 模式一起開關，沒有第二個開關。
- **快捷鍵總覽那張表。** 既有規則是「Vim 的按鍵不列進去」；本切片沒有新增任何這個 App 自己教的鍵，所以那張表一列都不動。
- **Vim 的指令列與搜尋。** 沿用上一個切片的範圍決定。
- **跨裝置／雲端剪貼簿。** 只談這台機器上的系統剪貼簿。
- **剪貼簿歷史。** 系統剪貼簿只有「現在這一份」，本切片不做多筆保存。

## 2. User Personas

- **主要角色：開著 Vim 模式的寫作者。** 他每天在 Rustle 寫文章，同時開著瀏覽器查資料、開著通訊軟體。文字在 Rustle 與外面之間**雙向流動是他的日常**：從網頁上抄一段引文進來、把寫好的一段貼到通訊軟體給人看。
- **次要角色（必須不受影響）：沒開 Vim 模式的寫作者。** 他完全不知道有這件事，而且應該繼續不知道。
- **使用情境：** 本機桌面 App，單一視窗，寫作中。**視窗會頻繁失焦與回焦**——因為「去別的 App 複製東西再回來」正是本切片要服務的動作。

## 3. User Stories & Acceptance Criteria

### US-01 — 把寫作區的文字帶出去 [priority: P0]

**As a** 開著 Vim 模式的寫作者，**I want** 用 Vim 的鍵複製或刪掉的文字自動進到系統剪貼簿，**so that** 我可以直接切到別的 App 貼上，不必為了「要拿出去」而改用另一套鍵重選一次範圍。

```gherkin
Scenario: 複製一段文字，其他 App 貼得到
  Given Vim 模式開著
  And 寫作區反白了「台積電」
  When 寫作者按 `y`
  Then 系統剪貼簿的內容是「台積電」
  And 切到其他 App 按貼上會出現「台積電」

Scenario: 複製一整行，換行一起帶走
  Given Vim 模式開著
  And 游標停在內容為「今日盤後觀察」的那一行
  When 寫作者按 `yy`
  Then 系統剪貼簿的內容是「今日盤後觀察」加上一個換行

Scenario: 刪掉一整行也算剪下
  Given Vim 模式開著
  And 游標停在內容為「今日盤後觀察」的那一行
  When 寫作者按 `dd`
  Then 系統剪貼簿的內容是「今日盤後觀察」加上一個換行
  And 那一行已從文章裡消失

Scenario: 刪掉單一個字元也算剪下
  Given Vim 模式開著
  And 游標停在「電」這個字上
  When 寫作者按 `x`
  Then 系統剪貼簿的內容是「電」

Scenario: 改寫一段文字，被換掉的原文帶得走
  Given Vim 模式開著
  And 寫作區反白了「聯電」
  When 寫作者按 `c` 並輸入「台積電」
  Then 系統剪貼簿的內容是「聯電」
  And 文章裡那一段變成「台積電」

Scenario: 存進具名暫存格的文字也送出去
  Given Vim 模式開著
  And 寫作區反白了「聯電」
  When 寫作者按 `"ay`
  Then 系統剪貼簿的內容是「聯電」
  And 具名暫存格 a 的內容也是「聯電」

Scenario: 垃圾桶暫存格什麼都不留，連現有的都不動
  Given Vim 模式開著
  And 系統剪貼簿的內容是「https://example.com/報告」
  When 寫作者按 `"_dd` 刪掉一整行
  Then 系統剪貼簿的內容仍然是「https://example.com/報告」
  And 那一行已從文章裡消失

Scenario: Vim 內部歸零暫存格時，系統剪貼簿原封不動
  Given Vim 模式開著
  And 系統剪貼簿的內容是「昨天複製的東西」
  When Vim 因為自己的緣故把預設暫存格歸零
  Then 系統剪貼簿的內容仍然是「昨天複製的東西」

Scenario: Vim 模式關著時，本規則完全不適用
  Given Vim 模式關著
  And 系統剪貼簿的內容是「昨天複製的東西」
  When 寫作者用滑鼠選了一段文字並按下退格鍵刪掉它
  Then 系統剪貼簿的內容仍然是「昨天複製的東西」
```

**As a** 開著 Vim 模式的寫作者，**I want** Vim 的貼上鍵貼出系統剪貼簿上現在那一份，**so that** 我從網頁抄一段引文進文章時手不必離開字母區。

```gherkin
Scenario: 其他 App 複製的文字，Vim 的貼上鍵貼得進來

  And 寫作者剛在瀏覽器複製了「營收成長」
  When 寫作者回到寫作區按 `p`
  Then 文章裡出現「營收成長」

Scenario: 最後一次複製的贏
  Given Vim 模式開著
  And 寫作者先在寫作區按 `y` 複製了「台積電」

  When 寫作者回到寫作區按 `p`

Scenario: 具名暫存格不讀系統剪貼簿
  Given Vim 模式開著

  And 系統剪貼簿的內容是「營收成長」
  When 寫作者按 `"ap`
  Then 文章裡出現「聯電」
  And 「營收成長」沒有出現

Scenario: 以換行結尾的文字用整行的方式貼
  Given Vim 模式開著

  And 游標停在某一行的中間

Scenario: 系統剪貼簿是空的，什麼都不做
  Given Vim 模式開著
  And 系統剪貼簿是空的

  When 寫作者按 `p`
  Then 文章的內容一個字都沒變

  When 寫作者按 `p`
  Then 那些文字以一般的方式貼入，不是方塊

Scenario: 剛自己複製的東西，立刻貼得回來
  Given Vim 模式開著
```

## 4. Business Flow & Logic

### 出去的那一半

```
寫作者按下任何一個「會拿走文字」的 Vim 鍵
        │  （複製、刪除、改寫，含具名暫存格）
        ▼
Vim 把被拿走的文字放進它的暫存格
        │
        ├── 用的是垃圾桶暫存格 ──▶ 到此為止，系統剪貼簿一個字都不動
        │
        ▼
同一份文字寫進系統剪貼簿（覆蓋原有內容）
```

### 進來的那一半

```
寫作者按下 Vim 的貼上鍵
        │
        ├── 指定了具名暫存格 ──▶ 貼出那一格自己的內容，不看系統剪貼簿
        │
        ▼
讀系統剪貼簿現在那一份文字
        │
        ├── 沒有文字（空的，或只有圖片）──▶ 什麼都不做，文章不變
        │
        ▼
以換行結尾？──是──▶ 用整行的方式貼（成為獨立的行）
        │
        否
        ▼
用一段的方式貼（插在當前行裡）
```

### Core Business Rules

| # | 規則 | 說明 |
| :-- | :--- | :--- |
| BR-1 | **出去全送，進來只有預設那一格** | 任何會拿走文字的 Vim 操作都更新系統剪貼簿，含存進具名暫存格的那些。但貼上時，只有「沒有指定暫存格」的貼上讀系統剪貼簿；指定了具名暫存格就讀那一格自己的。**理由**：具名暫存格的用途是「放旁邊別被蓋掉」，若進來也全讀系統剪貼簿，所有具名暫存格會拿到同一份內容，等於全部消失。 |
| BR-2 | **垃圾桶暫存格是唯一的例外，而且是雙向的例外** | 用它刪東西時系統剪貼簿完全不動——不是清空，是**原封不動**。 |
| BR-3 | **在 Vim 的語言裡，刪除就是剪下** | 刪一整行、刪單一個字元、改寫一段，被拿走的文字都算複製。這是 Vim 世界的既有語意，不是本切片新定的。 |
| BR-4 | **最後一次複製的贏，不分是誰複製的** | 系統剪貼簿只有一份現值。Rustle 裡的 Vim 複製與其他 App 的複製寫的是同一份，後寫的覆蓋前寫的。 |
| BR-5 | **「整行還是一段」由換行結尾決定** | 系統剪貼簿只能承載文字，承載不了「這是整行」這個標記。所以讀回來時以「文字是否以換行結尾」為判準。Rustle 自己的整行複製本來就以換行結尾，因此原地往返永遠正確；外面來的文字也有一個合理且可預期的判準。 |
| BR-6 | **沒有文字就什麼都不做，而且是安靜的** | 系統剪貼簿空的、或只有圖片時按 Vim 的貼上鍵，文章不變，**且不給任何提示**——Vim 本身在這種情況也是安靜的，多一個提示會讓寫作者以為出了錯。 |
| BR-6a | **「方塊」是這個 App 自己複製出來的那一份才有的性質** | 系統剪貼簿只承載文字，沒有地方放「這幾行是一個方塊」這個標記。所以**在這裡取走的方塊，貼回這裡仍是方塊**；**從別處來的文字永遠不是方塊**。**理由**：不處理它會讓上一個切片已交付的方塊貼上退化成整行貼上——那是既有行為的損壞，不是本切片的取捨。跨 App 的方塊貼上不在本切片範圍。 |
| BR-6b | **Vim 內部歸零暫存格，不等於寫作者要清空剪貼簿** | Vim 因為自己的緣故把預設暫存格歸零時，系統剪貼簿**原封不動**。**理由與 BR-2 同一條**：清空也是一種痕跡，而寫作者沒有要求它。 |
| BR-7 | **相通行為的存在與否，等於 Vim 模式的開關** | 沒有第二個設定。Vim 模式關著時，本切片的任何規則都不適用。 |
| BR-8 | **圖片一律不經過這條路** | 系統剪貼簿上的圖片由既有的貼上圖片行為處理，開關 Vim 模式都不影響它。Vim 的貼上鍵只看文字。 |

### Edge Cases

| 情況 | 期待行為 |
| :--- | :--- |
| 系統剪貼簿是空的 | Vim 的貼上鍵什麼都不做，文章不變，無提示（BR-6） |
| 系統剪貼簿只有圖片、沒有文字 | 同上（BR-6、BR-8） |
| 系統剪貼簿的文字非常長（例如整篇文章） | 照常貼上。不設長度上限，不截斷，不提示 |
| 系統剪貼簿的文字含多個換行 | 照常貼上，以最後一個字元是否為換行決定貼法（BR-5） |
| 剛按了複製，立刻按貼上（系統剪貼簿的寫入可能還沒完成） | **必須貼出剛複製的那一份**。寫作者的操作不能被系統剪貼簿的寫入速度絆住 |
| 視窗失焦去別的 App 複製東西後回來 | **回來之後第一次按貼上就要拿到新的那一份**（US-02「最後一次複製的贏」） |
| 讀寫系統剪貼簿失敗（作業系統拒絕、剪貼簿被別的程式鎖住） | **不能讓寫作動作跟著失敗。** 讀失敗時視為「沒有文字」（BR-6）；寫失敗時 Vim 自己的暫存格照樣完成，文章的編輯照樣完成 |
| 打開另一篇文章 | 系統剪貼簿不受影響——它屬於作業系統，不屬於某一篇文章 |
| 輸入法組字中 | 沿用既有規則：組字中一律不接按鍵。本切片不新增例外 |
| 唯讀的文章 | 複製與刪除的既有可行性不變；本切片不改任何一個鍵在唯讀時能不能按 |

---

## 5. UI/UX Design & Interaction

**這個切片沒有畫面。** 完整說明如下，因為「沒有畫面」在這裡是需求本身：

- **設定畫面不多任何一項**（US-03）。
- **狀態列不多任何一格**。模式指示那一格與今天完全相同。
- **快捷鍵總覽那張表一列都不動**。
- **成功時沒有任何回饋。** 複製成功不閃、不亮、不提示——剪貼簿本來就是無聲的，一個「已複製」的提示在每按一次 `x` 都會出現，會比沒有更糟。
- **失敗時也沒有任何回饋**（BR-6、Edge Cases）。
- **沒有載入中狀態。** 讀寫系統剪貼簿在寫作者的感受上必須是即時的；不存在需要等待的畫面。

## 6. Non-Functional Requirements

- **即時性（最硬的一條）：** 按下 Vim 的貼上鍵到文字出現在文章裡，**寫作者感受不到延遲**。「先讀系統剪貼簿、讀完再貼」這種需要等待的做法不可接受——貼上是連續操作的一環（`p` 之後可能立刻接 `.` 重複），中間出現任何等待都會破壞 Vim 的節奏。
- **不絆住編輯：** 寫進系統剪貼簿這件事**永遠不能延後或阻擋文章的編輯**。按 `dd`，那一行要立刻消失，不等剪貼簿。
- **失敗不外溢：** 系統剪貼簿讀或寫失敗，寫作區必須照常運作（見 Edge Cases）。
- **不打開的人零成本：** Vim 模式關著時，本切片不應產生任何持續進行的工作。
- **相容性：** 三個平台（macOS／Windows／Linux）行為一致；不為任何平台加特例。
- **Analytics：** 無。本專案不做行為追蹤。

## 7. Dependencies & Risks

### External Dependencies

- **作業系統的剪貼簿。** 屬於本機作業系統，唯一的外部資源。
- **既有的 Vim 模式。** 本切片建立在上一個切片交付的 Vim 模式之上，不改它任何一條既有承諾（特別是「既有快速鍵一律優先」）。
- **既有的貼上圖片行為。** 本切片必須不影響它（US-03）。

### Known Risks

| 風險 | 影響 | 對策 |
| :--- | :--- | :--- |
| **「剛複製立刻貼上」與「回焦後拿到新的」是兩個互相拉扯的要求** | 前者要求貼上不等待，後者要求貼上拿到的是最新的。兩者若沒有一起設計，會做出「快但是舊」或「新但是慢」 | 兩條都寫成驗收情境（US-02 的「最後一次複製的贏」與「剛自己複製的東西，立刻貼得回來」），任一條不過就是不合格 |
| **相通行為破壞既有的貼上圖片** | 圖片貼不進文章，是一個既有功能的退化 | US-03 兩條情境把「Vim 開與關之下圖片都照舊」都釘住 |
| **相通行為破壞具名暫存格** | 澄清過程中已經出現過這個矛盾（見 BRIEF 的 Context）。若做成雙向全通，所有具名暫存格會合成一格 | BR-1 明文寫下「出去全送、進來只有預設那一格」，並以 US-02 的具名暫存格情境釘住 |
| **垃圾桶暫存格的語意被破壞** | 寫作者用它是為了不留痕跡，一旦送出去等於這個工具消失 | BR-2 與 US-01 的情境把「連現有的內容都不能動」釘住——不是清空，是原封不動 |
