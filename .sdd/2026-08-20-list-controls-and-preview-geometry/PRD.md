# 需求規格 — 清單控制與預覽幾何

- **切片**：Wave 4，`feature/list-controls-and-preview-geometry`
- **覆蓋需求**：FR-2.2、FR-2.4、FR-5.6、FR-5.8；橫切 FR-8.6、FR-8.7（篩選框與分隔線的鍵盤）、NFR-3、NFR-5
- **共識來源**：[BRIEF.md](BRIEF.md)（假設一律以該檔第 7 節為準）
- **詞彙**：通用語言地圖

---

## 1. 目標

讓欄 2 在文章變多之後仍然找得到東西（排序＋即時篩選），並讓預覽面板的幾何是活的（寬度可拖曳並記住、兩欄捲動對到同一段內容）。四條需求都只動畫面：**沒有任何一條會改變磁碟上的文章**。

## 2. User Stories

| # | 身為 | 我想要 | 以便 |
| :--- | :--- | :--- | :--- |
| US-1 | 寫作者 | 一打開 workspace 就看到最近建立的文章在最上面 | 接著寫昨天那篇不用找 |
| US-2 | 寫作者 | 把清單切成按標題或按最近更新排 | 用「我記得標題開頭」或「我記得剛改過」兩種方式找 |
| US-3 | 寫作者 | 在欄 2 上方打幾個字就把清單縮小 | 幾百篇裡直接跳到相關的那幾篇 |
| US-4 | 用注音／拼音打字的寫作者 | 在篩選框打中文而候選視窗不受干擾 | 篩選跟編輯區一樣可靠 |
| US-5 | 寫作者 | 拖曳編輯區與預覽之間的分隔線，並且下次還是那個寬度 | 依文章型態（多圖／多程式碼）調整版面一次就好 |
| US-6 | 寫長文的寫作者 | 捲動任一邊時另一邊跟到同一段內容 | 一邊寫一邊看成品，而不是看成品的別的段落 |
| US-7 | 建立文章對話框（既有切片） | 拿到整個 workspace 的文章，不論欄 2 正在篩什麼 | 自動補全候選不會在最需要的時候縮小 |

## 3. 業務流程

### 3.1 欄 2 畫哪幾列

```
負責檔案存取的那一層給的文章列（整個 workspace）
        │
        ├───────────────▶ 建立文章對話框的自動補全候選（永遠是整份）
        │
        ▼
   套用篩選字串（比對 title / category / tags）
        │
        ├─ 正在編輯的那篇被篩掉了？ → 仍然保留它那一列，並標示「開著的」
        │
        ▼
   套用排序方式（建立時間新到舊 / 標題 / 更新時間新到舊）
        │
        ▼
   畫出來的列
```

「選取的是哪一篇」不在這條流程上：它由畫面層的狀態持有，篩選與排序都不寫它。

### 3.2 一次篩選的輸入

```
按鍵 ──▶ 篩選框立刻顯示這個字（畫面永遠等於寫作者打的字）
            │
            ├─ 組字中？ ──▶ 倒數暫停（清單完全不動）
            │
            └─ 停手 150ms ──▶ 套用篩選字串
                              │
   Enter（沒在組字）──────────┘（不等倒數，立刻套用）
   Enter（組字中）──▶ 什麼都不做，也不攔掉這次按鍵（它屬於輸入法）
   Esc（沒在組字）──▶ 清空並立刻套用
   Esc（組字中）──▶ 什麼都不做
```

### 3.3 一次拖曳

```
pointerdown 在分隔線上 ──▶ 記下起點與「編輯＋預覽」的總寬
        │
        ▼
pointermove ──▶ 由位移算出新比例（夾限 20%~80%）──▶ 畫面立刻套用（不寫檔）
        │
        ▼
pointerup ──▶ 把當前比例寫進 .rustle/settings.json（其他設定欄位原樣保留）
```

### 3.4 一次捲動同步

```
寫作者捲動 A 面（編輯區或預覽）
        │
        ▼
A 面回報「我最上面現在是正文第幾行」（可含小數）
        │
        ▼
B 面被寫入「把那一行放到最上面」對應的捲動位置
        │  （對照依據：預覽側是每個區塊上的 data-line 與它的實際像素位置）
        ▼
B 面因為被寫入而發出一次捲動事件
        │
        ▼
同步器認出這一次是自己造成的（位置與剛才寫進去的相符）→ 吃掉，流程結束
```

「吃掉」只吃一次，且**不看時間**：位置不符（寫作者真的又捲了 B 面）就當成一次真的捲動，換 B 面當主動方。

## 4. 驗收標準（Gherkin）

「清單」指欄 2 畫出來的文章列；「選取的文章」指編輯區當前開著、儲存機制綁著的那一篇。

### Feature：捲動同步（FR-5.8、§7.4）

「行號」一律是**正文的 0 起算行號**，也就是預覽切片寫在區塊上的那個值。

預覽側的共同輸入（一份會讓純比例捲動出錯的幾何）：

| 區塊的行號 | 區塊在預覽裡的上緣 |
| :--- | :--- |
| 0 | 0px |
| 10（一張高圖） | 200px |
| 11 | 800px |
| 20 | 980px |
| 可捲動總高 1500px，可見高度 300px | |

# TC-50

  那麼 編輯區被要求把第 12 行放到最上面

# TC-51
場景: 一次捲動就停下來
  假設 編輯區與預覽都接上了同步
  並且 預覽只能停在區塊的上緣（所以它跟隨之後回報的行號與編輯區的不同）
  當 寫作者捲動編輯區一次
  那麼 預覽被要求跟隨一次
  並且 編輯區完全沒有被要求捲動（寫作者正在看的那一欄不會跳）

# TC-52
場景: 跟隨之後，寫作者真的捲動那一邊仍然有效
  假設 編輯區捲動過一次、預覽已經跟隨過
  當 寫作者接著自己捲動預覽到別的位置
  那麼 編輯區跟到預覽的行號

# TC-53
場景: 只有一邊在的時候什麼都不做
  假設 只有編輯區接上了同步（預覽面板收合著）
  當 編輯區捲動
  那麼 沒有任何一邊被要求捲動
  並且 沒有丟出錯誤

# TC-54
場景: 跟隨方其實沒有動時，不留下任何「這是我造成的」記錄
  假設 編輯區與預覽都接上了同步
  並且 預覽已經在對應的位置上（跟隨之後位置沒有改變）
  當 寫作者接著自己捲動預覽
  那麼 編輯區跟到預覽的行號
  （沒有動就不會有回音事件，留著記錄反而會吃掉寫作者的下一次捲動）

# TC-55
場景: 面板收起來之後不再同步
  假設 編輯區與預覽都接上了同步
  當 預覽那一邊被卸下（面板收合或文章關閉）
  並且 編輯區捲動
  那麼 沒有任何一邊被要求捲動

# TC-56
場景: 編輯區把「最上面是第幾行」算成含小數的行號

  當 問編輯區最上面是第幾行
  那麼 答案是那一行加 0.5

# TC-57

  當 要編輯區把第 7 行放到最上面
  那麼 編輯區被捲到與文件高度 140px 相對應的位置

## 5. 不做（範圍邊界）

見 [BRIEF.md](BRIEF.md) 第 4 節。其中三條在 review 時最容易被誤判成「漏做」，在此重述：

1. **不做全文搜尋**（FR-2.4 明文）。比對範圍就是 `title` / `category` / `tags` 三者，檔名與正文都不算。
2. **篩選字串與排序方式不跨重啟保留**（假設 A-3）。設定檔記的是「寫作者在哪」，不是「上次找到一半」。
3. **捲動同步不是比例捲動**（§7.4）。任何以「捲動位置 ÷ 總捲動高度」比例為基礎的實作都不符合這份規格。
