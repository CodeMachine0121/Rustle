# 需求共識 — 清單控制與預覽幾何

- **切片**：Wave 4，`feature/list-controls-and-preview-geometry`
- **日期**：2026-08-20
- **輸入**：需求文件 §4.1（版面示意圖裡欄 2 上方那個 `🔍 篩選…` 方框）、§4.3（FR-2.2、FR-2.4）、§4.6（FR-5.6、FR-5.8）、§6.2（FR-8.6、FR-8.7）、§6.3（T-8、T-9）、§7.4（「捲動同步的假象」那一列）、NFR-3、NFR-5
- **狀態**：需求已定案（v0.3），本階段不回頭問使用者。需求文件留白處由本檔第 7 節裁決，並同步寫進 PR 說明

## 1. 這個切片要解決的問題

這是刻意的**兩組不相關需求併成一條**（交付計畫「波次順序的修正紀錄」已記錄理由：兩組都小、都只動畫面層、彼此不重疊，而每個切片各自跑完五階段是固定開銷）。所以「要解決的問題」也是兩個：

**A. 欄 2 現在只會照負責檔案存取的那一層給的順序把文章全部列出來。** 一個 workspace 到了 30 篇就開始找不到東西，到了 500 篇（NFR-3 明說的規模）就是一面牆。寫作者需要兩件事：**排序**（我剛寫的在最上面，或按標題找，或看我最近改過哪些）與**即時篩選**（打三個字就把清單縮到剩相關的幾列）。

**B. 預覽面板已經在第四欄，但它的幾何是死的。** 寬度是固定的一半一半，而且兩邊的捲軸各自為政——文章一長，右邊顯示的段落跟左邊在寫的段落完全不是同一段，預覽就從「看得到成品」退化成「看得到某段成品」。

B 的難處只有一個，而且需求文件已經替我們指出來了（§7.4）：**純比例捲動是假的**。左邊 50% 的行數不等於右邊 50% 的像素高度——一張高圖、一段長 code block、一張長表格都會讓兩邊差上整個畫面。真正的對照依據是預覽切片已經寫在每個區塊上的正文行號（`data-line`）。

## 2. 對誰有價值

| 角色 | 拿到什麼 |
| :--- | :--- |
| 使用者（每天寫、workspace 會長到幾百篇） | 打幾個字就找到那一篇；想按標題或按最近改動看就切一下；不必記得檔名 |
| 使用者（寫長文，一邊寫一邊看成品） | 兩邊永遠在同一段內容上；預覽寬一點窄一點自己拉，下次開 App 還是那個寬度 |
| 使用者（用注音／拼音打字） | 篩選框裡打中文，候選視窗照樣貼齊、`Enter` 只是選字；組字中不會一個字篩一次 |
| 建立文章對話框（既有切片） | 自動補全候選不受篩選影響——它拿到的仍然是整個 workspace 的文章 |
| Metadata 編輯／破壞性操作切片 | 欄 2 的「畫哪幾列」與「這個 workspace 有哪些文章」已經分開了，刪除一篇之後不必擔心篩選狀態把它藏成別的意思 |

## 3. 成功的樣子（可觀察的行為）

1. 選一個 workspace → 文章由**新到舊**列出（`created_at`），最上面那篇是最近建立的。
2. 把排序切成「標題」→ 同一批文章重新排；**正在編輯的那篇仍然是選取狀態，編輯區沒有換文章**。
3. 在篩選框打 `tauri` → 清單只剩標題／分類／標籤裡有 `tauri` 的文章；清空篩選框 → 全部回來。
4. 篩選框打的字**只比對標題、分類、標籤**。正文裡有那個字、或檔名裡有那個字，都不算符合。
5. 篩選把「正在編輯的那篇」篩掉時，**那一列仍然留在畫面上並標示著它是開著的那篇**，而且編輯區、儲存機制指向的文章一個都沒變。
6. 用注音在篩選框打「台積電」：組字期間清單不動，選完字之後才篩；`Enter` 只是確定選字，不會做任何別的事；候選視窗不必等任何倒數。
7. 沒有任何文章符合篩選 → 清單區說「沒有符合的文章」，而**不是**「建立第一篇文章」（那是另一件事）。
8. 拖曳編輯區與預覽之間的分隔線 → 兩欄寬度即時跟著走；放手之後關掉 App 再開 → 還是那個寬度。
9. 把分隔線一路往左（或往右）拖到底 → 兩邊都還在，誰都沒有被拖成 0 寬（要收掉預覽有它自己的開關）。
10. 捲動編輯區 → 預覽跟到**同一段內容**，即使那一段前面有一張佔半個畫面的圖或 40 行 code block。反向捲動預覽 → 編輯區跟到同一段。
11. 捲一下編輯區之後，兩邊**停下來**：不會互相追著跑、不會抖、寫作者正在看的那一欄不會被自己觸發的同步彈開。

## 4. 邊界：本切片明確不做

| 不做 | 為什麼／誰做 |
| :--- | :--- |
| **全文搜尋**（比對正文） | FR-2.4 明文「本版不做全文搜尋」。做了就是超出範圍，不是加分 |
| 篩選字串的進階語法（`category:技術`、多關鍵字 AND／OR、模糊匹配、拼音首字母） | 需求沒有要求；一個框一個子字串就是規格 |
| 排序方向可切換（升／降）、多欄排序 | FR-2.2 只點名三種順序，每一種的方向由它自己的語意決定（見假設 A-2） |
| 篩選字串與排序方式**跨重啟保留** | 需求沒有要求。理由見假設 A-4 |
| 欄 1／欄 2 之間、欄 2／欄 3 之間的分隔線也可拖曳 | FR-5.6 只說「編輯區與預覽面板之間」 |
| 預覽面板的收合／展開、快捷鍵、可見狀態持久化 | 預覽切片已交付。本切片只加「寬度比例」 |
| 捲動同步的細粒度（同步到字元、或到區塊內的段落中段以上的精度） | 對照依據是行號，精度就是行號的精度。見假設 B-3 |
| 捲動位置跨重啟保留、跨文章記住捲動位置 | 需求沒有要求 |
| 預覽裡點一個區塊就把編輯區游標移過去（click-to-locate） | 需求沒有要求；`data-line` 讓它以後很便宜，但不是現在 |
| 500 篇的清單虛擬捲動（windowing） | NFR-3 要的是「不卡」，先量再說。實測見 PR 說明；量不過才需要它 |

## 5. 例子（正常／邊界／例外）

### 5.1 排序（FR-2.2）

以下四篇文章為共同輸入：

| 檔名 | title | created_at | updated_at |
| :--- | :--- | :--- | :--- |
| `a.md` | Zen of Writing | 2026-08-18T09:00:00+08:00 | 2026-08-20T18:00:00+08:00 |
| `b.md` | Tauri 與 Electron | 2026-08-20T00:30:00+08:00 | 2026-08-20T01:00:00+08:00 |
| `c.md` | Alpha | 2026-08-19T22:00:00+08:00 | 2026-08-19T22:00:00+08:00 |
| `d.md` | Beta | （空字串） | （空字串） |

| # | 情境 | 順序 | 結果 |
| :--- | :--- | :--- | :--- |
| 1 | 正常（預設） | 建立時間新到舊 | `b`、`c`、`a`、`d` |
| 2 | 正常 | 標題 | `Alpha`、`Beta`、`Tauri 與 Electron`、`Zen of Writing` |
| 3 | 正常 | 更新時間新到舊 | `a`、`b`、`c`、`d` |
| 4 | 邊界 | 建立時間新到舊，其中一篇沒有時間（`d`） | 沒有時間的排在最後，不是最前 |
| 5 | 邊界 | 兩篇時間一模一樣 | 以標題定序，所以同一批文章每次畫出來的順序都一樣（不會跳動） |
| 6 | 邊界 | 兩篇時間寫在不同時區（`+08:00` 與 `Z`） | 比的是同一個瞬間，不是字串。`2026-08-19T20:00:00Z` 晚於 `2026-08-20T00:30:00+08:00` 就要排在它前面 |
| 7 | 例外 | 時間字串不是時間（`不知道`） | 當成沒有時間：排最後，不丟錯 |
| 8 | 例外 | 換排序方式 | **檔案一個都沒被動到**（沒有寫檔、沒有更新 `updated_at`） |

### 5.2 篩選（FR-2.4）

以下為共同輸入：`Tauri 與 Electron`（分類 `技術筆記`，標籤 `tauri`、`electron`）、`Zen of Writing`（分類 `隨筆`，無標籤）、`日常`（無分類無標籤，檔名 `tauri-note.md`）。

| # | 情境 | 打進篩選框 | 剩下 |
| :--- | :--- | :--- | :--- |
| 1 | 正常：比對標題 | `Zen` | `Zen of Writing` |
| 2 | 正常：比對分類 | `技術` | `Tauri 與 Electron` |
| 3 | 正常：比對標籤 | `electron` | `Tauri 與 Electron` |
| 4 | 正常：不分大小寫 | `ELECTRON` | `Tauri 與 Electron` |
| 5 | 正常：清空 | （空） | 三篇都在 |
| 6 | 邊界：只打空白 | `   ` | 三篇都在（空白不是條件） |
| 7 | 邊界：前後有空白 | ` Zen ` | `Zen of Writing` |
| 8 | 邊界：沒有任何一篇符合 | `xyz` | 一列都不剩，並且畫面說「沒有符合的文章」 |
| 9 | **例外：比對範圍** | `tauri`（`日常` 的**檔名**裡有它） | 只有 `Tauri 與 Electron`——檔名不算 |
| 10 | 例外：篩掉了正在編輯的那篇 | 開著 `Zen of Writing`，打 `技術` | 畫面上有 `Tauri 與 Electron`，**也仍然有 `Zen of Writing` 並標示著它是開著的那篇**；編輯區沒有換人 |
| 11 | 例外：篩選中開建立文章對話框 | 打 `技術`，然後按「＋ 新文章」，在 Category 欄打 `隨` | 候選裡出現 `隨筆`——它來自被篩掉的那篇。候選永遠是整個 workspace 的詞彙 |

### 5.3 篩選框與輸入法（FR-8.6、FR-8.7、T-9）

| # | 情境 | 動作 | 期望 |
| :--- | :--- | :--- | :--- |
| 1 | 正常 | 打 `zen`，停手 | 停手一小段時間之後篩一次，不是每個字母篩一次 |
| 2 | 例外 | 注音打「台積電」：組字開始 → 中間跳出候選 → 停 2 秒 → 選字結束 | 那 2 秒完全不篩；`compositionend` 之後才篩，而且只篩一次 |
| 3 | 例外 | 組字中按 `Enter`（確定選字） | 只確定選字。不送出、不清空、不做任何 App 自己的事，**也不得攔掉這個 `Enter`** |
| 4 | 正常 | 沒在組字時按 `Enter` | 立刻用當前字串篩（不用等倒數）；沒有表單被送出 |
| 5 | 正常 | 沒在組字時按 `Esc` | 清空篩選框，清單全部回來 |
| 6 | 例外 | 組字中按 `Esc`（輸入法用它取消組字） | 篩選框不清空、App 不動作 |
| 7 | 正常 | 焦點離開篩選框 | 共用的組字狀態被歸零（欄位沒人在裡面就不可能在組字） |

### 5.4 分隔線（FR-5.6）

| # | 情境 | 動作 | 期望 |
| :--- | :--- | :--- | :--- |
| 1 | 正常 | 把分隔線往左拖 100px（編輯＋預覽區域寬 1000px） | 預覽變寬 10 個百分點 |
| 2 | 正常 | 放手 | 這個比例被寫進 `.rustle/settings.json` 的 `previewPanel.widthRatio` |
| 3 | 正常 | 關掉 App 再開 | 還是那個比例 |
| 4 | 邊界 | 一路往左拖出視窗外 | 停在最寬的合理位置（預覽 80%），編輯區不會被拖成 0 |
| 5 | 邊界 | 一路往右拖出視窗外 | 停在最窄的合理位置（預覽 20%），預覽不會被拖成 0 |
| 6 | 邊界 | 設定檔裡 `widthRatio` 是 `0.97`（人手改的） | 顯示成 80%，不是 97%——同一條夾限規則 |
| 7 | 邊界 | 設定檔裡 `widthRatio` 是垃圾（`"寬一點"`、`0`、`1`） | 退回一半一半（負責檔案存取的那一層既有的正規化已經這麼做） |
| 8 | 例外 | 預覽面板是收合的 | 沒有分隔線可拖（沒有兩欄要分），編輯區照樣吃掉整個寬度 |
| 9 | 邊界 | 用鍵盤：焦點到分隔線，按左右方向鍵 | 每按一次移動一小段，放手即記住。組字中按方向鍵不動作（那一次按鍵屬於輸入法） |
| 10 | 例外 | 拖曳過程中 | **不是每一次 mousemove 都寫檔**——畫面即時跟著走，檔案在放手時才寫一次 |

### 5.5 捲動同步（FR-5.8、§7.4）

共同輸入是一篇「會讓純比例捲動出錯」的文章：

```
第 0~9 行：十段短文字
第 10 行：![](images/tall.png)     ← 渲染出來佔 600px 高
第 11~20 行：十段短文字
第 21 行起：一個 40 行的 fenced code block
第 62 行起：一張 15 列的表格
```

| # | 情境 | 動作 | 期望 |
| :--- | :--- | :--- | :--- |
| 1 | 正常 | 捲編輯區到第 11 行在最上面 | 預覽捲到**那張圖的下緣**（第 11 行對應的區塊），不是「總高度的 11/70」 |
| 2 | 正常 | 捲編輯區到 code block 中段（第 40 行） | 預覽停在 code block 內對應的位置，不是它後面的表格 |
| 3 | 正常（反向） | 捲預覽到表格開頭 | 編輯區捲到第 62 行 |
| 4 | 邊界 | 捲到最底 | 兩邊都在最底，沒有一邊多捲出一段空白 |
| 5 | 邊界 | 捲到最頂 | 兩邊都在最頂 |
| 6 | **例外：不能互相追** | 只捲一次編輯區 | 預覽動一次就停。編輯區**不會被自己觸發的同步移動**（寫作者正在看的那一欄不會跳） |
| 7 | 邊界 | 預覽面板收合著時捲動編輯區 | 什麼都不發生，也不出錯 |
| 8 | 邊界 | 文章短到不需要捲動 | 什麼都不發生 |
| 9 | 例外 | 兩邊都不動時 | 沒有任何一次多餘的捲動寫入（不會有「我把它設回同一個位置」這種空動作） |

## 6. 不在畫面上、但一樣是驗收條件

| 條件 | 判準 |
| :--- | :--- |
| 篩選與排序**都不碰檔案** | 兩者都是「畫哪幾列、依什麼順序」的畫面決定。整個切片不新增任何通道呼叫，唯一寫檔的是分隔線比例（走既有的 `writeSettings`） |
| 開著的文章與儲存機制指向的文章**永遠是同一篇** | 篩選與排序都不得呼叫「選取文章」或「關閉文章」。清單只是視圖 |
| 自動補全候選不因篩選而縮小 | 對話框收到的是整個 workspace 的文章列，不是畫面上剩下的那幾列 |
| NFR-3 | 500 篇文章排序與篩選沒有肉眼可見的停頓 |
| 捲動同步不得使用捲動百分比 | 對照依據是 `data-line`，常數由預覽切片匯出，不自己寫字串 |

## 7. 需求文件留白處的裁決（假設）

| # | 留白 | 裁決 | 理由 |
| :--- | :--- | :--- | :--- |
| A-1 | FR-2.4 沒說篩選是「子字串」還是「前綴」還是「模糊」 | **不分大小寫的子字串**，整個字串當一個條件 | 中文沒有空白分詞，前綴對標籤幾乎無用；子字串是「打三個字縮到幾列」最直接的實現 |
| A-2 | FR-2.2 沒說標題與 `updated_at` 的方向 | 建立時間、更新時間一律**新到舊**；標題**升序**（`localeCompare`） | 時間類的問題是「最近的是哪些」，標題類的問題是「A 開頭的在哪」 |
| A-3 | FR-2.2／2.4 沒說篩選字串與排序方式要不要跨重啟保留 | **不保留**，每次開 App 回到「全部、新到舊」 | 設定檔記的是「寫作者在哪」（workspace／文章／面板），不是「上次找東西找到一半」。一個記著上次篩選字串的清單，在重啟後看起來就是「我的文章不見了」 |
| A-4 | 沒說篩選把當前文章篩掉時該怎樣 | **那一列留在畫面上並標示是開著的那篇**，其餘照篩選 | 這是「畫面顯示的文章」與「儲存機制綁的文章」不一致的唯一防線。要嘛留著那一列，要嘛畫面上根本沒有東西指向正在被寫的檔案 |
| A-5 | 沒說篩選要不要去抖動 | **要，而且用共用的組字感知去抖動器**（150ms，與預覽重繪同一個延遲） | FR-8.6 要求「組字中的一次次中間狀態不被當成輸入」。共用零件已經存在，另寫一個計時器就是另一個會忘記組字的地方 |
| B-1 | FR-5.6 沒說寬度比例的合理範圍 | 預覽佔 **20% ~ 80%** | 兩邊都要留得住內容；要真的收掉預覽有它自己的開關（FR-5.2），拖到 0 只是另一條做同一件事而且做得更糟的路 |
| B-2 | FR-5.6 沒說「拖曳」要不要支援鍵盤 | **支援方向鍵**（分隔線是 `role="separator"` 且可取得焦點） | 這個 App 的鍵盤路徑是設計過的（編輯區吃掉 Tab，所以四欄的走訪順序是逃脫路徑）。一個只有滑鼠能動的控制項在這個產品裡是退步 |
| B-3 | FR-5.8 沒說同步的精度與「哪一邊為準」 | 精度＝**行號**（含區塊內的線性插值）；**動的那一邊為準**，另一邊跟隨 | 行號是需求文件自己指定的對照依據。「動的那一邊為準」是唯一不會跟寫作者搶方向盤的規則 |
| B-4 | FR-5.8 沒說怎麼避免兩邊互相觸發 | **不用計時器**：跟隨方被寫入之後，它自己回報的那一次捲動被認出來（位置相符）並吃掉 | 用計時器壓抑回音，在沒有焦點的視窗裡可能被節流成不可預測的長度（GUI 框架常在視窗失焦時節流計時器、暫停逐幀回呼；實作時須確認所選 GUI 框架的行為）。位置比對不看時間，所以不受影響 |
| B-5 | 沒說捲動同步在組字中要不要停 | **照舊同步**（不特別停） | 同步只改捲動位置，不動文件內容也不重建游標附近的畫面元素，所以 FR-8.1／8.2 沒有被觸碰。反過來說，預覽在組字中不重繪（既有行為），所以組字期間預覽的行號對照是上一次渲染的——這只影響精度，不影響輸入 |

## 8. 交付定義

1. `/prd` → `/architecture` → `/tdd` → `/contract` 走完，文件放本資料夾。
2. 每個 TDD cycle 一顆 commit，接進 App 各自一顆，英文 Conventional Commits，**不出現任何文件代號**。
3. 相關的輸入法回歸項目：**T-9**（篩選框用注音打字並用 `Enter` 選字）、**T-8**（組字中停留 2 秒，篩選不觸發）。兩項都是人工 runbook，見輸入法回歸清單。
4. PR 說明列出：覆蓋的需求 ID、T-x 項目、本檔第 7 節的假設、動到別的切片檔案的清單與理由、NFR-3 的實測數字。
